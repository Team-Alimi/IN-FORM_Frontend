# 구글 로그인

**구글 OAuth2 ID Token 을 검증하고 서비스 전용 JWT(Access/Refresh Token)를 발급합니다. 미가입자는 이 호출에서 자동으로 가입 처리되므로 별도의 회원가입 API 가 없습니다.**

- **Method / Endpoint: `POST /api/v1/auth/login/google`**
- **Auth Required: Not Required**

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Content-Type | application/json | 요청 바디 타입 | **필수** |

## Body Param

| Name | Type | Description | Required |
| --- | --- | --- | --- |
| id_token | String | 구글 OAuth2 클라이언트에서 발급받은 JWT 형식의 ID Token | **필수** |

- 인하대 계정(`@inha.ac.kr` / `@inha.edu`)만 통과합니다. 그 외 도메인은 `403 DOMAIN_RESTRICTED`
- 이메일은 **소문자로 정규화되어 저장**됩니다. `Kim@inha.ac.kr` 과 `kim@inha.ac.kr` 은 같은 계정입니다

## Request Sample

```json
POST /api/v1/auth/login/google
{
  "id_token": "eyJhbGciOiJSUzI1NiIsImtpZCI6ImZm..."
}
```

# Response

## Response Param

성공 응답의 모양은 신규·기존 구분 없이 **하나**입니다. 화면 분기는 `onboarding_completed` 로 합니다.

| name | type | 비고 |
| --- | --- | --- |
| success | Boolean | 요청 성공 여부 |
| data | Object | 응답 데이터 |
| data.access_token | String | 서비스 API 접근용. 유효기간 1시간 |
| data.refresh_token | String | 재발급용. 유효기간 14일 |
| data.user_info | Object | 로그인 직후 화면을 그리는 데 필요한 최소 정보 |
| data.user_info.user_id | Long | 사용자 고유 ID |
| data.user_info.email | String | 이메일 (소문자) |
| data.user_info.name | String | 구글 프로필 이름. 바뀌었으면 로그인할 때마다 갱신됩니다 |
| data.user_info.role | String | `USER` 또는 `ADMIN` |
| data.user_info.onboarding_completed | Boolean | **화면 분기의 기준.** `false` 면 온보딩으로 |
| error | Object | 에러 정보 (성공 시 null) |

> **`role` 에 `ROLE_` 접두사가 없습니다.** `ROLE_USER` 가 아니라 `USER` 입니다 —
> `ROLE_` 은 Spring Security 내부 표기이지 API 계약이 아닙니다.

> **`is_new_user` 는 없습니다. 의도적으로 뺐습니다.**
> "계정이 방금 만들어졌나" 와 "이 사람이 설정을 끝냈나" 는 다른 질문입니다.
> 가입 직후 온보딩 도중에 앱을 껐다가 다음 날 다시 들어오면 계정은 더 이상 새것이 아니지만
> 관심사는 여전히 비어 있습니다. 전자로 화면을 고르면 그 사람은 **메인 피드를 텅 빈 채로** 보게 되고,
> 앱이 고장 났다고 판단합니다. 서버는 200 을 주므로 아무 데도 기록이 남지 않습니다.
>
> `onboarding_completed` 는 `onboarding_completed_at` 에서 나오는 실제 상태라 몇 번째 로그인이든 맞습니다.

---

## Case 1. 로그인 성공 — 온보딩을 마친 사용자

메인 피드로 보냅니다.

```json
{
  "success": true,
  "data": {
    "access_token": "eyJhbGciOiJIUzI1Ni...",
    "refresh_token": "eyJhbGciOiJIUzI1Ni...",
    "user_info": {
      "user_id": 2,
      "email": "5ink@inha.edu",
      "name": "오인겸",
      "role": "ADMIN",
      "onboarding_completed": true
    }
  },
  "error": null
}
```

---

## Case 2. 로그인 성공 — 온보딩이 필요한 사용자

**첫 로그인뿐 아니라, 이전에 온보딩을 하다 만 사용자도 여기에 들어옵니다.**
온보딩 화면(`PUT /users/me/vendors` → `/interests/categories` → `/interests/club-types`
→ `POST /users/me/onboarding/complete`)으로 보냅니다.

```json
{
  "success": true,
  "data": {
    "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6...",
    "refresh_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6...",
    "user_info": {
      "user_id": 13,
      "email": "5ink@inha.edu",
      "name": "오인겸",
      "role": "USER",
      "onboarding_completed": false
    }
  },
  "error": null
}
```

> **전공(`major`) 필드는 없습니다.** 복수전공을 지원하면서 `users.major_vendor_id` 컬럼이
> 스키마에서 제거됐습니다. 구독 학과·기관은 여러 개이고 `GET /users/me/vendors` 로 조회합니다.

---

## Case 3. 로그인 실패 — 인하대 계정이 아님

```json
{
  "success": false,
  "data": null,
  "error": {
    "code": "DOMAIN_RESTRICTED",
    "message": "학교 이메일(@inha.ac.kr/@inha.edu)로만 로그인할 수 있습니다."
  }
}
```

---

## Case 4. 로그인 실패 — 구글 토큰이 유효하지 않음

만료됐거나 서명이 맞지 않는 경우입니다. 클라이언트는 구글 로그인부터 다시 시작해야 합니다.

```json
{
  "success": false,
  "data": null,
  "error": {
    "code": "INVALID_ID_TOKEN",
    "message": "유효하지 않은 구글 토큰입니다."
  }
}
```

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 400 | INVALID_INPUT_VALUE | 유효하지 않은 입력 값입니다. | `id_token` 누락 또는 빈 문자열 |
| 400 | MALFORMED_REQUEST | 요청 본문을 읽을 수 없습니다. | JSON 파싱 실패 |
| 401 | INVALID_ID_TOKEN | 유효하지 않은 구글 토큰입니다. | 서명 불일치·만료·잘못된 audience |
| 403 | DOMAIN_RESTRICTED | 학교 이메일(@inha.ac.kr/@inha.edu)로만 로그인할 수 있습니다. | 인하대 계정이 아님 |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 서버 측 처리 오류 |

> 탈퇴한 계정(`status = WITHDRAWN`)의 이메일로 다시 로그인하면 **새 계정이 만들어집니다.**
> 탈퇴는 soft delete 라 옛 행은 남지만, 조회 조건이 `ACTIVE` 뿐이라 별개 사용자가 됩니다.
> 이전 북마크·알림은 탈퇴 시점에 이미 지워졌으므로 복구되지 않습니다.
