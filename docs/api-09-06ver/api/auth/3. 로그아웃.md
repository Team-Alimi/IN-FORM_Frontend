# 로그아웃

**현재 기기의 세션 하나만 끊습니다. 본문에 담아 보낸 Refresh Token 이 대상 세션을 지목하며, 다른 기기의 세션은 그대로 유지됩니다. 사용자가 로그아웃 버튼을 눌렀을 때 호출합니다.**

- **Method / Endpoint: `POST /api/v1/auth/logout`**
- **Auth Required: Required (User)**

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Authorization | Bearer {access_token} | 서비스 Access Token | **필수** |
| Content-Type | application/json | | **필수** |

> **헤더와 본문이 둘 다 필요합니다.** 이 경로는 로그인 필요 구간이라 Access Token 이 없으면
> 컨트롤러에 닿기도 전에 401 입니다. 그런데 *어느 기기를 끊을지* 는 Access Token 으로는
> 알 수 없으므로(기기 식별자가 Refresh Token 쪽에 있습니다) 본문의 `refresh_token` 이
> 대상을 지목합니다.

## Body Param

| Name | Type | Description | Required |
| --- | --- | --- | --- |
| refresh_token | String | 끊을 세션의 Refresh Token. 이 기기가 마지막으로 저장해 둔 값 | **필수** |

## Request Sample

```json
POST /api/v1/auth/logout
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...
Content-Type: application/json

{
  "refresh_token": "eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiI3IiwianRpIjoiM2Y4Yi..."
}
```

# Response

## Response Param

| name | type | 비고 |
| --- | --- | --- |
| success | Boolean | 항상 `true` |
| data | Object | **없습니다.** 응답 본문에 `data` 키 자체가 나타나지 않습니다 |
| error | Object | **없습니다.** 성공 응답에는 이 키가 나타나지 않습니다 |

> **성공 응답은 `{"success": true}` 한 줄입니다.** `data: null` 이 아니라 키가 통째로
> 빠집니다(`default-property-inclusion: non_null`). `response.data.xxx` 로 접근하는 코드는
> 여기서 터집니다.

> **★ Access Token 은 무효화되지 않습니다.** 이 API 가 지우는 것은 Refresh Token 세션뿐이고,
> 이미 발급된 Access Token 은 stateless 라 **남은 수명(최대 1시간) 동안 그대로 통합니다.**
> 그래서 프론트는 200 을 받은 뒤 **저장해 둔 Access Token 을 반드시 스스로 지워야 합니다.**
> 서버가 대신 끊어 주지 않습니다. 남은 Access Token 까지 즉시 끊으려면 전체 기기 로그아웃을
> 쓰세요.

> **끊긴 세션은 "정상 종료" 로 기록됩니다.** 재발급 때 쓰는 소비 표시를 남기지 않으므로,
> 로그아웃한 토큰이 다시 오면 탈취가 아니라 그냥 무효한 토큰(`INVALID_REFRESH_TOKEN`)으로
> 처리됩니다. 전체 세션이 끊기는 일은 없습니다.

> **멱등합니다.** 이미 폐기된 세션이나 존재하지 않는 세션을 지목해도 200 입니다.
> 마찬가지로 **`refresh_token` 자리에 Access Token 을 보내면 아무 세션도 끊기지 않은 채 200 이 나갑니다**
> (기기 식별자 `jti` 가 없어 조용히 넘어갑니다). 200 을 받았다고 세션이 끊겼다고 단정할 수 없습니다.

> 서버는 본문의 Refresh Token 이 `Authorization` 헤더의 사용자 것인지 대조하지 않습니다.
> 세션을 끊는 대상은 **Refresh Token 안의 사용자**입니다.

## Response Sample

```json
{
  "success": true
}
```

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 400 | INVALID_INPUT_VALUE | refreshToken: refresh_token 은 필수입니다. | `refresh_token` 이 없거나 공백. **필드명이 camelCase(`refreshToken`)** 로 나갑니다 |
| 400 | MALFORMED_REQUEST | 요청 본문을 해석할 수 없습니다. | 본문이 비었거나 JSON 으로 파싱되지 않음 |
| 401 | UNAUTHORIZED | 인증이 필요합니다. | `Authorization` 헤더가 없거나, Access Token 이 만료·위조됐거나, 전체 로그아웃·탈퇴로 무효화된 토큰 |
| 401 | TOKEN_EXPIRED | 만료된 토큰입니다. | **본문의** Refresh Token 이 만료됨 |
| 401 | INVALID_REFRESH_TOKEN | 유효하지 않은 리프레시 토큰입니다. | **본문의** Refresh Token 이 서명 위조·형식 오류 |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 서버 측 처리 오류. 세션 저장소(Redis) 장애도 여기로 나갑니다 |

> **401 이 세 종류입니다.** `UNAUTHORIZED` 는 헤더(Access Token) 문제이고,
> `TOKEN_EXPIRED` · `INVALID_REFRESH_TOKEN` 은 본문(Refresh Token) 문제입니다.
> 뒤의 두 경우는 어차피 그 세션이 이미 죽었다는 뜻이므로, 프론트는 **에러를 받아도
> 로컬 토큰을 지우고 로그인 화면으로 보내면 됩니다.**
