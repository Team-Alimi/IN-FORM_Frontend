# 안 읽은 알림 개수 조회

**로그인한 사용자의 안 읽은 알림 개수만 돌려줍니다. 하단 탭이나 헤더의 알림 배지를 그릴 때 부릅니다. 배지는 화면 어디에나 떠 있어서 자주 불리기 때문에 목록과 분리했습니다 — 목록을 통째로 받아 세면 매번 알림 본문까지 실어 나르게 되지만, 이쪽은 안 읽은 알림만 담은 부분 인덱스(`idx_notifications_unread`)만 훑습니다.**

- **Method / Endpoint: `GET /api/v1/notifications/unread-count`**
- **Auth Required: Required (User)**

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Authorization | Bearer {access_token} | 서비스 Access Token | **필수** |

## Request Sample

```
GET /api/v1/notifications/unread-count
```

# Response

### Response Param

| name | type | 비고 |
| --- | --- | --- |
| success | Boolean | 요청 성공 여부 |
| data | Object | 응답 데이터 |
| data.unread_count | Long | 본인의 안 읽은 알림 개수. 없으면 0 |
| error | Object | 에러 정보. **성공 응답에는 필드 자체가 없습니다** |

> **`data` 는 숫자가 아니라 객체입니다.** `{ "unread_count": 3 }` 이지 `3` 이 아닙니다.
> 키 하나짜리 응답이라 헷갈리기 쉽습니다.

> `data.unread_count` 는 서버가 `Map` 으로 직접 만든 키라 snake_case 변환을 거치지 않습니다.
> 그래서 다른 필드와 달리 **이름이 코드에 그대로 박혀 있고** 바뀌지 않습니다.

> 상한이 없습니다. 화면에서 `99+` 로 줄여 보여 줄 거라면 클라이언트가 잘라야 합니다.

### Response Sample

```json
{
  "success": true,
  "data": {
    "unread_count": 3
  }
}
```

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 401 | UNAUTHORIZED | 인증이 필요합니다. | 토큰 없음·만료 |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 서버 측 처리 오류 |

> 파라미터가 없고 대상이 항상 본인이라 이 경로에서 던지는 업무 예외는 없습니다.
