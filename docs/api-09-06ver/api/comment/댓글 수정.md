# 댓글 수정

**본인이 쓴 댓글의 본문을 고칩니다. 응답에 수정된 댓글이 담기지 않으므로, 프론트는 자기가 보낸 본문으로 화면을 갱신하거나 목록을 다시 부릅니다.**

- **Method / Endpoint: `PATCH /api/v1/comments/{commentId}`**
- **Auth Required: Required (User)**

> 경로가 `/articles/{id}/comments/{id}` 가 아닌 이유는 댓글 id 하나로 대상이 정해지기 때문입니다.
> 공지 아래에 두면 클라이언트가 쓰지도 않을 공지 번호를 함께 들고 다녀야 하고,
> 그 번호가 실제 댓글의 공지와 다를 때 무엇을 해야 하는지가 또 문제가 됩니다.

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Authorization | Bearer {access_token} | 서비스 Access Token | **필수** |
| Content-Type | application/json | | **필수** |

## Path Param

| Name | Type | Description | Required |
| --- | --- | --- | --- |
| commentId | Long | 수정할 댓글 ID | **필수** |

## Body Param

| Name | Type | Description | Required |
| --- | --- | --- | --- |
| content | String | 새 본문. 공백만으로는 안 되고 **최대 1000자** | **필수** |

> **바꿀 수 있는 것은 본문뿐입니다.** `article_id`(대상 공지)는 생성 후 변경할 수 없습니다.
> body 에 넣어 보내도 무시됩니다.

> **`PATCH` 지만 `content` 는 생략할 수 없습니다.** 필드가 하나뿐이라 부분 수정이라는 개념이 없습니다.
> 빠뜨리면 `400 INVALID_INPUT_VALUE` 입니다.

## Request Sample

```json
PATCH /api/v1/comments/74
{
  "content": "네, 8/30 18시까지입니다. (시간 정정)"
}
```

# Response

**성공하면 `data` 가 없습니다.** `null` 필드는 응답에서 통째로 빠지므로(`default-property-inclusion: non_null`)
실제 본문은 `{"success": true}` 한 줄입니다. `data.id` 같은 값을 읽으려 하면 안 됩니다.

### Response Param

| name | type | 비고 |
| --- | --- | --- |
| success | Boolean | 요청 성공 여부. 성공 시 `true` |

> 성공 응답에는 `data` 도 `error` 도 키가 존재하지 않습니다. **`success` 로만 판정하세요.**

### Response Sample

```json
{
  "success": true
}
```

### 수정 후 `edited` 가 붙는 조건

목록의 `edited` 는 `created_at` 과 `updated_at` 이 다를 때 `true` 가 됩니다.
그리고 `updated_at` 은 **본문이 실제로 달라진 UPDATE 에서만** 갱신됩니다(트리거 `inform_comments_updated_at`).

- 같은 본문을 그대로 다시 보내면 `200` 이지만 **`edited` 는 계속 `false`** 입니다.
- 반대로 댓글 삭제나 관리자의 공지 병합(댓글 이동)처럼 본문과 무관한 변경은 `edited` 를 켜지 않습니다.
  이것이 없으면 관리자가 공지 두 개를 합쳤을 뿐인데 사용자가 쓴 댓글이 전부 "수정됨" 으로 표시됩니다.

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 400 | INVALID_INPUT_VALUE | content: 댓글 내용을 입력해 주세요. | `content` 가 없거나 비었거나 공백뿐 |
| 400 | INVALID_INPUT_VALUE | content: 댓글은 1000자를 넘을 수 없습니다. | 1000자 초과 |
| 400 | INVALID_INPUT_VALUE | commentId: 값의 형식이 올바르지 않습니다. | 경로 변수가 숫자가 아닐 때 |
| 400 | MALFORMED_REQUEST | 요청 본문을 해석할 수 없습니다. | body 가 JSON 으로 파싱되지 않음 |
| 401 | UNAUTHORIZED | 인증이 필요합니다. | 토큰 없음·만료 |
| 403 | FORBIDDEN | 본인이 작성한 댓글만 수정·삭제할 수 있습니다. | 남의 댓글 |
| 404 | COMMENT_NOT_FOUND | 존재하지 않는 댓글입니다. | 없는 댓글, 또는 **이미 삭제된 댓글** |
| 409 | CONCURRENT_MODIFICATION | 다른 사용자가 먼저 수정했습니다. 새로고침 후 다시 시도해 주세요. | 낙관적 잠금 충돌 |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 서버 측 처리 오류 |

> **남의 댓글은 404 가 아니라 403 입니다.** 다른 도메인과 달리 여기서는 존재를 감추지 않습니다 —
> 댓글은 목록에 이미 공개돼 있어서 존재 자체가 비밀이 아니기 때문입니다.

> **삭제되어 자리만 남은 댓글은 404 입니다.** 껍데기를 고치게 둘 이유가 없어 없는 것으로 다룹니다.
> 지워진 댓글은 목록에 아예 없으므로 수정 버튼을 그릴 일도 없습니다.

> **409 는 재시도로 풀리지 않을 수 있습니다.** 내가 수정 화면을 열어 둔 사이 그 댓글이 삭제(자리 남김)됐다면
> 서버는 낡은 본문이 삭제를 덮어쓰는 것을 막기 위해 409 로 거부합니다.
> 그대로 다시 보내면 이번에는 `404 COMMENT_NOT_FOUND` 가 됩니다. **목록을 새로 받아 상태를 다시 확인해야 합니다.**
