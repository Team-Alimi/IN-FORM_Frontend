# 카테고리 삭제

**카테고리를 완전히 지웁니다. 아무도 쓰고 있지 않은 카테고리만 지울 수 있습니다. 운영에 들어간 카테고리는 사실상 전부 어딘가에 쓰이고 있으므로, 이 API 는 실질적으로 잘못 만든 카테고리를 등록 직후 되돌리는 용도입니다. 이미 쓰이는 카테고리를 접으려면 삭제가 아니라 비활성화를 써야 합니다.**

- **Method / Endpoint: `DELETE /api/v1/admin/categories/{categoryId}`**
- **Auth Required: Required (Admin)**

성공 시 HTTP 상태는 **200 OK** 입니다 (204 가 아닙니다).

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Authorization | Bearer {access_token} | 서비스 Access Token | **필수** |

## Path Param

| Name | Type | Description | Required |
| --- | --- | --- | --- |
| categoryId | Long | 삭제할 카테고리 ID | **필수** |

> **삭제 버튼은 목록의 `in_use` 로 미리 막으세요.** `GET /admin/categories` 가 항목마다
> `in_use` 를 내려 줍니다. `true` 인 카테고리에 이 요청을 보내면 `409 CATEGORY_IN_USE` 로 돌아옵니다 —
> 누르기 전에 알 수 있게 하려고 넣은 값입니다.

> "쓰이고 있는지" 판정은 `article_categories`(공지에 붙은 카테고리)와
> `user_interest_categories`(사용자 관심분야) **둘 다** 를 봅니다.
> 공지가 하나도 안 쓰더라도 누군가의 관심분야에 들어 있으면 지울 수 없습니다.
> 두 테이블 모두 `ON DELETE RESTRICT` 라 한쪽만 확인하면 DELETE 단계에서 실패합니다.

## Request Sample

```
DELETE /api/v1/admin/categories/21
```

# Response

## Response Param

| name | type | 비고 |
| --- | --- | --- |
| success | Boolean | 요청 성공 여부. **성공 응답에 사실상 이 필드뿐입니다** |
| data | — | **응답에 존재하지 않습니다** (아래 설명) |

> **성공 본문은 `{"success": true}` 가 전부입니다.** 서버는 `data` 에 `null` 을 담아 내려보내는데
> `null` 필드는 응답에서 빠지므로, `data` 키 자체가 없습니다.
> 프론트가 `response.data.xxx` 를 읽거나 `data` 의 존재로 성공을 판단하면 그 자리에서 터집니다.
> 판단 기준은 HTTP 상태 코드와 `success` 입니다.

> 삭제된 카테고리의 정보는 돌려주지 않습니다. 화면에서 되돌리기(undo)를 제공하려면
> 삭제 전에 로컬에 값을 들고 있어야 합니다.

## Response Sample

```json
{
  "success": true
}
```

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 400 | INVALID_INPUT_VALUE | categoryId: 값의 형식이 올바르지 않습니다. | 경로 변수가 숫자가 아님 |
| 401 | UNAUTHORIZED | 인증이 필요합니다. | 토큰 없음·만료 |
| 403 | FORBIDDEN | 권한이 없습니다. | 로그인은 했으나 `ROLE_ADMIN` 이 아님 |
| 404 | CATEGORY_NOT_FOUND | 존재하지 않는 카테고리입니다. | 그 ID 의 카테고리가 없음 |
| 409 | CATEGORY_IN_USE | 이미 공지나 사용자 관심분야에 쓰이고 있어 삭제할 수 없습니다. 대신 비활성화하면 새로 선택되지 않습니다. 이미 붙어 있는 공지 카테고리는 그대로 유지되고, 크롤러 AI 카테고리 목록에서도 이 코드를 빼야 새 공지에 더 이상 붙지 않습니다. | 쓰이고 있음. **화면은 이때 비활성화를 안내해야 합니다** |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 서버 측 처리 오류 |

> **`409 CATEGORY_IN_USE` 의 메시지는 그대로 노출해도 되는 문구입니다.** 삭제가 막힌 이유와
> 대안(비활성화), 그리고 비활성화만으로는 부족하다는 사실(크롤러 목록에서도 빼야 함)까지
> 한 문장에 담겨 있습니다.

> 서버는 판정 전에 카테고리 행을 `FOR UPDATE` 로 잠급니다. 잠그지 않으면 "안 쓰임" 으로 판정한 직후
> 공지가 그 카테고리를 달 수 있고, 그때 DELETE 가 FK 위반(23503)으로 실패하는데 그 SQLSTATE 는
> `400 RELATED_RESOURCE_NOT_FOUND`("참조 대상이 존재하지 않습니다")로 매핑돼 있어
> **정반대 뜻의 메시지**가 나갑니다. 정상 경로에서는 이 응답을 볼 일이 없어야 합니다 —
> 만약 목격한다면 잠금이 깨진 것이므로 서버 이슈로 보고하세요.
