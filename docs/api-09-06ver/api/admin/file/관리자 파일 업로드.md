# 관리자 파일 업로드

**공지 본문·첨부에 쓸 이미지를 스토리지에 올리고 접근 주소를 돌려받습니다. 공지 작성·수정 화면에서 이미지를 고르는 즉시 호출하고, 돌려받은 `file_url` 을 공지 저장(`POST`·`PATCH /admin/articles`)의 `attachments` 에 실어 보내야 공지와 연결됩니다. 단일·다중 업로드가 같은 엔드포인트입니다.**

- **Method / Endpoint: `POST /api/v1/admin/files`**
- **Auth Required: Required (Admin)**

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Authorization | Bearer {access_token} | 서비스 Access Token (ROLE_ADMIN) | **필수** |
| Content-Type | multipart/form-data | 경계 문자열 포함 | **필수** |

## Body Param

`multipart/form-data` 이며 part 이름은 **`files` 하나뿐**입니다. 여러 개를 올릴 때도 같은 이름으로 반복합니다.

| Name | Type | Description | Required |
| --- | --- | --- | --- |
| files | File[] | 업로드할 이미지. 같은 이름의 part 를 반복해 다중 업로드 | **필수** |

### 제한

| 항목 | 값 |
| --- | --- |
| 허용 확장자 | `jpg` · `jpeg` · `png` · `gif` · `webp` |
| 파일당 최대 크기 | 10MB |
| 요청 전체 최대 크기 | 60MB |

> **판정 기준은 파일 이름의 확장자입니다. 클라이언트가 보낸 part 의 `Content-Type` 은 믿지 않습니다.**
> 그건 요청자가 마음대로 정할 수 있어 검사로서 의미가 없습니다. 확장자 대소문자는 가리지 않습니다(`.PNG` 도 통과).
> 확장자가 없는 파일 이름은 거부됩니다.

> **한 건이라도 규격에 어긋나면 전부 거부하고 아무것도 올리지 않습니다.** 올리면서 검사하면
> 세 번째 파일이 위반일 때 앞의 두 개는 이미 스토리지에 올라간 채로 400 이 나가고,
> 그 둘은 아무도 모르는 고아 객체가 됩니다. 그래서 검증을 전부 먼저 합니다.

## Request Sample

```
POST /api/v1/admin/files
Content-Type: multipart/form-data; boundary=----WebKitFormBoundaryXYZ
Authorization: Bearer {access_token}

------WebKitFormBoundaryXYZ
Content-Disposition: form-data; name="files"; filename="poster.png"
Content-Type: image/png

(바이너리)
------WebKitFormBoundaryXYZ
Content-Disposition: form-data; name="files"; filename="detail.jpg"
Content-Type: image/jpeg

(바이너리)
------WebKitFormBoundaryXYZ--
```

# Response

## Response Param

| name | type | 비고 |
| --- | --- | --- |
| success | Boolean | 요청 성공 여부 |
| data | Array | 업로드 결과. **요청한 순서와 같은 순서**로 돌아옵니다 |
| data[].file_url | String | 공개 접근 주소. 공지 저장 시 `attachments[].file_url` 로 넘길 값 |
| data[].original_name | String | 올린 파일의 원본 이름. **표시용**이며 저장 키에는 쓰이지 않습니다 |
| data[].content_type | String | **서버가 확장자로 다시 정한** MIME 타입 |
| data[].size_bytes | Long | 파일 크기 (바이트) |
| error | Object | 에러 정보. 성공 시 null — `non_null` 설정이라 **성공 응답에는 이 키가 아예 없습니다** |

> **`data` 는 페이징 봉투가 아니라 배열입니다.** `content`·`page_info` 가 없습니다.

> **이 시점에는 스토리지에만 올라가고 DB 레코드는 생기지 않습니다.**
> 공지를 저장할 때 `file_url` 을 넘겨야 `attachments` 행이 생깁니다. 업로드해 두고 작성을 취소하면
> **연결되지 않은 객체가 남으므로** `DELETE /admin/files` 로 정리해야 합니다.
> 취소조차 하지 않은 경우는 서버 측 정리 배치가 필요한 영역입니다.

> **`object_key`(스토리지 내부 키)는 내보내지 않습니다.** 화면은 `file_url` 만 있으면 되고,
> 키를 알려 주면 클라이언트가 그것으로 삭제를 시도하게 됩니다. 삭제는 `file_url` 로 요청하며
> 서버가 키를 되짚습니다.

> **`content_type` 은 요청에 실어 보낸 값이 아닙니다.** `evil.png` 라는 이름에 `text/html` 을 실어 올리면
> 버킷 도메인이 그것을 HTML 로 서빙해 저장형 XSS 가 되므로, 확장자에 대응하는 타입만 붙입니다.
> 화면에서 보낸 타입과 응답의 타입이 다를 수 있습니다.

> **저장 경로에 원본 파일명이 들어가지 않습니다.** 키는 `yyyy/MM/{uuid}.{확장자}` 형태입니다 —
> 한글·공백·`../` 가 섞이고 같은 이름이 서로를 덮어쓰는 문제를 피하기 위해서입니다.
> 원본 이름은 `original_name` 으로만 유지되고, 공지에 연결되면 `attachments.original_name` 에 남습니다.

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 400 | FILE_IS_EMPTY | 업로드할 파일이 없습니다. | `files` part 는 있으나 파일이 하나도 없음 |
| 400 | FILE_IS_EMPTY | 빈 파일은 업로드할 수 없습니다. | 0바이트 파일이 섞여 있음 |
| 400 | INVALID_FILE_TYPE | 허용되지 않는 파일 형식입니다. (허용: jpg, jpeg, png, gif, webp) | 확장자가 화이트리스트 밖이거나 확장자가 없음 |
| 400 | FILE_SIZE_EXCEEDED | 파일 크기는 10MB를 초과할 수 없습니다. | 파일당 10MB 초과. **요청 전체가 60MB 를 넘는 경우도 같은 코드**로 나갑니다 |
| 401 | UNAUTHORIZED | 인증이 필요합니다. | 토큰 없음·만료 |
| 403 | FORBIDDEN | 권한이 없습니다. | 로그인은 했으나 ROLE_ADMIN 이 아님 |
| 500 | FILE_UPLOAD_FAILED | 파일 업로드에 실패했습니다. | 스토리지 전송 실패 |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 서버 측 처리 오류. **아래 주의 참조** |

> **용량 초과는 두 경로로 갈라지지만 코드는 같습니다.** 앱 상한(10MB)보다 큰 파일은 톰캣이 요청 본문을
> 다 읽기 전에 끊고, 그 이하는 앱 검증이 잡습니다. 어느 쪽이든 `400 FILE_SIZE_EXCEEDED` 로 통일해 두었습니다 —
> 프론트가 5xx 를 재시도 대상으로 다루면 큰 파일일수록 재업로드가 반복되기 때문입니다.

> **`files` part 이름을 틀리거나 `multipart/form-data` 가 아닌 요청은 현재 `500 INTERNAL_SERVER_ERROR` 입니다.**
> 전역 예외 핸들러가 `MissingServletRequestPartException`·`HttpMediaTypeNotSupportedException` 을 다루지 않아
> 400 이 아닌 500 으로 나갑니다. **의미상 400 이어야 하는 자리이므로 서버 보완 대상이고,
> 프론트는 이 500 을 재시도해도 고쳐지지 않습니다.**
