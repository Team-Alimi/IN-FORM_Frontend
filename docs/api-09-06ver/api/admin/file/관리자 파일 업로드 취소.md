# 관리자 파일 업로드 취소

**공지에 연결되기 전에 취소한 업로드 파일을 스토리지에서 정리합니다. 관리자가 이미지를 올려 두고 공지 작성을 취소하거나, 붙였던 이미지를 저장 전에 빼는 순간 호출합니다. 이미 공지에 연결된 파일은 여기서 지울 수 없습니다 — 그건 공지 수정·삭제 흐름에서 처리합니다.**

- **Method / Endpoint: `DELETE /api/v1/admin/files`**
- **Auth Required: Required (Admin)**

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Authorization | Bearer {access_token} | 서비스 Access Token (ROLE_ADMIN) | **필수** |
| Content-Type | application/json | | **필수** |

## Body Param

| Name | Type | Description | Required |
| --- | --- | --- | --- |
| file_urls | Array&lt;String&gt; | 지울 파일의 `file_url`. **비어 있으면 400**, **최대 100건**, 원소에 null 이 섞이면 400 | **필수** |

> **`DELETE` 인데 body 를 씁니다.** 쿼리 파라미터로 주소 목록을 나열하면 URL 길이 제한에 걸립니다.

> `file_url` 은 업로드(`POST /admin/files`) 응답의 `data[].file_url` 을 그대로 넣습니다.
> 스토리지 내부 키는 클라이언트에 내려가지 않으며, 서버가 URL 에서 되짚습니다.

## Request Sample

```json
DELETE /api/v1/admin/files
{
  "file_urls": [
    "https://inform-prod.s3.ap-northeast-2.amazonaws.com/2026/08/9f1c2e40-7b1a-4d33-9a6e-1c9d0f2b7a11.png"
  ]
}
```

# Response

## Response Param

| name | type | 비고 |
| --- | --- | --- |
| success | Boolean | 요청 성공 여부 |
| data | Object | 응답 데이터 |
| data.deleted | Integer | **삭제를 요청한 객체 수.** 요청 건수와 다를 수 있습니다 (아래 주의) |
| error | Object | 에러 정보. 성공 시 null — `non_null` 설정이라 **성공 응답에는 이 키가 아예 없습니다** |

> **`deleted` 가 요청한 `file_urls` 개수와 다를 수 있습니다.** 세 가지 이유입니다.
> - 중복 주소는 하나로 합쳐집니다
> - **우리 스토리지 주소가 아닌 URL 은 조용히 건너뜁니다** — 남의 주소를 넣어 우리 버킷의 다른 객체를
>   지우게 만들 수 없어야 하기 때문입니다. 이 경우 에러가 아니라 `deleted` 에서 빠질 뿐입니다
>   (전부 외부 주소면 `deleted: 0` 인 200 입니다)
> - 없는 객체를 지우는 것은 오류가 아닙니다. 같은 주소를 두 번 보내면 두 번 다 성공으로 셉니다

> **`deleted` 는 "지워졌다" 가 아니라 "삭제를 시도했다" 입니다.** 스토리지 삭제가 실패해도 예외를 던지지 않고
> 서버 로그에만 남깁니다 — 여기서 던지면 되돌릴 수 없는 삭제가 이미 일부 일어난 채로 오류만 나갑니다.
> 화면은 이 값을 "몇 건을 정리 요청했는지" 로만 쓰세요.

> **연결된 파일이 하나라도 섞여 있으면 아무것도 지우지 않고 400 입니다.** 일부만 지우면 관리자는 200 을 받고
> 나머지가 남은 줄 모릅니다. 이미 공지에 연결된 파일을 여기서 지우면 공지에는 깨진 이미지 링크만 남으므로,
> 공지 수정(`PATCH /admin/articles/{id}`)이나 삭제 흐름으로 유도합니다.

> 이 API 는 스토리지 객체만 다룹니다. `attachments` 행은 애초에 연결된 파일에만 존재하고,
> 연결된 파일은 여기서 거부되므로 **DB 는 변경되지 않습니다.**

## Response Sample

```json
{
  "success": true,
  "data": {
    "deleted": 1
  },
  "error": null
}
```

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 400 | INVALID_INPUT_VALUE | fileUrls: 지울 파일을 선택해 주세요. | `file_urls` 가 없거나 빈 배열 |
| 400 | INVALID_INPUT_VALUE | fileUrls: 한 번에 100건까지 처리할 수 있습니다. | `file_urls` 가 100건 초과 |
| 400 | INVALID_INPUT_VALUE | fileUrls[0]: 파일 주소가 비어 있습니다. | 배열 원소에 null 이 섞임 |
| 400 | INVALID_INPUT_VALUE | 이미 공지에 연결된 파일은 여기서 지울 수 없습니다. 공지를 수정하거나 삭제해 주세요. 대상=[...] | 요청에 이미 `attachments` 로 연결된 주소가 섞임. **아무것도 지우지 않았습니다** |
| 400 | MALFORMED_REQUEST | 요청 본문을 해석할 수 없습니다. | body 가 JSON 이 아니거나 `file_urls` 타입이 맞지 않음 |
| 401 | UNAUTHORIZED | 인증이 필요합니다. | 토큰 없음·만료 |
| 403 | FORBIDDEN | 권한이 없습니다. | 로그인은 했으나 ROLE_ADMIN 이 아님 |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 서버 측 처리 오류 |

> **"이미 연결된 파일" 에 전용 에러 코드가 없습니다.** 검증 실패와 같은 `INVALID_INPUT_VALUE` 로 나가므로
> 프론트가 코드만 보고는 두 경우를 구분할 수 없습니다. 구분이 필요하면 `message` 를 봐야 하며,
> 메시지 끝의 `대상=[...]` 에 문제가 된 주소 목록이 그대로 들어 있습니다.

> 검증 실패 메시지의 필드명은 **JSON 키(`file_urls`)가 아니라 자바 필드명(`fileUrls`)** 으로 나옵니다.
> 메시지를 그대로 노출하면 화면에 `fileUrls: ...` 가 보이므로, 사용자에게는 화면 문구로 갈아 끼우세요.
