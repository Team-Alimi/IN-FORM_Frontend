# 공지 수정

**공지의 내용·기간·분류·출처·첨부를 고칩니다. 검수 화면의 저장 버튼과 동아리 공지 편집이 같은 엔드포인트를 씁니다. 부분 수정이라 보낸 필드만 반영되고, 응답으로 수정 후 상세 전체가 내려오므로 저장 직후 화면을 다시 그릴 수 있습니다.**

- **Method / Endpoint: `PATCH /api/v1/admin/articles/{articleId}`**
- **Auth Required: Required (Admin)**

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Authorization | Bearer {access_token} | 서비스 Access Token | **필수** |
| Content-Type | application/json | | **필수** |

## Path Param

| Name | Type | Description | Required |
| --- | --- | --- | --- |
| articleId | Long | 수정할 게시글 번호 | **필수** |

## Body Param

| Name | Type | Description | Required |
| --- | --- | --- | --- |
| title | String | 제목. 최대 500자 | 선택 |
| content | String | 본문(HTML) | 선택 |
| starts_on | LocalDate | 시작일 (yyyy-MM-dd) | 선택 |
| ends_on | LocalDate | 마감일 (yyyy-MM-dd) | 선택 |
| category_ids | Array&lt;Long&gt; | 분류 번호. **보내면 전체 교체** | 선택 |
| vendors | Array | 출처. **보내면 전체 교체** | 선택 |
| vendors[].id | Long | 기존 출처 행 번호. **새 출처는 비웁니다** | 선택 |
| vendors[].vendor_id | Long | 제공처 번호 | **필수** |
| vendors[].source_url | String | 원본 게시판 글 주소. 최대 1000자 | 선택 |
| attachments | Array | 첨부. **보내면 전체 교체.** 최대 20개 | 선택 |
| attachments[].id | Long | 기존 첨부 행 번호. **새 파일은 비웁니다** | 선택 |
| attachments[].file_url | String | `POST /admin/files` 가 돌려준 주소. 최대 1000자 | **필수** |
| attachments[].original_name | String | 원본 파일 이름. 최대 255자 | 선택 |
| attachments[].content_type | String | MIME 타입. 최대 100자 | 선택 |
| attachments[].size_bytes | Long | 파일 크기. 양수 | 선택 |
| article_id | Long | **무시됩니다.** 상한 검사만 받습니다 | 선택 |
| source_type | String | **무시됩니다** | 선택 |
| status | String | **무시됩니다.** 상태 변경은 `POST /admin/articles/bulk/status` 로만 | 선택 |

> **`article_id` · `source_type` · `status` 는 조용히 무시됩니다.** 거부하지 않는 이유는
> 화면이 상세 응답을 통째로 되돌려 보내는 흔한 구현에서 매번 400 이 나기 때문입니다.
> 다만 `article_id` 는 상한(1억) 검사만 그대로 받으므로 큰 값을 실어 보내면
> **바꾸지도 않을 값 때문에 400** 이 납니다.

### null 은 "유지", 빈 배열은 "전부 삭제"

**생략과 빈 배열은 다른 뜻입니다.**

| 보낸 값 | 결과 |
| --- | --- |
| 키 자체를 생략 (또는 `null`) | 건드리지 않습니다 |
| `[]` | **전부 지웁니다** |
| 값이 있는 배열 | 그 목록으로 맞춥니다 |

제목 오타 하나를 고치려고 저장한 요청이 분류를 통째로 지우는 일이 없게 하려는 설계입니다.
반대로 분류를 **비우려면 `[]` 를 명시적으로** 보내야 합니다.

> **기간은 지울 수 없습니다.** `null` 이 "그대로 두기" 라서 "비워 달라" 를 표현할 방법이 없습니다.
> 목록 세 가지는 빈 배열로 구분되지만 날짜에는 그런 값이 없습니다. 지금 스펙에는 이 경로가 없습니다.

### `vendors` 는 완전한 교체가 아닙니다

**크롤러가 수집한 출처 행(`external_key` 가 있는 행)은 요청에서 빠져 있어도 지워지지 않습니다.**
그 행이 사라지면 크롤러가 원본을 처음 보는 글로 인식해 **다음 수집에서 같은 공지를 새로 만듭니다.**

| 요청 항목 | 처리 |
| --- | --- |
| `id` 있음 + 그 행이 수집분 | 그대로 둡니다 (URL 변경도 반영되지 않습니다) |
| `id` 있음 + 수기 행 | `vendor_id` · `source_url` 을 갱신합니다 |
| `id` 없음 | 새 수기 행으로 넣습니다 |
| 요청에 없는 수기 행 | 지웁니다 |

> **`id` 를 빠뜨리면 행이 늘어납니다.** 상세 응답을 그대로 되돌려 보낼 때 `vendors[].id` 를
> 실어 보내지 않으면 서버는 전부 "새 출처" 로 보고 한 벌 더 넣습니다.
> `(article_id, vendor_id)` 유니크가 **의도적으로 없어서**(같은 게시판 재게시를 보존해야 합니다)
> 아무것도 막아 주지 않고, 저장할 때마다 한 줄씩 늘어납니다. 첨부도 같습니다.

### 저장이 부르는 부수 효과

- **제목·본문·기간이 실제로 바뀌면 DB 가 `summary` 를 NULL 로 만듭니다.** 응답에서는 `summary` 키가 통째로 사라집니다(null 필드 미직렬화). 프론트가 요약 박스를 그리기 전에 키 존재를 확인해야 합니다
- `updated_at` 도 DB 가 올립니다. 앱이 따로 하는 일은 없습니다
- **첨부를 요청에서 빼면 DB 행은 지워지지만 S3 객체는 남습니다.** 트랜잭션이 롤백되면 되살릴 수 없어서 여기서는 지우지 않습니다. 떨어져 나온 객체는 정리 배치가 다룹니다

## Request Sample

```json
// 제목만 고치기 — 분류·출처·첨부는 그대로 유지됩니다
PATCH /api/v1/admin/articles/42
{
  "title": "2026학년도 1학기 국가장학금 신청 안내 (기간 연장)"
}
```

```json
// 분류를 통째로 비우기 — 빈 배열을 명시해야 합니다
PATCH /api/v1/admin/articles/42
{
  "category_ids": []
}
```

```json
// 출처를 유지하면서 한 건 추가 — 기존 행은 id 를 실어 보냅니다
PATCH /api/v1/admin/articles/42
{
  "vendors": [
    { "id": 88, "vendor_id": 3, "source_url": "https://cse.inha.ac.kr/bbs/12345" },
    { "vendor_id": 7, "source_url": "https://me.inha.ac.kr/bbs/551" }
  ]
}
```

# Response

## Response Param

| name | type | 비고 |
| --- | --- | --- |
| success | Boolean | 요청 성공 여부 |
| data | Object | 수정 후 관리자 상세 전체 |
| data.id | Long | 게시글 번호 |
| data.source_type | String | `SCHOOL` \| `CLUB` |
| data.status | String | `PENDING_REVIEW` \| `READY_TO_PUBLISH` \| `DRAFT` \| `PUBLISHED` \| `TRASHED` |
| data.title | String | 제목 |
| data.content | String | 본문(HTML) |
| data.summary | String | AI 요약. **본문·기간을 고치면 무효화되어 키가 사라집니다** |
| data.starts_on | String | 시작일 (yyyy-MM-dd). 없으면 키 없음 |
| data.ends_on | String | 마감일 (yyyy-MM-dd). 없으면 키 없음 |
| data.published_at | String | 최초 발행 시각 (ISO-8601 offset). **한 번도 발행된 적 없으면 키 없음** |
| data.similarity_score | Number | 중복 의심 점수 (0~100, 소수 둘째 자리). 미판정이면 키 없음 |
| data.similar_article_id | Long | 비슷하다고 판정된 상대 공지. 미판정이면 키 없음 |
| data.created_by | Long | 작성 관리자. **크롤러 수집분이면 키 없음** |
| data.created_at | String | 생성 시각 (ISO-8601 offset) |
| data.updated_at | String | 수정 시각 (ISO-8601 offset) |
| data.categories | Array | 분류 목록 |
| data.categories[].id | Long | 분류 번호 |
| data.categories[].name | String | 분류 이름 |
| data.vendors | Array | 출처 목록 |
| data.vendors[].id | Long | **연결 행(`article_vendors`)의 번호.** 되돌려 보낼 때 이 값이 필요합니다 |
| data.vendors[].vendor_id | Long | 제공처 번호 |
| data.vendors[].vendor_name | String | 제공처 이름 |
| data.vendors[].source_url | String | 원본 게시판 글 주소. 없으면 키 없음 |
| data.vendors[].external_key | String | 원본 게시판 글 번호. **키가 있으면 크롤러 수집분** — 화면에서 삭제 불가로 표시해야 합니다 |
| data.attachments | Array | 첨부 목록 (`id` 오름차순) |
| data.attachments[].id | Long | 첨부 행 번호 |
| data.attachments[].file_url | String | 파일 주소 |
| data.attachments[].original_name | String | 원본 파일 이름. 없으면 키 없음 |
| data.attachments[].content_type | String | MIME 타입. 없으면 키 없음 |
| data.attachments[].size_bytes | Long | 파일 크기. 없으면 키 없음 |
| data.status_logs | Array | **최근 5건만.** 전체는 `GET /admin/articles/{id}/status-logs` |
| data.status_logs[].id | Long | 이력 번호 |
| data.status_logs[].from_status | String | 이전 상태. **최초 생성이면 키 없음** |
| data.status_logs[].to_status | String | 바뀐 상태 |
| data.status_logs[].changed_by | Long | 변경한 관리자. **키가 없으면 시스템(크롤러·스케줄러)** |
| data.status_logs[].changed_by_name | String | 관리자 이름. 시스템 변경이면 키 없음 |
| data.status_logs[].memo | String | 변경 사유. 없으면 키 없음 |
| data.status_logs[].created_at | String | 변경 시각 (ISO-8601 offset) |

> **`external_key` 는 최상위가 아니라 `vendors[]` 안에 있습니다.** 수집 식별자는 게시판마다
> 다르기 때문입니다 — 같은 공지가 두 게시판에 올라오면 키도 두 개입니다.
>
> 사용자 상세(`GET /articles/{id}`)와 달리 `is_bookmarked` · `bookmark_count` 같은
> 개인화·카운트 값은 **없습니다.** 검수는 "누가 보느냐" 로 달라지는 화면이 아닙니다.

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 400 | INVALID_INPUT_VALUE | 유효하지 않은 입력 값입니다. | 합쳐진 제목이 비었거나 500자 초과, 본문이 빈 문자열 |
| 400 | INVALID_INPUT_VALUE | 게시글 번호가 너무 큽니다. | `article_id` 가 1억 초과 (무시되는 값인데도 검사합니다) |
| 400 | INVALID_INPUT_VALUE | {필드}: {제약 메시지} | Bean Validation 위반. 첨부 21개 이상, `vendors[].vendor_id` 누락, `attachments[].file_url` 누락 등 |
| 400 | INVALID_ARTICLE_PERIOD | 시작일은 종료일보다 늦을 수 없습니다. | **보낸 값과 기존 값을 합친 결과**로 판정합니다. `starts_on` 만 보내도 기존 `ends_on` 보다 늦으면 걸립니다 |
| 400 | VENDOR_TYPE_MISMATCH | 공지 출처(...)와 제공처 유형(...)이 다릅니다 | 학교 공지에 동아리 제공처를 붙인 경우. DB 트리거(IN002) |
| 400 | RELATED_RESOURCE_NOT_FOUND | 참조 대상이 존재하지 않습니다. | 없는 `category_id` · `vendor_id` (FK 위반 23503) |
| 400 | MALFORMED_REQUEST | 요청 본문을 해석할 수 없습니다. | JSON 파싱 실패, enum 오타 |
| 401 | UNAUTHORIZED | 인증이 필요합니다. | 토큰 없음·만료 |
| 403 | FORBIDDEN | 권한이 없습니다. | 관리자가 아님 |
| 404 | ARTICLE_NOT_FOUND | 존재하지 않는 공지입니다. | `articleId` 에 해당하는 공지 없음 |
| 409 | CONCURRENT_MODIFICATION | 다른 사용자가 먼저 수정했습니다. 새로고침 후 다시 시도해 주세요. | 관리자 두 명이 같은 공지를 동시에 수정 (낙관적 락) |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 서버 측 처리 오류 |

> **409 를 재시도하면 안 됩니다.** 낙관적 락은 정확히 "낡은 본문이 덮어쓰는 것" 을 막으려고 있습니다.
> 화면을 다시 읽어 최신 내용 위에서 고쳐야 합니다.
>
> 북마크·조회수·AI 요약 변경은 **일부러** 락 버전을 올리지 않습니다.
> 누가 북마크를 눌렀다고 관리자의 수정이 실패하면 안 되기 때문입니다.
