# 공지 작성

**관리자가 공지를 직접 등록합니다. 동아리 공지 작성이 주 용도이지만 학교 공지 수기 등록에도 같은 엔드포인트를 씁니다. 응답은 새로 만들어진 게시글 번호 하나뿐이라, 저장 직후 상세 화면으로 넘어가려면 `GET /api/v1/admin/articles/{id}` 를 이어서 부릅니다.**

- **Method / Endpoint: `POST /api/v1/admin/articles`**
- **Auth Required: Required (Admin)**

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Authorization | Bearer {access_token} | 서비스 Access Token | **필수** |
| Content-Type | application/json | | **필수** |

## Body Param

| Name | Type | Description | Required | Default |
| --- | --- | --- | --- | --- |
| article_id | Long | 게시글 번호 수동 지정. 양수, **최대 100000000** | 선택 | 시퀀스 발급 |
| source_type | String | `SCHOOL` \| `CLUB` | 선택 | `SCHOOL` |
| status | String | 초기 상태. `TRASHED` 불가 | 선택 | 아래 표 |
| title | String | 제목. 최대 500자. **생성에서는 필수** | **필수** | - |
| content | String | 본문(HTML). **생성에서는 필수** | **필수** | - |
| starts_on | LocalDate | 시작일 (yyyy-MM-dd) | 선택 | - |
| ends_on | LocalDate | 마감일 (yyyy-MM-dd) | 선택 | - |
| category_ids | Array&lt;Long&gt; | 분류 번호. **복수입니다** | 선택 | - |
| vendors | Array | 출처(제공처 + 원본 URL) | 선택 | - |
| vendors[].id | Long | **생성에서는 비웁니다.** 기존 행 식별용 | 선택 | - |
| vendors[].vendor_id | Long | 제공처 번호 | **필수** | - |
| vendors[].source_url | String | 원본 게시판 글 주소. 최대 1000자 | 선택 | - |
| attachments | Array | 첨부. **최대 20개** | 선택 | - |
| attachments[].id | Long | **생성에서는 비웁니다.** 기존 행 식별용 | 선택 | - |
| attachments[].file_url | String | `POST /admin/files` 가 돌려준 주소. 최대 1000자 | **필수** | - |
| attachments[].original_name | String | 원본 파일 이름. 최대 255자 | 선택 | - |
| attachments[].content_type | String | MIME 타입. 최대 100자 | 선택 | - |
| attachments[].size_bytes | Long | 파일 크기. **양수여야 합니다** | 선택 | - |

> `title` · `content` 는 DTO 에 `@NotBlank` 가 **없습니다.** 같은 DTO 를 `PATCH` 가 함께 쓰는데
> 거기서는 "안 보냄" 이 정상이기 때문입니다. 생성 경로에서만 서비스가 따로 확인해
> `400 INVALID_INPUT_VALUE` 로 거부합니다. 그래서 오류 메시지가 필드명이 아니라
> "제목을 입력해 주세요." / "본문을 입력해 주세요." 로 나갑니다.

### `status` 기본값

| source_type | 생략 시 초기 상태 |
| --- | --- |
| `SCHOOL` | `PENDING_REVIEW` (검수 대기) |
| `CLUB` | `DRAFT` (임시저장) |

지정할 수 있는 값은 출처에 따라 갈립니다. `PENDING_REVIEW` · `READY_TO_PUBLISH` 는 `SCHOOL` 전용,
`DRAFT` 는 `CLUB` 전용, `PUBLISHED` 는 양쪽 다 됩니다. 맞지 않으면 `400 INVALID_STATUS_FOR_SOURCE` 입니다.

> **`TRASHED` 로는 만들 수 없습니다.** 복구는 상태 이력의 직전 상태로만 가는데,
> 처음부터 휴지통으로 만들면 그 이력의 `from_status` 가 없어 **영영 꺼낼 수 없는 공지**가 됩니다.
> 목록에도 안 뜨니 만든 사람조차 존재를 잊습니다.

> **생성은 전이 규칙을 타지 않습니다.** `PENDING_REVIEW` 를 거치지 않고 곧바로 `PUBLISHED` 로
> 만들 수 있습니다 — 관리자가 직접 쓴 글은 검수할 대상이 자기 자신이기 때문입니다.
> 반면 만들어진 뒤의 상태 변경은 전부 전이 규칙을 탑니다(`POST /admin/articles/bulk/status`).

### `article_id` 수동 지정

비워 두면 시퀀스가 번호를 발급합니다. 값을 주면 그 번호로 넣고 **시퀀스도 그 번호까지 밀어올립니다** —
그러지 않으면 나중에 크롤러가 그 번호에 도달했을 때 PK 가 충돌해 그날 수집이 통째로 실패합니다.

- 상한이 **1억**인 이유는 시퀀스를 되돌릴 수 없기 때문입니다. 실수로 큰 값을 넣으면 그 사이 번호가 전부 타 버립니다
- 이미 쓰인 번호면 `409 DUPLICATE_RESOURCE` 입니다
- `GET /admin/articles/duplicate-check` 의 확인 결과는 **보장이 아닙니다.** 두 관리자가 같은 번호를 확인하면 둘 다 "사용 가능" 을 받고 저장에서 한 명이 실패합니다. 최종 판정은 이 API 입니다

### `attachments` 는 업로드가 먼저입니다

`POST /admin/files` 로 파일을 올려 `file_url` 을 받은 뒤 그 값을 여기로 넘겨야 공지에 붙습니다.
업로드만으로는 아무 데도 연결되지 않습니다.

`storage_type` 은 **클라이언트가 정하지 않습니다.** 서버가 `file_url` 이 우리 버킷 주소인지 판정해
`S3` / `EXTERNAL` 을 스스로 붙입니다. 클라이언트 말을 믿으면 남의 주소를 S3 첨부로 등록해 두었다가
공지를 지울 때 엉뚱한 객체를 지우게 만들 수 있습니다.

# Response

**HTTP 201 Created** 입니다. 200 이 아닙니다.

## Response Param

| name | type | 비고 |
| --- | --- | --- |
| success | Boolean | 요청 성공 여부 |
| data | Object | 응답 데이터 |
| data.id | Long | 새로 만들어진 게시글 번호 |

> **응답에 담기는 것은 `id` 하나뿐입니다.** 제목도 상태도 돌려주지 않습니다.
> 저장 후 상세 화면을 그리려면 `GET /api/v1/admin/articles/{id}` 를 한 번 더 부르세요.
>
> **성공 응답에 `error` 키는 아예 없습니다.** `default-property-inclusion: non_null` 이라
> null 필드가 직렬화에서 빠집니다. `response.error === null` 로 성공을 판정하면 안 되고
> `success` 를 보거나 `error` 의 **존재 여부**를 봐야 합니다.

## Response Sample

```json
{
  "success": true,
  "data": {
    "id": 512
  }
}
```

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 400 | INVALID_INPUT_VALUE | 제목을 입력해 주세요. | `title` 이 없거나 공백 |
| 400 | INVALID_INPUT_VALUE | 본문을 입력해 주세요. | `content` 가 없거나 공백 |
| 400 | INVALID_INPUT_VALUE | 게시글 번호가 너무 큽니다. | `article_id` 가 1억 초과 |
| 400 | INVALID_INPUT_VALUE | {필드}: {제약 메시지} | Bean Validation 위반. 제목 500자 초과, 첨부 21개 이상, `vendors[].vendor_id` 누락, `attachments[].file_url` 누락, `size_bytes` 가 0 이하 등 |
| 400 | INVALID_STATUS_FOR_SOURCE | 휴지통 상태로는 공지를 만들 수 없습니다. | `status=TRASHED` |
| 400 | INVALID_STATUS_FOR_SOURCE | 공지 출처에서 사용할 수 없는 상태입니다. | `CLUB` + `PENDING_REVIEW` 처럼 짝이 안 맞는 조합 |
| 400 | INVALID_ARTICLE_PERIOD | 시작일은 종료일보다 늦을 수 없습니다. | `starts_on` > `ends_on` |
| 400 | VENDOR_TYPE_MISMATCH | 공지 출처(...)와 제공처 유형(...)이 다릅니다 | `source_type` 과 `vendors[].vendor_id` 의 유형 불일치. DB 트리거(IN002) |
| 400 | RELATED_RESOURCE_NOT_FOUND | 참조 대상이 존재하지 않습니다. | 없는 `category_id` · `vendor_id` (FK 위반 23503) |
| 400 | MALFORMED_REQUEST | 요청 본문을 해석할 수 없습니다. | JSON 파싱 실패, enum 오타 |
| 401 | UNAUTHORIZED | 인증이 필요합니다. | 토큰 없음·만료 |
| 403 | FORBIDDEN | 권한이 없습니다. | 관리자가 아님 |
| 409 | DUPLICATE_RESOURCE | 이미 존재하는 값입니다. | `article_id` 가 이미 쓰인 번호 (PK 위반 23505) |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 서버 측 처리 오류 |

> 트리거 메시지(IN002 등)는 **DB 가 만든 한글 문구가 그대로** 내려갑니다.
> `ErrorCode` 의 기본 문구보다 구체적이라 그대로 씁니다. 문구를 파싱하지 말고 `code` 로 분기하세요.
