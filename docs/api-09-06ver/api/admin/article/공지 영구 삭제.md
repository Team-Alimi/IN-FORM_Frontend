# 공지 영구 삭제

**휴지통에 있는 공지를 완전히 지웁니다. 휴지통 화면에서만 부릅니다. 되돌릴 수 없는 조작이고 딸린 첨부·북마크·댓글·알림·상태 이력이 함께 사라지며, S3 에 올라간 파일도 지워집니다.**

- **Method / Endpoint: `POST /api/v1/admin/articles/bulk/delete`**
- **Auth Required: Required (Admin)**

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Authorization | Bearer {access_token} | 서비스 Access Token | **필수** |
| Content-Type | application/json | | **필수** |

## Body Param

| Name | Type | Description | Required |
| --- | --- | --- | --- |
| ids | Array&lt;Long&gt; | 대상 게시글 번호. **1건 이상 200건 이하**. 원소에 `null` 불가 | **필수** |
| memo | String | **받기는 하지만 쓰이지 않습니다.** 아래 설명 참조 | 선택 |

> **`memo` 는 어디에도 기록되지 않습니다.** 요청 DTO 가 다른 벌크 API 와 공유되어 필드는
> 존재하고 500자 검증도 받지만, 삭제 경로는 그 값을 읽지 않습니다.
> 애초에 남길 자리가 없습니다 — 공지를 지우면 상태 이력도 CASCADE 로 함께 사라집니다.

### 휴지통에 있는 공지만 지울 수 있습니다

| 현재 상태 | 결과 |
| --- | --- |
| `TRASHED` | 삭제 |
| 그 외 전부 | **실패** — `NOT_IN_TRASH` |

되돌릴 수 없는 조작이라 "휴지통으로 보내기" 를 한 번 거치게 해서 실수의 여지를 줄입니다.
목록에서 잘못 선택한 공지가 곧바로 사라지면 복구할 방법이 없습니다.

### 함께 사라지는 것

`articles` 를 참조하는 외래 키가 자기 참조 하나를 빼고 전부 `ON DELETE CASCADE` 입니다.

| 대상 | 처리 |
| --- | --- |
| `attachments` | DB 행 삭제 + **S3 객체 삭제** |
| `bookmarks` · `article_likes` | 삭제 |
| `comments` | 삭제 |
| `notifications` | 삭제 |
| `article_categories` · `article_vendors` | 삭제 |
| `article_status_logs` | 삭제 — **누가 무엇을 지웠는지 DB 에 남지 않습니다** |
| 이 공지를 가리키던 `similar_article_id` | `NULL` 로 바뀝니다 (자기 참조 FK 만 `SET NULL`) |

> **★ DB 에는 삭제 흔적이 하나도 남지 않습니다.** 상태 이력이 함께 지워지기 때문입니다.
> 지금은 애플리케이션 로그(`공지 영구 삭제. articleId=... status=... title=... 첨부=...`)가
> 유일한 기록입니다. 관리자 조작 전용 감사 테이블이 없어서 생긴 공백이고, 보완이 필요한 지점입니다.

> **S3 객체 삭제는 커밋 이후에 일어납니다.** 트랜잭션 안에서 지우면 이후 롤백됐을 때
> "공지는 살아 있는데 이미지만 사라진" 상태가 되고 되돌릴 방법이 없습니다.
> 반대로 커밋 뒤에 지우다 실패하면 고아 객체가 남지만 그건 비용 문제일 뿐입니다.
> **S3 삭제 실패는 응답에 나타나지 않습니다** — 예외를 던지지 않고 로그만 남깁니다.

## Request Sample

```json
POST /api/v1/admin/articles/bulk/delete
{
  "ids": [41, 42]
}
```

# Response

## Response Param

| name | type | 비고 |
| --- | --- | --- |
| success | Boolean | 요청 성공 여부 |
| data | Object | 응답 데이터 |
| data.succeeded | Array&lt;Long&gt; | 영구 삭제된 게시글 번호 |
| data.failed | Array | 실패한 건 |
| data.failed[].id | Long | 실패한 게시글 번호 |
| data.failed[].code | String | 실패 사유 코드 |
| data.failed[].message | String | 사람이 읽을 사유 |

> **`failed` 가 비어 있지 않아도 HTTP 는 200 입니다.** 프론트는 상태 코드가 아니라
> `failed` 배열을 보고 판단해야 합니다.
>
> 요청한 번호는 **전부** 둘 중 한쪽에 나타납니다. 중복으로 담긴 번호는 한 번으로 합쳐집니다.
> **건별로 트랜잭션이 나뉘므로 되돌릴 수 없는 삭제가 일부만 커밋된 상태로 끝날 수 있습니다** —
> `succeeded` 에 담긴 것은 이미 사라진 것입니다.

### `data.failed[].code` 로 올 수 있는 값

| code | 원인 |
| --- | --- |
| ARTICLE_NOT_FOUND | 그 번호의 공지가 없음 |
| NOT_IN_TRASH | 휴지통에 없는 공지 (`휴지통에 있는 공지만 영구 삭제할 수 있습니다. articleId=...`) |
| RESOURCE_BUSY | 교착·직렬화 실패. 재시도하면 성공할 수 있습니다 |
| INTERNAL_SERVER_ERROR | 매핑되지 않은 실패 |

## Response Sample

```json
{
  "success": true,
  "data": {
    "succeeded": [41],
    "failed": [
      {
        "id": 42,
        "code": "NOT_IN_TRASH",
        "message": "휴지통에 있는 공지만 영구 삭제할 수 있습니다. articleId=42"
      }
    ]
  }
}
```

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 400 | INVALID_INPUT_VALUE | ids: 대상 공지를 선택해 주세요. | `ids` 가 비었거나 없음 |
| 400 | INVALID_INPUT_VALUE | ids: 한 번에 200건까지 처리할 수 있습니다. | `ids` 가 200건 초과 |
| 400 | INVALID_INPUT_VALUE | memo: 사유는 500자를 넘을 수 없습니다. | `memo` 500자 초과. **쓰이지 않는 값인데도 검증은 받습니다** |
| 400 | MALFORMED_REQUEST | 요청 본문을 해석할 수 없습니다. | JSON 파싱 실패 |
| 401 | UNAUTHORIZED | 인증이 필요합니다. | 토큰 없음·만료 |
| 403 | FORBIDDEN | 권한이 없습니다. | 관리자가 아님 |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 서버 측 처리 오류 |

> 위 표는 **요청 전체가 거부되는 경우**만입니다. 개별 건의 실패(`NOT_IN_TRASH` 포함)는
> HTTP 에러가 아니라 `data.failed[]` 로 내려갑니다.
