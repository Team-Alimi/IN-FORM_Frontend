# 관리자 댓글 목록·검색

**공지를 가로질러 댓글을 찾습니다. 신고나 문의가 들어왔을 때 "이 단어가 든 댓글" 또는 "이 사람이 쓴 댓글" 을 찾아 일괄 삭제 대상으로 고르는 화면에서 씁니다. 관리자 화면에서 운영을 완결하기 위한 조회이므로 작성자 이메일·이름을 가리지 않습니다.**

- **Method / Endpoint: `GET /api/v1/admin/comments`**
- **Auth Required: Required (Admin)**

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Authorization | Bearer {access_token} | 서비스 Access Token (ROLE_ADMIN) | **필수** |

## Query Param

| Name | Type | Description | Required | Default |
| --- | --- | --- | --- | --- |
| page | Integer | 조회할 페이지 번호 (**1부터 시작**) | 선택 | 1 |
| size | Integer | 페이지당 건수. **최대 50** | 선택 | 20 |
| keyword | String | 본문 부분 일치. **2글자 미만은 무시** | 선택 | - |
| article_id | Long | 특정 공지의 댓글만 | 선택 | - |
| user_id | Long | 특정 작성자의 댓글만 | 선택 | - |

### `sort` 는 받지 않습니다

**정렬은 최신순(`created_at desc`, 동률 시 `id desc`)으로 고정입니다.** 조회가 native 쿼리라
클라이언트 정렬이 끼어들 경로 자체가 없습니다. `sort` 를 붙여 보내도 **오류 없이 무시**됩니다.
신고 대응은 방금 달린 것부터 보는 화면이라 다른 정렬이 필요하지 않습니다.

### `keyword` 주의

**1글자 검색어는 400 이 아니라 조용히 무시됩니다.** 조건이 아예 빠진 것과 같아 전체 목록이 나옵니다.
공지 목록(`GET /articles`)이 1글자에 `400 SEARCH_KEYWORD_TOO_SHORT` 를 주는 것과 **다르게 동작**하므로,
검색어 길이 검사는 화면에서 해야 합니다.

- 대소문자를 구분하지 않습니다 (`lower()` 비교)
- `%`, `_`, `\` 는 이스케이프되어 **문자 그대로** 취급됩니다 (패턴으로 해석되지 않습니다)
- 댓글 본문에는 검색 인덱스가 없습니다. `article_id` 나 `user_id` 로 함께 좁혀 쓰는 것을 전제로 만든 조건입니다

## Request Sample

```
# 기본 목록 (1페이지, 20건, 삭제 제외)
GET /api/v1/admin/comments

# 본문 검색
GET /api/v1/admin/comments?keyword=광고&page=1&size=20

# 특정 사용자가 쓴 댓글을 공지 가로질러 모두
GET /api/v1/admin/comments?user_id=77

# 특정 공지의 댓글 (삭제된 자리 포함)
GET /api/v1/admin/comments?article_id=105
```

# Response

## Response Param

| name | type | 비고 |
| --- | --- | --- |
| success | Boolean | 요청 성공 여부 |
| data | Object | 응답 데이터 |
| data.page_info | Object | 페이징 정보 |
| data.page_info.current_page | Integer | 현재 페이지 번호 (1부터). 결과가 0건이어도 1 |
| data.page_info.size | Integer | 페이지당 건수 |
| data.page_info.total_pages | Integer | 전체 페이지 수. 0건이면 0 |
| data.page_info.total_items | Long | 전체 건수 |
| data.page_info.has_next | Boolean | 다음 페이지 존재 여부 |
| data.content | Array | 댓글 목록 |
| data.content[].id | Long | 댓글 ID |
| data.content[].article_id | Long | 댓글이 달린 공지 ID |
| data.content[].article_title | String | 공지 제목 |
| data.content[].author_id | Long | 작성자 ID |
| data.content[].author_email | String | 작성자 이메일. **가리지 않습니다** |
| data.content[].author_name | String | 작성자 이름. **가리지 않습니다** |
| data.content[].author_withdrawn | Boolean | 탈퇴 회원 여부 |
| data.content[].content | String | 본문. **삭제된 댓글이면 빈 문자열(`""`)** |
| data.content[].created_at | String | 작성 일시 (ISO-8601 offset) |
| error | Object | 에러 정보. 성공 시 null — `non_null` 설정이라 **성공 응답에는 이 키가 아예 없습니다** |


> **작성자 정보를 가리지 않는 것은 의도입니다.** 사용자용 댓글 목록은 탈퇴자를 "탈퇴한 사용자" 로 감추지만,
> 이 화면은 신고·문의에 대응해 **같은 사람이 쓴 다른 댓글을 찾는** 곳입니다. 가리면 기능이 성립하지 않습니다.
> 탈퇴 여부는 `author_withdrawn` 으로 표시하세요.

> (`POST /admin/comments/bulk/delete` 참조). 삭제 확인 문구를 다르게 띄우라고 내려주는 값입니다.

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 400 | INVALID_INPUT_VALUE | {파라미터명}: 값의 형식이 올바르지 않습니다. | `article_id`·`user_id` 에 숫자가 아닌 값, `include_deleted` 에 boolean 이 아닌 값, `page`·`size` 형식 오류 |
| 401 | UNAUTHORIZED | 인증이 필요합니다. | 토큰 없음·만료 |
| 403 | FORBIDDEN | 권한이 없습니다. | 로그인은 했으나 ROLE_ADMIN 이 아님 |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 서버 측 처리 오류 |

> 이 엔드포인트는 **자체적으로 던지는 비즈니스 예외가 없습니다.** 조건에 맞는 댓글이 없으면
> 404 가 아니라 `content: []` 와 `total_items: 0` 인 **200** 입니다.
> 없는 `article_id`·`user_id` 를 넣어도 마찬가지로 빈 목록입니다.

> **삭제된 댓글은 나오지 않습니다.** 지우면 행째 사라지므로 "삭제된 댓글 포함" 같은 옵션이 없습니다.
> 답글 기능이 없어 자리를 남길 이유도 사라졌습니다.
