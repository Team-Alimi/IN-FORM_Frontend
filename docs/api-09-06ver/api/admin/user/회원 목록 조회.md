# 회원 목록 조회

**관리자 페이지의 회원 관리 화면이 열릴 때, 그리고 검색어·필터를 바꿀 때마다 부르는 목록입니다. 이메일·이름 부분 일치 검색과 권한·상태 필터, 페이지네이션을 지원합니다. 여기서 고른 회원을 `PATCH /api/v1/admin/users/{userId}/role` 로 승격·강등합니다.**

- **Method / Endpoint: `GET /api/v1/admin/users`**
- **Auth Required: Required (Admin)**

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Authorization | Bearer {access_token} | 관리자 Access Token | **필수** |

## Query Param

| Name | Type | Description | Required | Default |
| --- | --- | --- | --- | --- |
| page | Integer | 조회할 페이지 번호 (**1부터 시작**) | 선택 | 1 |
| size | Integer | 페이지당 회원 수. **최대 50** | 선택 | 20 |
| keyword | String | 이메일·이름 부분 일치. **2글자 이상** | 선택 | - |
| role | String | `USER` \| `ADMIN` | 선택 | - |
| status | String | `ACTIVE` \| `WITHDRAWN` | 선택 | - |

### `keyword` 주의 — 1글자는 에러가 아니라 **무시**입니다

> 공지 목록(`GET /articles`)은 1글자 검색어에 `400 SEARCH_KEYWORD_TOO_SHORT` 를 돌려주지만,
> **이 API 는 다릅니다.** 공백을 제거한 길이가 2글자 미만이면 `keyword` 를 통째로 버리고
> **필터 없는 전체 목록**을 200 으로 돌려줍니다. 프론트가 "검색했는데 왜 전체가 나오지" 를
> 겪는 지점이므로, 입력이 1글자일 때는 화면에서 먼저 막아 주세요.

- 대소문자를 구분하지 않습니다. 이메일과 이름 양쪽을 소문자로 낮춰 비교합니다
- `%` 와 `_` 는 **리터럴로** 검색됩니다. `kim_hs` 를 넣으면 `kimahs` 는 걸리지 않습니다
  (LIKE 패턴 이스케이프 처리)
- `role`·`status` 와 함께 보내면 AND 로 걸립니다

### 정렬은 고정입니다 — `sort` 는 무시됩니다

**가입 최신순(`created_at DESC`, 동률이면 `id DESC`) 고정입니다.** Pageable 이 `sort` 파라미터를
받기는 하지만 서버가 버립니다. Spring Data 가 클라이언트 정렬을 검증 없이 `ORDER BY` 뒤에
이어 붙이는 구조라, `?sort=foo` 하나로 JPQL 파싱이 깨지면서 SQLSTATE 없는 500 이 나가기 때문입니다.

> 따라서 `?sort=nonExistingProperty` 를 보내도 **에러가 아니라 200** 이고, 결과 순서도 바뀌지 않습니다.
> 정렬 UI 는 이 API 에 붙일 수 없습니다.

### 페이지 파라미터의 경계

- `page=0` 이나 음수는 **1페이지**로 처리됩니다
- `size` 가 50 을 넘으면 **50 으로 잘립니다** (요청 하나가 회원 전체를 긁어가는 것을 막는 상한)
- 숫자로 해석되지 않는 값(`page=abc`)은 기본값으로 대체됩니다 — 400 이 아닙니다

## Request Sample

```
# 기본 목록 (1페이지, 20건, 가입 최신순)
GET /api/v1/admin/users

# 이메일 조각으로 검색
GET /api/v1/admin/users?keyword=kim

# 관리자만 추리기
GET /api/v1/admin/users?role=ADMIN

# 탈퇴한 회원만, 2페이지
GET /api/v1/admin/users?status=WITHDRAWN&page=2&size=20
```

# Response

## Response Param

| name | type | 비고 |
| --- | --- | --- |
| success | Boolean | 요청 성공 여부 |
| data | Object | 응답 데이터 |
| data.content | Array | 회원 목록 |
| data.content[].id | Long | 회원 고유 ID. 권한 변경 API 의 `{userId}` |
| data.content[].email | String | 이메일 (**소문자로만 저장**) |
| data.content[].name | String | 이름. 값이 없으면 **필드 자체가 빠집니다** |
| data.content[].role | String | `USER` \| `ADMIN` |
| data.content[].status | String | `ACTIVE` \| `WITHDRAWN` |
| data.content[].onboarding_completed | Boolean | 온보딩 완료 여부 |
| data.content[].created_at | String | 가입 일시 (ISO-8601 offset) |
| data.content[].withdrawn_at | String | 탈퇴 일시. **활성 회원은 필드 자체가 빠집니다** |
| data.page_info | Object | 페이징 정보 |
| data.page_info.current_page | Integer | 현재 페이지 번호 (1부터. 0건이어도 1) |
| data.page_info.size | Integer | 페이지당 건수 |
| data.page_info.total_pages | Integer | 전체 페이지 수 (0건이면 0) |
| data.page_info.total_items | Long | 전체 건수 |
| data.page_info.has_next | Boolean | 다음 페이지 존재 여부 |

> **`null` 필드는 응답에서 아예 빠집니다** (`default-property-inclusion: non_null`).
> `name` 과 `withdrawn_at` 이 여기 해당합니다. `withdrawn_at === null` 로 탈퇴 여부를 판단하면
> 키가 없어서 `undefined` 가 나옵니다 — **탈퇴 여부는 `status` 로 판단**하세요.
> 성공 응답에는 `error` 키도, 실패 응답에는 `data` 키도 없습니다.

> **이름과 이메일을 가리지 않습니다.** 탈퇴한 회원도 마찬가지입니다. 댓글 화면에서는
> "탈퇴한 사용자" 로 감추지만, 여기는 권한을 줄 대상을 사람으로 특정해야 하는 화면이라
> 가리면 기능 자체가 성립하지 않습니다. `/admin/**` 은 관리자 전용 경로입니다.

> **탈퇴한 회원도 목록에 남습니다.** 탈퇴는 soft delete 라 행이 지워지지 않습니다.
> 게다가 관리자가 탈퇴하면 `status` 만 `WITHDRAWN` 이 되고 `role` 은 `ADMIN` 인 채로 남으므로,
> `role=ADMIN` 필터 결과에 탈퇴한 관리자가 섞여 나올 수 있습니다.

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 400 | INVALID_INPUT_VALUE | role: 값의 형식이 올바르지 않습니다. | `role`·`status` 에 허용값 밖 문자열. **enum 은 대문자입니다** (`admin` 은 실패) |
| 401 | UNAUTHORIZED | 인증이 필요합니다. | 토큰 없음·만료. 본인이 방금 강등당해 토큰이 무효화된 경우도 여기입니다 |
| 403 | FORBIDDEN | 권한이 없습니다. | 로그인은 되었으나 `ROLE_ADMIN` 이 아님 |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 서버 측 처리 오류 |

> 검색어가 짧거나 조건에 맞는 회원이 없어도 에러가 아닙니다. `content` 가 빈 배열이고
> `total_items` 가 0 인 **200** 입니다.
