# 북마크 목록 조회

**로그인한 사용자가 저장해 둔 공지를 목록으로 돌려줍니다. 필터·정렬·페이징 규약이 일반 공지 목록과 완전히 같아서, 프론트는 두 화면에 같은 필터 UI 를 그대로 쓸 수 있습니다. 마이페이지의 "저장한 공지" 탭을 열 때 호출합니다.**

- **Method / Endpoint: `GET /api/v1/bookmarks`**
- **Auth Required: Required (User)**

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Authorization | Bearer {access_token} | 서비스 Access Token | **필수** |

## Query Param

| Name | Type | Description | Required | Default |
| --- | --- | --- | --- | --- |
| page | Integer | 조회할 페이지 번호 (**1부터 시작**) | 선택 | 1 |
| size | Integer | 페이지당 건수. **최대 50** | 선택 | 20 |
| sort | String | `{필드},{asc\|desc}` 형태. 허용 필드는 아래 표 | 선택 | `published_at,desc` |
| source_type | String | `SCHOOL` \| `CLUB`. 생략 시 통합 | 선택 | - |
| category_id | List&lt;Long&gt; | 분류 ID 다중 필터 (예: `1,2`) | 선택 | - |
| vendor_id | List&lt;Long&gt; | 제공처 ID 다중 필터 (예: `5,12`) | 선택 | - |
| keyword | String | 제목·본문 검색어. **2글자 이상** | 선택 | - |
| starts_from | LocalDate | 기간 필터 시작 (yyyy-MM-dd) | 선택 | - |
| ends_to | LocalDate | 기간 필터 끝 (yyyy-MM-dd) | 선택 | - |
| has_deadline | Boolean | 마감일이 있는 공지만 | 선택 | false |

### `interest_only` 는 받지 않습니다

**공지 목록에 있는 `interest_only` 가 여기에는 없습니다.** 보내도 무시되고 400 도 아닙니다.
내가 직접 저장한 목록을 다시 관심 분야로 거르는 것은 기대하지 않는 동작이라 서버가 항상 끈 상태로 조회합니다.
관심 분야를 바꿔도 이미 저장한 공지가 목록에서 사라지지 않습니다.

### `sort` 허용 필드

`published_at` · `created_at` · `updated_at` · `ends_on` · `bookmark_count`

목록에 없는 값을 보내면 `400 INVALID_SORT_PROPERTY` 입니다.
서버가 **항상 `id desc` 를 뒤에 붙입니다** — 일괄 발행하면 30건의 `published_at` 이 완전히 같아지는데,
tie-breaker 가 없으면 페이지 경계에서 같은 공지가 두 번 나오거나 누락됩니다.

> **`created_at` · `updated_at` 은 공지의 생성·수정 시각입니다. 북마크를 저장한 시각이 아닙니다.**
> 정렬 컬럼은 전부 `articles` 테이블을 가리킵니다. **"내가 최근에 저장한 순서" 로는 정렬할 수 없습니다** —
> `bookmarks.created_at` 은 존재하지만 정렬 화이트리스트에도, 응답 필드에도 들어 있지 않습니다.
> 화면에 "최근 저장순" 을 두려면 서버 작업이 먼저 필요합니다.

> `sort=ends_on` (마감 임박순) 은 `has_deadline=true` 와 **함께만** 쓸 수 있습니다.
> 마감일 없는 공지가 섞이면 부분 인덱스를 벗어나 전체 정렬이 되기 때문입니다.
> 단독으로 보내면 `400 INVALID_SORT_PROPERTY` 입니다.

### 기간 필터(`starts_from` · `ends_to`)는 "겹침" 판정입니다

이름과 달리 "시작일이 X 이후" 가 아니라 **공지의 기간이 지정한 구간과 겹치는가**를 봅니다.

- `starts_from` → `ends_on IS NULL OR ends_on >= starts_from`
- `ends_to` → `starts_on IS NULL OR starts_on <= ends_to`

한쪽만 보내면 반대쪽은 무한으로 봅니다. 공지 쪽 날짜가 비어 있어도 무한으로 봅니다 —
"마감일 없는 상시 모집" 이 기간 검색에서 빠지면 안 되기 때문입니다.

> **다만 `starts_from` 이나 `ends_to` 중 하나라도 보내면 `starts_on` · `ends_on` 이 둘 다 없는 공지는 제외됩니다.**
> 기간으로 찾는다는 건 행사·모집을 찾는다는 뜻인데, 날짜가 없는 일반 안내까지 걸리면 필터가 의미를 잃습니다.
> 기간 필터를 켠 순간 결과 건수가 눈에 띄게 줄어드는 것은 정상입니다.

### 목록에 나오는 공지의 범위

일반 피드보다 **넓습니다.**

| 공지 상태 | 북마크 목록 | 일반 피드 |
| --- | --- | --- |
| `PUBLISHED` | 나옴 | 나옴 |
| `PENDING_REVIEW` 이면서 한 번이라도 배포된 적 있음 | **나옴** (`under_review: true`) | 안 나옴 |
| `PENDING_REVIEW` 이면서 배포된 적 없음 | 안 나옴 | 안 나옴 |
| `TRASHED` · `DRAFT` · `READY_TO_PUBLISH` | 안 나옴 | 안 나옴 |

크롤러가 원본의 오탈자 하나만 고쳐도 공지는 재검수 대기로 내려갑니다.
피드 기준을 그대로 쓰면 **사용자가 저장해 둔 공지가 목록에서 사라지므로**, 여기서는 남겨 두고
`under_review` 로 "검수 중" 배지를 띄웁니다.

## Request Sample

```
# 기본 목록 (1페이지, 20건, 발행 최신순)
GET /api/v1/bookmarks

# 학교 공지만, 2페이지
GET /api/v1/bookmarks?source_type=SCHOOL&page=2&size=20

# 다중 분류 + 키워드
GET /api/v1/bookmarks?category_id=1,2&keyword=장학금

# 마감 임박순 (has_deadline=true 가 반드시 함께 와야 합니다)
GET /api/v1/bookmarks?has_deadline=true&sort=ends_on,asc

# 기간 겹침 필터
GET /api/v1/bookmarks?starts_from=2026-02-01&ends_to=2026-02-28
```

# Response

### `deadline_status` 분류 기준

| 값 | 조건 |
| --- | --- |
| `UPCOMING` | 오늘 &lt; `starts_on` |
| `OPEN` | 진행 중 |
| `CLOSING_SOON` | `ends_on` 까지 **3일 이내** |
| `CLOSED` | 오늘 &gt; `ends_on` |
| `ALWAYS` | `starts_on` · `ends_on` 이 둘 다 없음 (상시) |

> DB 컬럼이 아니라 **조회 시각에 계산**하는 파생값입니다. 정렬 기준으로는 쓸 수 없고,
> 마감 정렬은 `ends_on` 으로 합니다. 한 페이지 안의 모든 항목은 같은 기준일로 판정됩니다.

## Response Param

| name | type | 비고 |
| --- | --- | --- |
| success | Boolean | 요청 성공 여부 |
| data | Object | 응답 데이터 |
| data.content | Array | 북마크한 공지 목록. 없으면 `[]` |
| data.content[].id | Long | 공지 고유 ID |
| data.content[].source_type | String | `SCHOOL` \| `CLUB` |
| data.content[].title | String | 제목 |
| data.content[].summary | String | AI 생성 요약. **미생성이면 키 자체가 없음** |
| data.content[].published_at | String | 발행 일시 (ISO-8601 offset) |
| data.content[].starts_on | String | 시작일 (yyyy-MM-dd). **없으면 키 자체가 없음** |
| data.content[].ends_on | String | 마감일 (yyyy-MM-dd). **없으면 키 자체가 없음** |
| data.content[].deadline_status | String | 마감 상태 (위 표) |
| data.content[].bookmark_count | Integer | 이 공지의 전체 북마크 수 (나 말고 전원) |
| data.content[].comment_count | Integer | 댓글 수 |
| data.content[].view_count | Long | 조회 수 |
| data.content[].is_bookmarked | Boolean | 본인 북마크 여부. **이 목록에서는 항상 `true`** |
| data.content[].has_attachment | Boolean | 첨부 존재 여부 (클립 아이콘용). 개수·목록은 내려가지 않음 |
| data.content[].under_review | Boolean | 재검수 중 배지. **이 목록에서만 `true` 가 될 수 있음** |
| data.content[].vendors | Array | 제공처 목록. 없으면 `[]` |
| data.content[].vendors[].id | Long | 제공처 ID |
| data.content[].vendors[].name | String | 제공처 이름 |
| data.content[].vendors[].initial | String | 축약 표시 (좁은 칸용, 예: "컴공") |
| data.content[].vendors[].type | String | `SCHOOL` \| `CLUB` |
| data.content[].categories | Array | 분류 목록. 없으면 `[]` |
| data.content[].categories[].id | Long | 분류 ID |
| data.content[].categories[].name | String | 분류 이름 |
| data.page_info | Object | 페이징 정보 |
| data.page_info.current_page | Integer | 현재 페이지 번호 (1부터). **0건이어도 1** |
| data.page_info.size | Integer | 페이지당 건수 |
| data.page_info.total_pages | Integer | 전체 페이지 수. 0건이면 0 |
| data.page_info.total_items | Long | 전체 건수 |
| data.page_info.has_next | Boolean | 다음 페이지 존재 여부 |
| error | Object | 에러 정보. **성공 시 키 자체가 없음** |

> **null 인 필드는 응답에서 아예 빠집니다** (`default-property-inclusion: non_null`).
> `summary`, `starts_on`, `ends_on` 은 `null` 로 오는 게 아니라 **키가 없습니다.**
> `response.data.content[0].summary` 를 곧바로 참조하면 `undefined` 이므로, 존재 여부를 먼저 확인하세요.

> **`is_bookmarked` 는 이 목록에서 항상 `true`** 입니다. 북마크 필터를 이미 통과한 결과이기 때문입니다.
> 카드 컴포넌트를 공지 목록과 공유한다면 이 값을 그대로 써도 무방합니다.

> **`bookmark_count` 는 서비스 전체의 저장 수**입니다. 내 저장 개수가 아닙니다.
> 내가 저장한 총 개수는 `data.page_info.total_items` 입니다.

> `vendors` · `categories` 는 배열입니다. 같은 공지가 학과 게시판과 교무처 게시판에 동시에 올라오는 일이 흔하고,
> 분류도 여러 개 붙습니다. `vendors` 는 중복 제공처를 합쳐서 내려갑니다.

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 400 | SEARCH_KEYWORD_TOO_SHORT | 검색어는 2글자 이상 입력해야 합니다. | `keyword` 를 공백 제거 후 1글자로 보낸 경우. pg_bigm 이 2-gram 이라 인덱스가 후보를 좁히지 못합니다 |
| 400 | INVALID_SORT_PROPERTY | 허용되지 않은 정렬 기준입니다: {필드} | `sort` 화이트리스트 밖의 필드 |
| 400 | INVALID_SORT_PROPERTY | 마감 임박순은 has_deadline=true 와 함께만 사용할 수 있습니다. | `sort=ends_on` 을 `has_deadline=true` 없이 보낸 경우 |
| 400 | INVALID_INPUT_VALUE | {파라미터명}: 값의 형식이 올바르지 않습니다. | `source_type=club` (enum 은 대문자), `starts_from=2026-13-01`, `category_id=abc` 등 |
| 401 | UNAUTHORIZED | 인증이 필요합니다. | 토큰 없음·만료 |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 서버 측 처리 오류 |

> `page` · `size` 는 범위를 벗어나도 **오류가 아니라 조용히 보정**됩니다.
> `size=100` 은 50 으로 잘리고, `page=0` 은 1페이지로 취급됩니다.
> 응답의 `page_info.size` 를 보면 실제로 적용된 값을 알 수 있습니다.

> 결과가 0건인 것은 오류가 아닙니다. `content: []`, `total_pages: 0`, `current_page: 1` 로 200 이 나갑니다.
