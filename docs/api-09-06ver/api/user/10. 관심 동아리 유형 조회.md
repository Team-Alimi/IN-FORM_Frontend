# 관심 동아리 유형 조회

**내가 고른 관심 동아리 유형(학술·체육·봉사 등) 목록을 조회합니다. 온보딩 4단계에서 체크박스의 초기 선택 상태를 그릴 때, 그리고 마이페이지 관심사 관리 화면을 열 때 부릅니다. 여기서 고른 유형이 동아리 공지 추천의 기준이 됩니다.**

- **Method / Endpoint: `GET /api/v1/users/me/interests/club-types`**
- **Auth Required: Required (User)**

> **이건 「내가 고른 것」입니다. 「고를 수 있는 전체 목록」이 아닙니다.**
> 선택 화면의 칩을 그리려면 [동아리 유형 조회](../common/%EB%8F%99%EC%95%84%EB%A6%AC%20%EC%9C%A0%ED%98%95%20%EC%A1%B0%ED%9A%8C.md) (`GET /api/v1/club-types`) 를
> 부르고, 이 응답의 id 와 대조해 선택 상태를 표시하세요.
> `/categories` 와 `/users/me/interests/categories` 의 관계와 같습니다.

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Authorization | Bearer {access_token} | 서비스 Access Token | **필수** |

## Request Sample

```
GET /api/v1/users/me/interests/club-types
Authorization: Bearer eyJ...
```

# Response

## Response Param

| name | type | 비고 |
| --- | --- | --- |
| success | Boolean | 요청 성공 여부 |
| data | Array | **객체가 아니라 배열입니다.** 선택한 항목 목록 |
| data[].id | Long | `club_types.id` |
| data[].name | String | 동아리 유형 이름 (예: `학술`) |
| error | Object | 에러 정보 (성공 시 키 자체가 빠짐) |

> **`data` 가 배열입니다.** `data.content` / `data.page_info` 로 감싸지 않고 페이징도 없습니다.

> **`code`·`is_active`·`sort_order` 는 내려가지 않습니다.** id 와 이름 두 개뿐입니다.

> **정렬은 이름 오름차순(`name ASC`)입니다.** 마스터 목록의 `sort_order` 와 다르므로
> 두 화면의 순서를 맞추려면 프론트에서 다시 정렬해야 합니다.

> **비활성화된 유형도 여기에는 그대로 나옵니다.** 관리자가 유형을 비활성화해도 이미 선택해 둔
> 관계는 지우지 않습니다. 그 항목은 선택 목록 화면에는 없는데 이 응답에는 있을 수 있습니다.

> **선택이 없으면 빈 배열 `[]` 입니다.** `null` 이 아닙니다.

## Response Sample

```json
{
  "success": true,
  "data": [
    { "id": 2, "name": "봉사" },
    { "id": 1, "name": "학술" }
  ]
}
```

선택이 하나도 없을 때:

```json
{
  "success": true,
  "data": []
}
```

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 401 | UNAUTHORIZED | 인증이 필요합니다. | 토큰 없음·만료·무효화됨 |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 서버 측 처리 오류 |

> **이 조회는 `USER_NOT_FOUND` 를 내지 않습니다.** 사용자 행을 확인하지 않고 관계 테이블만 읽기
> 때문입니다. 저장(`PUT`) 쪽은 사용자 행을 확인하므로 `404` 가 있습니다.
