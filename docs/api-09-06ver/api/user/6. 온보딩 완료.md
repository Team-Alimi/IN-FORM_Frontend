# 온보딩 완료

**온보딩을 마쳤다고 표시합니다. 구독 학과·기관, 관심 분류, 관심 동아리 유형은 각 단계의 PUT 으로 이미 저장된 상태이고, 이 호출은 완료 플래그만 세웁니다. 온보딩 마지막 화면의 "시작하기" 버튼이 부르며, 응답으로 갱신된 프로필 전체가 내려옵니다.**

- **Method / Endpoint: `POST /api/v1/users/me/onboarding/complete`**
- **Auth Required: Required (User)**

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Authorization | Bearer {access_token} | 서비스 Access Token | **필수** |

요청 body 가 없습니다. 선택 항목은 이 호출로 보내지 않습니다 — 앞선 PUT 들이 이미 저장했습니다.

> **body 를 보내도 무시됩니다.** 여기에 `ids` 를 실어 보내면 저장되지 않은 채 온보딩만 완료되어,
> 사용자는 아무것도 고르지 않은 상태로 서비스에 들어갑니다. 각 단계의 PUT 이 `200` 을 돌려준 것을
> 확인한 뒤에 이 API 를 부르세요.

## Request Sample

```
POST /api/v1/users/me/onboarding/complete
Authorization: Bearer eyJ...
```

# Response

## Response Param

| name | type | 비고 |
| --- | --- | --- |
| success | Boolean | 요청 성공 여부 |
| data | Object | 갱신된 프로필 전체 (`GET /users/me` 와 같은 모양) |
| data.id | Long | 사용자 고유 ID |
| data.email | String | 로그인 이메일 (항상 소문자) |
| data.name | String | 구글 프로필 이름. **없으면 키 자체가 응답에서 빠집니다** |
| data.role | String | `USER` \| `ADMIN` |
| data.onboarding_completed | Boolean | 이 호출 이후에는 항상 `true` |
| data.email_notification_enabled | Boolean | 마감 알림 메일 수신 여부 |
| error | Object | 에러 정보 (성공 시 키 자체가 빠짐) |

> **멱등입니다.** 이미 완료한 사용자가 다시 불러도 오류 없이 `200` 이고, **최초 완료 시각을
> 유지**합니다. 완료 시각이 뒤로 밀리지 않습니다.

> **선택을 하나도 하지 않았어도 통과합니다.** 이 호출 자체는 선택 개수를 검사하지 않습니다.
> 최소 1개 검증은 각 단계의 PUT 이 담당하며, 그것도 "온보딩 중일 때 빈 배열 거부" 일 뿐
> 단계를 아예 건너뛰고 이 API 만 부르는 것은 막지 않습니다. 구독 0개는 유효한 상태이고
> 전체 피드는 그대로 보입니다.

> **완료 이후에는 각 PUT 의 규칙이 바뀝니다.** 온보딩 중에는 거부되던 `ids: []` 가 이 호출
> 이후에는 "전부 해제" 로 정상 처리됩니다. 서버가 온보딩 여부를 DB 의 완료 시각으로 판정하기
> 때문입니다.

> **토큰은 갱신되지 않습니다.** 로그인·토큰 재발급 응답에도 `onboarding_completed` 가 실려
> 오지만, 이 호출로 기존 Access Token 이 바뀌지는 않습니다. 프론트는 이 응답 값으로 화면 상태를
> 갱신하세요.

## Response Sample

```json
{
  "success": true,
  "data": {
    "id": 7,
    "email": "kim@inha.ac.kr",
    "name": "김인하",
    "role": "USER",
    "onboarding_completed": true,
    "email_notification_enabled": true
  }
}
```

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 401 | UNAUTHORIZED | 인증이 필요합니다. | 토큰 없음·만료·무효화됨 |
| 404 | USER_NOT_FOUND | 존재하지 않는 사용자입니다. | 계정이 없거나 이미 `WITHDRAWN` |
| 409 | CONCURRENT_MODIFICATION | 다른 사용자가 먼저 수정했습니다. 새로고침 후 다시 시도해 주세요. | 저장 중 관리자가 같은 계정의 권한을 바꾼 경우 (낙관적 잠금) |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 서버 측 처리 오류 |

> 이미 완료한 사용자가 다시 부르는 경우는 행을 갱신하지 않으므로 `409` 도 나지 않습니다.
