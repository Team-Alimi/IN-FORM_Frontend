# 내 프로필 조회

**로그인한 본인의 계정 정보를 조회합니다. 앱 진입 직후에 불러 `onboarding_completed` 로 온보딩 화면으로 보낼지 판단하고, 마이페이지 상단의 이름·이메일·알림 수신 설정을 그립니다. 대상 사용자를 URL 로 받지 않고 항상 Access Token 에 담긴 id 를 쓰므로, 남의 프로필을 조회할 경로 자체가 없습니다.**

- **Method / Endpoint: `GET /api/v1/users/me`**
- **Auth Required: Required (User)**

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Authorization | Bearer {access_token} | 서비스 Access Token | **필수** |

## Request Sample

```
GET /api/v1/users/me
Authorization: Bearer eyJ...
```

# Response

## Response Param

| name | type | 비고 |
| --- | --- | --- |
| success | Boolean | 요청 성공 여부 |
| data | Object | 응답 데이터 |
| data.id | Long | 사용자 고유 ID |
| data.email | String | 로그인 이메일. **항상 소문자**입니다 (저장 전에 정규화하고 DB CHECK 가 강제) |
| data.name | String | 구글 프로필 이름. **없으면 키 자체가 응답에서 빠집니다** |
| data.role | String | `USER` \| `ADMIN` |
| data.onboarding_completed | Boolean | 온보딩 완료 여부 |
| data.email_notification_enabled | Boolean | 마감 알림 메일 수신 여부. 가입 시 기본값 `true` |
| error | Object | 에러 정보 (성공 시 키 자체가 빠짐) |

> **`name` 은 없을 수 있고, 없으면 `null` 이 아니라 키가 사라집니다.**
> 구글 id_token 에 `name` 클레임이 없으면 그대로 비워 둡니다. 응답 직렬화가
> `default-property-inclusion: non_null` 이라 `"name": null` 이 아니라 `name` 키 자체가 빠집니다.
> `data.name.length` 같은 접근은 터집니다. 이름 표시는 항상 기본값을 준비해 두세요.

> **`onboarding_completed` 가 `false` 여도 서버가 다른 API 를 막지 않습니다.**
> 차단이 아니라 유도입니다. 온보딩을 건너뛴 상태로도 공지 목록은 그대로 열립니다.
> 다만 구독·관심사를 저장하는 PUT 들은 온보딩 중일 때 빈 배열을 거부합니다
> (`ONBOARDING_MIN_SELECTION`). 같은 값이 로그인·토큰 재발급 응답에도 실려 옵니다.

> **`major_vendor_id` 는 이 응답에 없습니다.** `users.major_vendor_id` 컬럼은 복수전공을
> 지원하면서 v11 스키마에서 제거됐습니다. 구독 학과는 `GET /users/me/vendors` 로 따로 읽습니다.
> 구판 명세를 본 프론트가 있을 수 있어 남겨 둡니다.

> **`role` 은 DB 값입니다.** Access Token 안에 박힌 권한과 다를 수 있는 구간이 잠깐 존재하지만,
> 관리자가 권한을 실제로 바꾸면 그 사용자의 기존 Access Token 이 즉시 무효화되므로
> 다음 요청이 `401` 을 받습니다. 그때는 재로그인이 아니라 **토큰 재발급**으로 복구합니다
> (`POST /auth/token/refresh` 가 사용자를 다시 읽어 새 권한이 담긴 토큰을 줍니다).

## Response Sample

```json
{
  "success": true,
  "data": {
    "id": 7,
    "email": "kim@inha.ac.kr",
    "name": "김인하",
    "role": "USER",
    "onboarding_completed": true,
    "email_notification_enabled": true
  }
}
```

이름이 없는 계정 (`name` 키가 통째로 빠집니다):

```json
{
  "success": true,
  "data": {
    "id": 8,
    "email": "noname@inha.ac.kr",
    "role": "USER",
    "onboarding_completed": false,
    "email_notification_enabled": true
  }
}
```

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 401 | UNAUTHORIZED | 인증이 필요합니다. | 토큰 없음·만료·서명 불일치. 탈퇴·전체 로그아웃·권한 변경으로 **무효화된 토큰**도 여기 해당합니다 |
| 404 | USER_NOT_FOUND | 존재하지 않는 사용자입니다. | 토큰은 유효하지만 계정이 없거나 이미 `WITHDRAWN` 인 경우 |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 서버 측 처리 오류 |
