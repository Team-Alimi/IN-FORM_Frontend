# 관리자 공지 상세 조회

**검수 화면에서 공지 한 건의 전체 내용을 봅니다. 본문·첨부·제공처 원본 링크·분류에 더해 검수에 필요한 값(상태, 중복 판정, 최근 상태 이력 5건)이 함께 내려갑니다. 목록에서 한 건을 클릭했을 때, 그리고 수정(`PATCH /admin/articles/{id}`) 직후에 부릅니다.**

- **Method / Endpoint: `GET /api/v1/admin/articles/{articleId}`**
- **Auth Required: Required (Admin)**

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Authorization | Bearer {access_token} | 서비스 Access Token | **필수** |

## Path Param

| Name | Type | Description | Required |
| --- | --- | --- | --- |
| articleId | Long | 공지 ID | **필수** |

> **상태를 가리지 않습니다.** 검수 대기든 임시저장이든 휴지통이든 열립니다.
> 그게 사용자 상세(`GET /articles/{id}`)와의 본질적인 차이입니다 —
> 사용자 쪽은 배포된 공지만 열리고 나머지는 404 입니다.

## Request Sample

```
GET /api/v1/admin/articles/42
```

# Response

## Response Param

| name | type | 비고 |
| --- | --- | --- |
| success | Boolean | 요청 성공 여부 |
| data | Object | 응답 데이터 |
| data.id | Long | 공지 ID |
| data.source_type | String | `SCHOOL` \| `CLUB`. **생성 후 변경 불가** |
| data.status | String | 검수 상태 (`PENDING_REVIEW`/`READY_TO_PUBLISH`/`DRAFT`/`PUBLISHED`/`TRASHED`) |
| data.title | String | 제목 |
| data.content | String | 본문 **HTML** |
| data.summary | String | AI 생성 요약. **미생성이면 필드가 빠집니다** |
| data.starts_on | String | 시작일 (yyyy-MM-dd). 없으면 필드가 빠집니다 |
| data.ends_on | String | 마감일 (yyyy-MM-dd). 없으면 필드가 빠집니다 |
| data.published_at | String | 최초 배포 시각 (ISO-8601 offset). **한 번도 배포된 적 없으면 필드가 빠집니다** |
| data.similarity_score | Number | 중복 의심 점수 **0~100** (소수 2자리). 미판정이면 필드가 빠집니다 |
| data.similar_article_id | Long | 중복 의심 상대 공지 ID. 미판정이면 필드가 빠집니다 |
| data.created_by | Long | 작성 관리자 ID. **크롤러 수집분은 필드가 빠집니다** |
| data.created_at | String | 생성 시각 (ISO-8601 offset) |
| data.updated_at | String | 내용 수정 시각 (ISO-8601 offset) |
| data.categories | Array | 분류 목록 |
| data.categories[].id | Long | 분류 ID |
| data.categories[].name | String | 분류 이름 |
| data.vendors | Array | 제공처 목록 (원본 식별자 포함) |
| data.vendors[].id | Long | **연결 행의 ID** (`article_vendors.id`). 제공처 ID 가 아닙니다 |
| data.vendors[].vendor_id | Long | 제공처 ID |
| data.vendors[].vendor_name | String | 제공처 이름 |
| data.vendors[].source_url | String | 원본 게시글 URL. 없으면 필드가 빠집니다 |
| data.vendors[].external_key | String | 원본 게시판 글 번호. **없으면 필드가 빠집니다** |
| data.attachments | Array | 첨부 목록 (`id` 오름차순) |
| data.attachments[].id | Long | 첨부 ID. 삭제에 씁니다 |
| data.attachments[].file_url | String | 파일 URL |
| data.attachments[].original_name | String | 원본 파일명 |
| data.attachments[].content_type | String | MIME 타입. 없으면 필드가 빠집니다 |
| data.attachments[].size_bytes | Long | 파일 크기(바이트). 없으면 필드가 빠집니다 |
| data.status_logs | Array | 상태 변경 이력 **최근 5건** (최신순) |
| data.status_logs[].id | Long | 이력 ID |
| data.status_logs[].from_status | String | 이전 상태. **최초 생성이면 필드가 빠집니다** |
| data.status_logs[].to_status | String | 바뀐 상태 |
| data.status_logs[].changed_by | Long | 변경한 관리자 ID. **없으면 시스템(크롤러·스케줄러)** |
| data.status_logs[].changed_by_name | String | 변경한 관리자 이름. 시스템 변경이면 필드가 빠집니다 |
| data.status_logs[].memo | String | 상태 이력 메모. 없으면 필드가 빠집니다 |
| data.status_logs[].created_at | String | 변경 시각 (ISO-8601 offset) |
| error | Object | 에러 정보 (성공 시 null) |

> **`external_key` 는 최상위가 아니라 `vendors[]` 안에 있습니다.** 수집 식별자는 게시판마다
> 다르기 때문입니다 — 같은 공지가 두 게시판에 올라오면 키도 두 개입니다.
> 그리고 **`external_key` 가 있으면 크롤러 수집분**이라, 그 제공처 연결을 지우면
> 다음 수집에서 같은 공지가 새로 만들어집니다. 화면에서 수기 추가분과 구분해 주세요.

> **`vendors[].id` 와 `vendors[].vendor_id` 를 헷갈리지 마세요.** 앞은 연결 행(`article_vendors`)의 id,
> 뒤가 제공처 자체의 id 입니다. 목록 응답의 `vendors[].id` 는 **제공처 id** 라 의미가 반대입니다.

> **`status_logs` 는 최근 5건뿐입니다.** 검수 화면은 "직전에 무슨 일이 있었나" 만 보면 되고,
> 전체 이력은 `GET /admin/articles/{articleId}/status-logs` 로 따로 봅니다.
> 정렬은 `created_at` 내림차순, 같은 시각이면 `id` 내림차순입니다 —
> 일괄 처리는 한 트랜잭션이라 여러 줄의 시각이 완전히 같아질 수 있습니다.

> **북마크·댓글·조회 수가 없습니다.** 관리자 응답에는 개인화 값(`is_bookmarked` 등)도
> 카운트도 들어 있지 않습니다. 검수는 "이 공지를 내보내도 되는가" 를 판단하는 일이고
> 반응 수치는 그 판단에 쓰이지 않습니다.

> 반대로 **첨부는 반드시 들어 있습니다.** 붙어 있는 파일을 못 보면 내보내도 되는지 판단할 수 없습니다.
> 첨부 삭제도 이 화면에서 시작합니다.

> `summary` 는 `PATCH /admin/articles/{id}` 로 직접 고칠 수 있고,
> `POST /admin/articles/{id}/summary/regenerate` 는 **지우기만** 합니다.
> 재생성 직후 이 응답에서 `summary` 필드가 사라져 있는 것이 정상이고,
> 주기 배치가 돌아야 다시 채워집니다.

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 400 | INVALID_INPUT_VALUE | articleId: 값의 형식이 올바르지 않습니다. | 경로 변수가 숫자가 아님 |
| 401 | UNAUTHORIZED | 인증이 필요합니다. | 토큰 없음·만료 |
| 403 | FORBIDDEN | 권한이 없습니다. | `ROLE_ADMIN` 이 아님 |
| 404 | ARTICLE_NOT_FOUND | 존재하지 않는 공지입니다. | 해당 ID 의 공지 없음 (영구 삭제됐거나 병합으로 흡수됨) |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 서버 측 처리 오류 |

> **휴지통에 있는 공지는 404 가 아닙니다.** 200 으로 열리고 `status` 가 `TRASHED` 입니다.
> 404 는 진짜로 행이 사라졌을 때뿐입니다 — 영구 삭제나 병합으로 흡수된 경우입니다.
