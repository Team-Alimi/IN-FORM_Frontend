# 북마크 해제

**공지를 사용자의 북마크에서 뺍니다. 저장 버튼을 끌 때, 그리고 북마크 목록에서 항목 하나를 치울 때 호출합니다. 추가와 짝을 이루는 멱등 조작이라 저장하지 않은 공지를 해제해도 성공입니다.**

- **Method / Endpoint: `DELETE /api/v1/bookmarks/articles/{articleId}`**
- **Auth Required: Required (User)**

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Authorization | Bearer {access_token} | 서비스 Access Token | **필수** |

## Path Param

| Name | Type | Description | Required |
| --- | --- | --- | --- |
| articleId | Long | 해제할 공지의 ID | **필수** |

> 요청 body 와 쿼리 파라미터는 없습니다.

### 멱등입니다

저장한 적 없는 공지를 해제해도 `200` 입니다. 지울 행이 없으면 그냥 0건이 지워질 뿐 오류가 아닙니다.

v1 의 `POST /bookmarks` 는 토글이라 **응답을 못 받고 재시도하면 상태가 원상복구**됐습니다.
네트워크가 불안정할 때 사용자가 의도하지 않은 상태가 되는 구조였습니다.
v2 는 `PUT`(켜기) / `DELETE`(끄기) 로 나눠 몇 번 호출해도 결과가 같습니다.

### 추가와 달리 공지 노출 여부를 보지 않습니다

**해제에는 가시성 검사가 없습니다.** 저장해 둔 공지가 나중에 휴지통으로 갔더라도
사용자는 자기 목록에서 치울 수 있어야 하기 때문입니다.

그래서 다음이 전부 `200` 입니다.

- 휴지통(`TRASHED`)으로 간 공지
- 한 번도 배포된 적 없는 공지
- **존재하지 않는 공지 ID**

> **이 엔드포인트는 `404 ARTICLE_NOT_FOUND` 를 내지 않습니다.** 추가와 대칭이 아닙니다.
> 오타 난 ID 를 보내도 조용히 200 이 돌아오므로, "해제 성공" 이 "그 공지가 존재한다" 를 뜻하지 않습니다.

## Request Sample

```
DELETE /api/v1/bookmarks/articles/42
Authorization: Bearer {access_token}
```

# Response

## Response Param

| name | type | 비고 |
| --- | --- | --- |
| success | Boolean | 항상 `true` |

> **`data` 키가 없습니다.** 이 API 는 본문을 돌려주지 않고(`ApiResponse<Void>`),
> `null` 필드는 응답에서 아예 빠지므로 성공 응답은 **`{"success": true}` 한 줄이 전부**입니다.
> `error` 키도 없습니다.
>
> **실제로 지워졌는지, 원래 없었는지 구분되지 않습니다.** 저장소 계층은 삭제 건수를 알고 있지만
> 응답에 담지 않습니다. 바뀐 `bookmark_count` 도 내려오지 않으므로 화면 갱신은
> 로컬 처리나 재조회로 해야 합니다.

## Response Sample

```json
{
  "success": true
}
```

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 400 | INVALID_INPUT_VALUE | articleId: 값의 형식이 올바르지 않습니다. | 경로 변수가 정수가 아닌 경우 (`/bookmarks/articles/abc`) |
| 401 | UNAUTHORIZED | 인증이 필요합니다. | 토큰 없음·만료 |
| 409 | RESOURCE_BUSY | 요청이 일시적으로 충돌했습니다. 잠시 후 다시 시도해 주세요. | 북마크 수를 갱신하는 트리거가 같은 공지 행에서 경합한 경우. **재시도하면 성공하는 실패**라 5xx 와 구분해 둡니다 |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 서버 측 처리 오류 |

> `404` 가 없는 것이 의도입니다. 위 "가시성 검사가 없습니다" 절을 참고하세요.
