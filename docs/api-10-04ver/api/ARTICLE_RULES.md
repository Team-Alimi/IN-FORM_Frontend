# 공지 상태·분류 요약

## 0. 공지 하나에 붙는 "상태" 는 두 축

| 축 | 개수 | 저장 | 누가 보나 | 정하는 것 |
|---|---:|---|---|---|
| **검수 상태** | 5 | DB 컬럼 | 관리자 | 사용자에게 **보이냐** |
| **마감 상태** | 5 | 계산 | 사용자 | 지금 **쓸모 있냐** |
| (파생 이름) | 4 | 계산 | 관리자 | 관리 화면 분류 |

## 1. 검수 상태 5개

| | 부르는 말 | 뜻 | 누구 것 | 만든 주체 | 사용자에게 | 다음 |
|---|---|---|---|---|---|---|
| `PENDING_REVIEW` | 미검수 | 아무도 안 봄 | 학교 | 크롤러 | ✗ | 발행 대기 |
| `READY_TO_PUBLISH` | 발행 대기 | 봤고 발행만 남음 | 학교 | 관리자 | ✗ | 발행됨 · 미검수 |
| `DRAFT` | 임시저장 | 쓰는 중 | 동아리 | 관리자 | ✗ | 발행됨 |
| `PUBLISHED` | 발행됨 | 나가 있음 | 둘 다 | 관리자 | **✓** | 미검수 · 발행 대기 |
| `TRASHED` | 휴지통 | 버려짐 | 둘 다 | 관리자 | ✗ | 복구만 |

휴지통은 어느 상태에서든 갈 수 있습니다.

## 2. 마감 상태 5개

| | 뜻 | 조건 |
|---|---|---|
| `ALWAYS` | 상시 | 시작·마감 둘 다 없음 |
| `UPCOMING` | 시작 전 | 오늘 < 시작일 |
| `OPEN` | 진행 중 | 그 외 |
| `CLOSING_SOON` | 마감 임박 | 마감까지 **3일 이내** |
| `CLOSED` | 마감됨 | 오늘 > 마감일 |

저장되지 않습니다. 조회할 때마다 계산합니다.

## 3. 파생 이름 4개

| 이름 | 조건 | 왜 따로 세나 |
|---|---|---|
| 신규 수집분 | 미검수 + 발행된 적 **없음** | 처음 검수할 대상 |
| 재검수 대기 | 미검수 + 발행된 적 **있음** | **지금 피드에서 사라져 있음** |
| 확인 필요 | 6조건 중 하나 (§5) | 문제 있는 것 |
| 중복 의심 | 유사도 80 이상 (휴지통 제외) | 병합 대상 |

## 4. 미검수 vs 발행 대기

| | 미검수 | 발행 대기 |
|---|---|---|
| 갈리는 지점 | `검수 완료` **안 누름** | `검수 완료` **누름** |
| 여기 온 방법 | 크롤러가 자동 | 관리자가 손으로 |
| 사람이 봤나 | ✗ | ✓ |
| 남은 일 | 읽고 판단 | 발행 클릭 |
| 사용자에게 | ✗ | ✗ |
| 크롤러가 본문 고치면 | 그대로 | **미검수로 떨어짐** |

```
크롤러 → [미검수] → 검수완료 클릭 → [발행 대기] → 발행 클릭 → [발행됨]
```

### 발행 대기는 언제 쓰나

여기 오는 방법은 **관리자가 "검수 완료" 를 누르는 것 하나**뿐입니다.
크롤러도 시간 경과도 이 상태를 만들지 못합니다.

| 상황 | 쓰나 |
|---|---|
| 여러 건 검토해두고 **모아서 발행** | ✅ 주 용도 |
| 검토하다 끊고 **나중에 이어서** (어디까지 봤는지 표시) | ✅ |
| 검토하는 사람과 발행하는 사람이 **다름** | ✅ |
| 한 건 검토하고 **바로 발행** | ❌ 거칠 필요 없음 |

핵심은 **발행 시점을 따로 고르는 것**입니다.

```
검토 = 이 내용 맞나?
발행 = 지금 내보낼까?
```

둘을 동시에 결정할 필요가 없을 때 중간에 세워 둡니다.
한 건씩 바로 내보낼 거면 안 거쳐도 됩니다 — `재검수 완료` 버튼이 실제로
검토와 발행을 한 번에 처리합니다.

### 현재 거의 안 쓰이고 있습니다 (2026-09-20)

| 전이 | 횟수 |
|---|---:|
| 미검수 → 발행됨 (중간 건너뜀) | 189 |
| 미검수 → 발행 대기 | **1** |

발행 189건은 초기 데이터를 **SQL 로 직접** 올린 것이라 검수 화면을 거치지 않았습니다.
관리자가 실제로 검수 작업을 시작하면 달라질 수 있어 **일단 유지**합니다.

한 달쯤 운영한 뒤 `article_status_logs` 로 **검수 완료 → 발행 사이 간격**을 보면
판단이 섭니다 — 몇 초면 클릭 두 번을 억지로 누른 것이고,
몇 시간이면 모아서 발행하는 패턴이 실제로 생긴 것입니다.

## 6. 누가 상태를 바꾸나

| 누가 | 언제 | 결과 |
|---|---|---|
| 크롤러 | 새 공지 수집 | → 미검수 |
| 크롤러 | 기존 공지 **내용 변경** | 어느 상태든 → **미검수** |
| 크롤러 | 기존 공지 **변경 없음** | 변화 없음 |
| 크롤러 | 휴지통 공지 수정 | **휴지통 유지** |
| 관리자 | 검수 완료 | 미검수 → 발행 대기 |
| 관리자 | 발행 | 발행 대기 → 발행됨 |
| 관리자 | 재검수 완료 | 미검수 → **발행됨** (한 번에) |
| 관리자 | 반려 | 발행 대기 → 미검수 |
| 시간 경과 | — | **변화 없음** (자동 발행 없음) |
| 조회 | — | **변화 없음** (읽어도 안 바뀜) |

## 12. 착각 vs 사실

| 착각 | 사실 |
|---|---|
| 이상한 것만 미검수로 온다 | **전부** 미검수. 이상한 건 "확인 필요" 표시 |
| 열어보면 발행 대기로 바뀐다 | 안 바뀜. **버튼**을 눌러야 함 |
| 확인 필요도 상태다 | 필터. 저장 안 됨 |
| 미검수는 다 신규다 | 발행됐다 내려온 것도 섞임 |
| 사용자는 발행된 것만 본다 | **목록만** 그럼. 북마크는 내려가도 열림 |
| 분류 0개면 오류다 | 정상. "어디에도 안 맞음" 표시 |
| 복구하면 원하는 곳으로 간다 | 버리기 **직전 상태**로만 |
| 영구삭제는 아무 때나 | **휴지통에서만** |
| 관리자 없이는 안 바뀐다 | 크롤러가 **발행본을 끌어내림** |

### 북마크가 내려가도 열리는 이유

목록은 발행됨만, **상세는 "한 번이라도 발행된 적 있으면"** 열어줍니다.
안 그러면 저장해둔 공지가 404 가 납니다. 검수 전 신규분은 해당 없습니다.
