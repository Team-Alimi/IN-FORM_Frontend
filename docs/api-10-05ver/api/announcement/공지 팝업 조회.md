# 공지 팝업 조회

**앱에 들어올 때 모달로 띄울 공지들입니다. 지금 띄워야 할 것만 내려옵니다 — 클라이언트가 조건을 따질 필요가 없습니다.**

- **Method / Endpoint: `GET /api/v1/announcements/popup`**
- **Auth Required: Not Required**

> **앱 진입 때 한 번 부르면 됩니다.** 조건 판정(상태·날짜)은 전부 서버가 끝낸 결과입니다.

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Authorization | Bearer {access_token} | 있어도 되고 없어도 됩니다. 응답은 동일합니다 | 선택 |

파라미터가 없습니다.

## Request Sample

```
GET /api/v1/announcements/popup
```

# Response

## Response Param

| name | type | 비고 |
| --- | --- | --- |
| success | Boolean | 요청 성공 여부 |
| data | Object[] | 지금 띄울 팝업. **없으면 빈 배열** |
| data[].id | Long | 공지 번호. **"다시 보지 않기" 의 키입니다** |
| data[].type | String | `MAINTENANCE` \| `UPDATE` \| `EVENT` \| `GENERAL` |
| data[].title | String | 제목 |
| data[].content | String | 본문 평문 텍스트. **상세를 한 번 더 부를 필요가 없습니다** |
| data[].published_at | String | 발행 일시 (ISO-8601 offset) |

정렬은 **최신 발행순**입니다. 앞에서부터 쌓아 올리면 됩니다.

### ★ 여러 건이 동시에 올 수 있습니다

팝업은 **여러 개를 동시에 켜 둘 수 있다**는 것이 운영 정책입니다.
서버가 건수를 자르지 않습니다 — 상한을 두면 운영자가 켠 팝업이 조용히 안 뜨게 됩니다.
(대신 관리 화면에 "지금 N건이 동시에 뜬다" 경고가 나갑니다)

### ★ "다시 보지 않기" 는 클라이언트가 처리합니다

서버는 **누가 무엇을 닫았는지 저장하지 않습니다.** 기기별 설정이라 기기마다 달라야 하고,
기억하려면 공지 하나당 사용자 수만큼 행이 쌓입니다.

`id` 를 키로 `localStorage` 에 "언제까지 숨김" 을 적어 두고 걸러 주세요.

```js
// 예: { "12": "2026-10-12", "11": "forever" }
const hidden = JSON.parse(localStorage.getItem("hiddenPopups") ?? "{}");

const toShow = popups.filter((p) => {
  const until = hidden[String(p.id)];
  if (!until) return true;
  if (until === "forever") return false;
  return new Date(until) < new Date();   // 기간이 지났으면 다시 보여 준다
});
```

- **다시 보지 않기** → `forever`
- **7일간 보지 않기** → 오늘 + 7일

> ⚠ **공지 내용이 바뀌어도 키는 그대로입니다.** 이미 닫은 사용자는 같은 번호를 숨긴 상태라
> 바뀐 내용을 못 봅니다. 운영팀에 "내용이 달라지면 새로 작성해야 한다" 고 전달돼 있습니다.

> **빈 배열은 정상입니다.** 404 가 아닙니다 — 앱 진입마다 부르는 호출이라
> 오류로 다루면 클라이언트가 매번 오류 처리를 타고 재시도하게 됩니다.

### 팝업으로 뜨는 조건

```
상태 = 발행 중
AND 팝업 지정됨
AND (노출 시작일이 없거나  시작일 <= 오늘)
AND (노출 종료일이 없거나  종료일 >= 오늘)
```

기준일은 **KST** 이고 경계 날짜는 **포함**입니다 — 시작일과 종료일이 둘 다 오늘인 공지는 오늘 뜹니다.

## Response Sample

```json
{
  "success": true,
  "data": [
    {
      "id": 12,
      "type": "MAINTENANCE",
      "title": "10월 7일 새벽 서버 점검 안내",
      "content": "10월 7일(화) 02:00 ~ 04:00 동안 서버 점검이 진행됩니다.",
      "published_at": "2026-10-05T10:00:00+09:00"
    }
  ]
}
```

띄울 것이 없을 때:

```json
{
  "success": true,
  "data": []
}
```

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 서버 측 처리 오류 |

입력값이 없고 인증도 필요 없어 **4xx 가 나지 않습니다.**
