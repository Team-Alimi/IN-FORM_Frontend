# 알림 전체 읽음 처리

**본인의 안 읽은 알림을 한 번에 모두 읽음으로 표시합니다. 알림함 상단의 "모두 읽음" 버튼이 부릅니다. 이번 호출에서 실제로 처리된 개수를 돌려주기 때문에, 클라이언트는 배지를 다시 조회하지 않고 바로 0 으로 내릴 수 있고 "3건을 읽음 처리했습니다" 같은 안내도 띄울 수 있습니다.**

- **Method / Endpoint: `PATCH /api/v1/notifications/read-all`**
- **Auth Required: Required (User)**

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Authorization | Bearer {access_token} | 서비스 Access Token | **필수** |

> 경로 변수·쿼리 파라미터·요청 body 가 모두 없습니다. 대상은 언제나 토큰의 주인 본인입니다.

## Request Sample

```
PATCH /api/v1/notifications/read-all
```

# Response

### Response Param

| name | type | 비고 |
| --- | --- | --- |
| success | Boolean | 요청 성공 여부 |
| data | Object | 응답 데이터 |
| data.read_count | Integer | **이번 호출에서** 읽음 처리된 개수 |
| error | Object | 에러 정보. **성공 응답에는 필드 자체가 없습니다** |

> **`read_count` 는 전체 알림 수가 아니라 "이번에 새로 읽음 처리된" 개수입니다.**
> `UPDATE ... WHERE user_id = ? AND read_at IS NULL` 이 갱신한 행 수라
> 이미 다 읽은 상태에서 다시 부르면 **0** 이 나옵니다. 0 은 실패가 아니라 정상 응답입니다.
> 이 값으로 "읽을 게 없었다" 와 "요청이 실패했다" 를 구분하려 하면 안 됩니다.

> `data.read_count` 는 서버가 `Map` 으로 직접 만든 키라 snake_case 변환을 거치지 않습니다.
> 안 읽은 개수 조회의 `unread_count` 와 마찬가지로 이름이 코드에 그대로 박혀 있습니다.

> **단건 읽음 처리와 달리 읽은 시각을 보존하지 않습니다.** 대상이 안 읽은 알림뿐이라 덮어쓸 값이 애초에 없습니다.

> 다른 사용자의 알림은 건드리지 않습니다. 소유자 조건이 `WHERE` 절에 들어가 있습니다.

### Response Sample

```json
{
  "success": true,
  "data": {
    "read_count": 3
  }
}
```

이미 전부 읽은 상태에서 다시 부른 경우.

```json
{
  "success": true,
  "data": {
    "read_count": 0
  }
}
```

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 401 | UNAUTHORIZED | 인증이 필요합니다. | 토큰 없음·만료 |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 서버 측 처리 오류 |

> 입력이 없고 대상이 본인으로 고정이라 이 경로에서 던지는 업무 예외는 없습니다.
