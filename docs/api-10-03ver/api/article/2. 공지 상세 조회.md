# 공지 상세 조회

**공지 한 건의 본문과 부가 정보를 전부 내려 줍니다. 목록·캘린더·북마크·알림에서 공지를 눌렀을 때 부르는 화면입니다. 본문(`content`), 원본 링크가 붙은 제공처 목록, 첨부 목록, AI 요약, 본인의 북마크 여부가 한 번에 옵니다. 조회수 집계도 이 호출이 담당합니다.**

- **Method / Endpoint: `GET /api/v1/articles/{articleId}`**
- **Auth Required: Required (User)**

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Authorization | Bearer {access_token} | 서비스 Access Token | **필수** |

## Path Param

| Name | Type | Description | Required |
| --- | --- | --- | --- |
| articleId | Long | 게시글 고유 ID | **필수** |

숫자가 아닌 값이 오면 `400 INVALID_INPUT_VALUE` 입니다.

## Request Sample

```
GET /api/v1/articles/42
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...
```

# Response

### 노출 기준 — 목록보다 넓습니다

다음 둘 중 하나면 열립니다.

- `status = PUBLISHED`
- `status = PENDING_REVIEW` **이면서** `published_at` 이 있는 경우 (= 한 번 배포된 뒤 재검수로 내려간 공지)

> **목록 기준을 그대로 쓰면 안 되는 이유.** 크롤러가 배포된 공지의 오탈자 하나만 고쳐도 재검수 대기로
> 내려갑니다. 목록 기준(`PUBLISHED` 만)을 상세에도 쓰면 **사용자가 저장해 둔 공지를 눌렀을 때 404** 가 납니다.
> `published_at IS NOT NULL` 이 "한 번 배포된 적 있음" 표식이라, 아직 한 번도 배포된 적 없는
> 신규 수집분은 자동으로 걸러집니다.

이 경로로 열린 공지는 `under_review: true` 로 내려갑니다. 프론트는 이 값으로 "검수 중" 배지를 띄웁니다.
목록 응답에서는 이 값이 항상 `false` 이므로, **`true` 를 볼 수 있는 곳은 상세와 북마크 목록뿐입니다.**

> **없는 공지와 볼 수 없는 공지를 똑같이 `404 ARTICLE_NOT_FOUND` 로 다룹니다.**
> 403 을 쓰면 "그 번호의 공지가 존재하기는 한다" 는 사실이 새어 나갑니다.
> 미배포·휴지통 공지의 존재를 확인하는 통로가 되면 안 됩니다.

### 조회수

이 호출이 조회 1건을 기록합니다.

- **같은 사용자가 30분 안에 다시 열면 세지 않습니다.** 새로고침으로 조회수를 부풀리는 걸 막습니다
- **관리자(`ROLE_ADMIN`)의 조회는 세지 않습니다.** 검수하느라 여러 번 드나드는 것이 인기도로 잡히면 안 됩니다
- 집계는 Redis 에 모았다가 주기적으로 DB 에 반영합니다. 따라서 **응답의 `view_count` 에 방금 이 호출이 반영되어 있지 않습니다.** 화면에서 즉시 +1 을 보여 주고 싶다면 클라이언트가 더해서 그려야 합니다
- Redis 가 죽어도 상세 조회는 정상 응답합니다. 조회수는 부가 정보이지 공지를 못 보여줄 이유가 아닙니다

### `summary`

AI 생성 요약입니다. **없으면 필드 자체가 응답에서 빠집니다.**

요약이 없는 상태로 이 API 를 부르면 서버가 생성을 **시작만 하고 기다리지 않습니다.**
동기로 기다리면 첫 진입이 수 초 걸리고 그 대기가 모든 사용자에게 반복됩니다.
프론트는 요약 박스를 생략하고, 사용자는 다음 진입 때 요약을 봅니다.

> **현재 빌드에는 실제 생성기가 없습니다.** 요청을 로그로만 남기는 구현체(`NoOpArticleSummaryGenerator`)가
> 붙어 있어서, 지금은 몇 번을 다시 열어도 `summary` 가 채워지지 않습니다.
> 요약 박스가 계속 안 뜨는 것은 버그가 아니라 이 상태입니다.

### `deadline_status` 분류 기준

| 값 | 조건 |
| --- | --- |
| `UPCOMING` | 오늘 < `starts_on` |
| `OPEN` | 진행 중 (`starts_on` 만 있고 `ends_on` 이 없는 경우 포함) |
| `CLOSING_SOON` | `ends_on` 까지 **3일 이내** |
| `CLOSED` | 오늘 > `ends_on` |
| `ALWAYS` | `starts_on` · `ends_on` 이 둘 다 없음 (상시) |

DB 컬럼이 아니라 조회 시각에 계산하는 파생값입니다.

### Response Param

| name | type | 비고 |
| --- | --- | --- |
| success | Boolean | 요청 성공 여부 |
| data | Object | 응답 데이터 |
| data.id | Long | 게시글 고유 ID |
| data.source_type | String | `SCHOOL` \| `CLUB` |
| data.title | String | 제목 |
| data.content | String | 본문 HTML. 항상 존재합니다 |
| data.summary | String | AI 생성 요약. **미생성이면 필드 자체가 없습니다** |
| data.published_at | String | 발행 일시 (ISO-8601 offset) |
| data.starts_on | String | 시작일 (yyyy-MM-dd). **없으면 필드 자체가 없습니다** |
| data.ends_on | String | 마감일 (yyyy-MM-dd). **없으면 필드 자체가 없습니다** |
| data.deadline_status | String | 마감 상태 (위 표) |
| data.bookmark_count | Integer | 전체 북마크 수 |
| data.comment_count | Integer | 댓글 수. 삭제된 댓글(자리만 남은 것 포함)은 세지 않습니다 |
| data.view_count | Long | 조회 수. **이번 호출은 아직 반영 전입니다** |
| data.is_bookmarked | Boolean | 호출한 사용자의 북마크 여부 |
| data.under_review | Boolean | 재검수 중 배지. `true` 면 원본이 바뀌어 검수 대기 중입니다 |
| data.categories | Array | 분류 목록. 없으면 빈 배열 |
| data.categories[].id | Long | 분류 ID |
| data.categories[].name | String | 분류 이름 |
| data.vendors | Array | 제공처 + 그 제공처의 원본 링크. 없으면 빈 배열 |
| data.vendors[].id | Long | 제공처 ID |
| data.vendors[].name | String | 제공처 이름 |
| data.vendors[].initial | String | 축약 표시 ("컴퓨터공학과" → "컴공") |
| data.vendors[].type | String | `SCHOOL` \| `CLUB` |
| data.vendors[].source_url | String | 그 게시판의 원문 링크. **없으면 필드 자체가 없습니다** |
| data.attachments | Array | 첨부 목록. 없으면 빈 배열 |
| data.attachments[].id | Long | 첨부 ID |
| data.attachments[].file_url | String | 파일 URL. 항상 존재합니다 |
| data.attachments[].original_name | String | 원본 파일명. **없으면 필드 자체가 없습니다** |
| data.attachments[].content_type | String | MIME 타입. **없으면 필드 자체가 없습니다** |
| data.attachments[].size_bytes | Long | 파일 크기(byte). **없으면 필드 자체가 없습니다** |
| error | Object | 에러 정보 (성공 시 null) |

> **`null` 인 필드는 응답에서 아예 빠집니다** (`default-property-inclusion: non_null`).
> `summary` · `starts_on` · `ends_on` · `source_url` · `original_name` · `content_type` · `size_bytes` 가
> 여기 해당합니다. 프론트는 값이 null 인지가 아니라 **키가 있는지**로 판단해야 합니다.

> **상세에는 `has_attachment` 가 없습니다.** 목록에만 있는 필드입니다.
> 상세는 `attachments` 배열을 그대로 주므로 길이로 판단하세요.

> **`vendors` 의 모양이 목록과 다릅니다.** 목록 항목에 `source_url` 이 하나 더 붙습니다.
> 이름을 `sources` 가 아니라 `vendors` 로 둔 것은 목록과 상세에서 같은 것을 같은 이름으로 부르기 위해서입니다.
>
> **같은 제공처가 두 번 이상 나올 수 있습니다.** 같은 게시판에 재게시된 원본은 각자 다른 URL 을 가지므로
> 상세에서는 중복을 그대로 남깁니다(목록 카드는 반대로 중복을 정리합니다).
> `vendor.id` 를 키로 쓰면 React 목록 렌더링에서 중복 key 경고가 납니다.

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 400 | INVALID_INPUT_VALUE | articleId: 값의 형식이 올바르지 않습니다. | 경로 변수가 숫자가 아님 (`/articles/abc`) |
| 401 | UNAUTHORIZED | 인증이 필요합니다. | 토큰 없음·만료. **상세는 비로그인으로 열리지 않습니다** |
| 404 | ARTICLE_NOT_FOUND | 존재하지 않는 공지입니다. | 없는 ID, 휴지통·미배포 공지, 한 번도 배포된 적 없는 수집분. **볼 수 없는 경우도 전부 이 코드입니다** |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 서버 측 처리 오류 |
