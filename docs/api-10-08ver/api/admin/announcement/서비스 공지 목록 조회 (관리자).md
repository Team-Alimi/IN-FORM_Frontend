# 서비스 공지 목록 조회 (관리자)

**임시저장·보관까지 전부 보이는 관리 화면용 목록입니다. 본문까지 실려 오므로 수정 화면을 목록에서 바로 열 수 있습니다.**

- **Method / Endpoint: `GET /api/v1/admin/announcements`**
- **Auth Required: Required (Admin)**

> **사용자용 목록(`GET /api/v1/announcements`)과 별개입니다.** 그쪽은 발행 중이고
> 노출 기간 안쪽인 것만, 본문 없이 내보냅니다.

> **상세 엔드포인트가 따로 없습니다.** 이 목록이 본문까지 싣고 있어서 필요하지 않습니다.

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Authorization | Bearer {access_token} | 서비스 Access Token | **필수** |

## Query Param

| Name | Type | Description | Required |
| --- | --- | --- | --- |
| status | String | `DRAFT` \| `PUBLISHED` \| `ARCHIVED`. 생략하면 전체 | 선택 |
| type | String | `MAINTENANCE` \| `UPDATE` \| `EVENT` \| `GENERAL`. 생략하면 전체 | 선택 |
| is_popup | Boolean | `true` 면 팝업 지정된 것만, `false` 면 아닌 것만. 생략하면 전체 | 선택 |
| page | Integer | 1부터. 기본값 `1` | 선택 |
| size | Integer | 기본값 `20` | 선택 |

> **`sort` 는 받지 않습니다.** 보내도 무시됩니다. 정렬은 **최근 작성순 고정**(`id DESC`)입니다 —
> 관리자는 방금 쓴 것부터 봐야 하고, 임시저장 공지에는 `published_at` 이 없어 정렬 기준이 될 수 없습니다.

### ★ `is_popup` 과 "지금 뜨는 팝업" 은 다릅니다

`is_popup=true` 는 **플래그만** 봅니다. 실제로 뜨려면 상태가 발행 중이고 노출 기간 안쪽이어야 합니다.

| 알고 싶은 것 | 부를 곳 |
|---|---|
| 팝업으로 지정해 둔 공지 전체 | `GET /api/v1/admin/announcements?is_popup=true` |
| **지금 사용자에게 실제로 뜨는 팝업** | `GET /api/v1/announcements/popup` |

## Request Sample

```
GET /api/v1/admin/announcements?page=1&size=20
```

초안만 보기:

```
GET /api/v1/admin/announcements?status=DRAFT
```

팝업으로 지정해 둔 것만 보기:

```
GET /api/v1/admin/announcements?is_popup=true
```

# Response

## Response Param

| name | type | 비고 |
| --- | --- | --- |
| success | Boolean | 요청 성공 여부 |
| data.content | Object[] | 공지 목록. 없으면 빈 배열 |
| data.content[].id | Long | 공지 번호 |
| data.content[].type | String | `MAINTENANCE` \| `UPDATE` \| `EVENT` \| `GENERAL` |
| data.content[].title | String | 제목 |
| data.content[].content | String | **본문이 실립니다** |
| data.content[].image_url | String | 대표 이미지 주소. 없으면 **필드가 빠집니다** |
| data.content[].status | String | `DRAFT` \| `PUBLISHED` \| `ARCHIVED` |
| data.content[].is_popup | Boolean | 팝업 지정 여부 |
| data.content[].published_at | String | 발행 일시. 한 번도 발행하지 않았으면 **필드가 빠집니다** |
| data.content[].starts_on | String | 노출 시작일. 없으면 **필드가 빠집니다** |
| data.content[].ends_on | String | 노출 종료일. 없으면 **필드가 빠집니다** |
| data.content[].created_by | Long | 작성한 관리자 번호. 탈퇴했으면 **필드가 빠집니다** |
| data.content[].created_at | String | 등록 일시 |
| data.content[].updated_at | String | 최종 수정 일시 |
| data.content[].warnings | String[] | **목록에서는 항상 빈 배열** (아래 설명) |
| data.page_info | Object | 페이징 정보. [00-common.md](../../00-common.md) 공통 규격 |

### `warnings` 는 목록에서 계산하지 않습니다

행마다 경고 문장을 붙이면 화면이 경고로 가득 차서, 정작 방금 한 조작의 경고가 묻힙니다.
목록에는 `status` 와 `is_popup` 이 그대로 나오므로 관리자가 표에서 직접 봅니다.

경고는 **쓰기 응답**(등록·수정·발행·보관)에만 실립니다.

### 관리 화면에서 "안 보이는 이유" 를 직접 판정하려면

```
사용자에게 보이는 공지 = status == "PUBLISHED"
                        AND (starts_on 없음 OR starts_on <= 오늘)
                        AND (ends_on   없음 OR ends_on   >= 오늘)

팝업으로 뜨는 공지      = 위 조건 AND is_popup == true
```

기준일은 **KST** 이고 경계 날짜는 **포함**입니다.

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 400 | INVALID_INPUT_VALUE | 유효하지 않은 입력 값입니다. | `status`·`type` 에 허용되지 않은 문자열, `is_popup` 에 `true`/`false` 가 아닌 값 |
| 401 | UNAUTHORIZED | 인증이 필요합니다. | 토큰 없음·만료 |
| 403 | FORBIDDEN | 권한이 없습니다. | `ROLE_ADMIN` 이 아님 |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 서버 측 처리 오류 |

> **`is_popup` 에 이상한 값을 보내면 400 입니다.** `false` 로 조용히 해석되지 않습니다.
> Spring 은 `true/on/yes/1` 과 `false/off/no/0` 만 받습니다.
