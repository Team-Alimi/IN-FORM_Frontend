# 서비스 공지 보관

**노출 중인 공지를 내립니다. 목록·상세·팝업에서 모두 빠지고 기록은 남습니다.**

- **Method / Endpoint: `POST /api/v1/admin/announcements/{announcementId}/archive`**
- **Auth Required: Required (Admin)**

> **DELETE 는 없습니다.** 공지는 "무엇을 언제 알렸는지" 의 기록이기도 해서 지우면
> 나중에 확인할 방법이 없습니다. 내리는 것은 전부 보관으로 갈음합니다.

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Authorization | Bearer {access_token} | 서비스 Access Token | **필수** |

## Path Variable

| Name | Type | Description | Required |
| --- | --- | --- | --- |
| announcementId | Long | 공지 번호 | **필수** |

본문이 없습니다.

## Request Sample

```
POST /api/v1/admin/announcements/12/archive
```

# Response

[서비스 공지 등록.md](%EC%84%9C%EB%B9%84%EC%8A%A4%20%EA%B3%B5%EC%A7%80%20%EB%93%B1%EB%A1%9D.md) 의 응답과 **같은 모양**이고, 보관 후의 전체 상태가 나갑니다.

### 상태 전이

| 현재 | 보관 가능? |
|---|---|
| `DRAFT` | ✅ (쓰다 만 것 접기) |
| `PUBLISHED` | ✅ |
| `ARCHIVED` | ❌ **400** |

### 보관이 바꾸지 않는 것

| 값 | 보관 후 |
|---|---|
| `published_at` | **그대로 남습니다** |
| `is_popup` | **그대로 남습니다** |
| `starts_on` · `ends_on` | 그대로 |

되살릴 때 원래 설정으로 돌아오는 편이 낫기 때문입니다.
그래서 **보관 응답에 "팝업인데 안 뜬다" 경고가 함께 나갈 수 있습니다** — 정상입니다.
팝업을 아예 끄려면 보관과 별개로 `is_popup: false` 로 수정하세요.

### 되살리기

[서비스 공지 발행.md](%EC%84%9C%EB%B9%84%EC%8A%A4%20%EA%B3%B5%EC%A7%80%20%EB%B0%9C%ED%96%89.md) 로 돌아갑니다.
최초 발행 시각이 유지되므로 목록 순서는 흔들리지 않습니다.

> **`DRAFT` 로는 되돌아갈 수 없습니다.** 한 번 발행한 공지를 임시저장으로 내리면
> 사용자가 이미 본 안내가 "없던 일" 이 되는데, 공지의 성격상 그건 보관이 맞습니다.

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 400 | INVALID_STATE_TRANSITION | 현재 상태(ARCHIVED)에서 ARCHIVED 로는 바꿀 수 없습니다. | 이미 보관 상태 |
| 401 | UNAUTHORIZED | 인증이 필요합니다. | 토큰 없음·만료 |
| 403 | FORBIDDEN | 권한이 없습니다. | `ROLE_ADMIN` 이 아님 |
| 404 | ANNOUNCEMENT_NOT_FOUND | 존재하지 않는 서비스 공지입니다. | 없는 번호 |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 서버 측 처리 오류 |
