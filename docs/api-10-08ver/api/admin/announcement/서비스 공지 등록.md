# 서비스 공지 등록

**운영팀이 앱 사용자에게 알리는 안내를 작성합니다. 수집 공지(`/admin/articles`)와는 다른 테이블이며 검수 단계가 없습니다.**

- **Method / Endpoint: `POST /api/v1/admin/announcements`**
- **Auth Required: Required (Admin)**

성공 시 HTTP 상태는 **201 Created** 입니다.

> **응답의 `warnings` 를 화면에 반드시 띄우세요.** 저장은 성공했지만 사용자에게는
> 아무것도 안 보이는 조합이 여럿 있습니다. 오류가 아니라서 상태 코드로는 알릴 수 없습니다.

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Authorization | Bearer {access_token} | 서비스 Access Token | **필수** |
| Content-Type | application/json | | **필수** |

## Body Param

| Name | Type | Description | Required |
| --- | --- | --- | --- |
| type | String | `MAINTENANCE`(점검) \| `UPDATE`(업데이트) \| `EVENT`(이벤트) \| `GENERAL`(일반) | **필수** |
| title | String | 제목. 최대 500자. 앞뒤 공백은 서버가 걷어냅니다 | **필수** |
| content | String | 본문 평문 텍스트. **공백만 보내면 거부됩니다** | **필수** |
| image_url | String | 대표 이미지. `POST /admin/files` 가 돌려준 `file_url`. 최대 1000자 | 선택 |
| status | String | 초기 상태. `DRAFT`(임시저장) \| `PUBLISHED`(바로 발행). 생략하면 `DRAFT` | 선택 |
| is_popup | Boolean | 앱 진입 시 팝업으로 띄울지. 생략하면 `false` | 선택 |
| starts_on | String | 노출 시작일 `yyyy-MM-dd`. 생략하면 "발행 즉시" | 선택 |
| ends_on | String | 노출 종료일 `yyyy-MM-dd`(이 날짜 포함). 생략하면 "계속" | 선택 |

> **`ARCHIVED` 로는 만들 수 없습니다** (400). 한 번도 알리지 않은 "지난 안내" 는 뜻이 없고,
> 쓰다 만 것을 접는 자리는 `DRAFT` 입니다.

> **작성자는 토큰에서 가져옵니다.** 요청 본문으로 받지 않습니다.

### 대표 이미지

**한 장만** 붙습니다. 본문 안에 삽입되지 않고 별개 필드로 나갑니다.

```
1) POST /api/v1/admin/files          이미지 올리기 → file_url 받기
2) POST /api/v1/admin/announcements  그 file_url 을 image_url 로 보내기
```

> **우리 스토리지 주소만 받습니다.** `POST /admin/files` 가 돌려준 주소가 아니면
> `400 INVALID_INPUT_VALUE` 입니다. 외부 사이트 이미지를 그대로 쓰면 두 가지가 조용히 깨집니다 —
> 그 사이트가 이미지를 내리면 팝업이 깨지고, `DELETE /admin/files` 의 삭제 보호도 적용되지 않습니다.

> **올리기만 하면 아무 데도 붙지 않습니다.** 2단계를 빠뜨리면 그 파일은 어느 공지에도
> 연결되지 않은 채 스토리지에 남습니다. `DELETE /admin/files` 로 치우세요.

### 상태와 팝업은 서로 독립입니다

| `status` | `is_popup` | 사용자에게 |
|---|---|---|
| `DRAFT` | `false` | 아무것도 안 보임 |
| `DRAFT` | `true` | **아무것도 안 보임** (발행해야 뜸) → 경고 |
| `PUBLISHED` | `false` | 목록에만 보임 |
| `PUBLISHED` | `true` | 목록 + 팝업 |

임시저장 상태에서 팝업을 미리 켜 두어도 됩니다 — **발행되는 순간부터** 뜹니다.

### 노출 기간

날짜 단위이고 **경계는 포함**입니다. 기준일은 KST 입니다.

| 보낸 값 | 뜻 |
|---|---|
| 둘 다 생략 | 발행 즉시부터 계속 |
| `starts_on` 만 | 그 날부터 계속. 미래면 **예약** |
| `ends_on` 만 | 발행 즉시부터 그 날까지 |
| `starts_on` = `ends_on` = 오늘 | **오늘 하루만** |

> **기간이 지나면 목록·상세·팝업에서 통째로 사라집니다.** 오류가 아니라 설정이라 더 찾기 어렵습니다.
> "지난 안내도 계속 읽히게" 하려면 `ends_on` 을 비워 두세요.

> `starts_on` > `ends_on` 이면 400 입니다.

## Request Sample

쓰고 바로 올리면서 팝업까지 켜는, 가장 흔한 경우입니다.

```json
POST /api/v1/admin/announcements
{
  "type": "MAINTENANCE",
  "title": "10월 7일 새벽 서버 점검 안내",
  "content": "10월 7일(화) 02:00 ~ 04:00 동안 서버 점검이 진행됩니다.\n점검 중에는 로그인과 공지 조회가 일시적으로 중단됩니다.",
  "image_url": "https://<bucket>.s3.<region>.amazonaws.com/2026/10/08/maintenance.png",
  "status": "PUBLISHED",
  "is_popup": true,
  "starts_on": "2026-10-05",
  "ends_on": "2026-10-07"
}
```

초안만 저장:

```json
POST /api/v1/admin/announcements
{
  "type": "EVENT",
  "title": "가을 이벤트 (작성 중)",
  "content": "내용 확정 전"
}
```

# Response

## Response Param

| name | type | 비고 |
| --- | --- | --- |
| success | Boolean | 요청 성공 여부 |
| data.id | Long | 새로 발급된 공지 번호 |
| data.type | String | `MAINTENANCE` \| `UPDATE` \| `EVENT` \| `GENERAL` |
| data.title | String | 정규화(앞뒤 공백 제거)된 제목 |
| data.content | String | 본문 |
| data.image_url | String | 대표 이미지 주소. 안 보냈으면 **필드 자체가 빠집니다** |
| data.status | String | `DRAFT` \| `PUBLISHED` \| `ARCHIVED` |
| data.is_popup | Boolean | 팝업 지정 여부 |
| data.published_at | String | 발행 일시. `DRAFT` 면 **필드 자체가 빠집니다** |
| data.starts_on | String | 노출 시작일. 없으면 **필드가 빠집니다** |
| data.ends_on | String | 노출 종료일. 없으면 **필드가 빠집니다** |
| data.created_by | Long | 작성한 관리자 번호 |
| data.created_at | String | 등록 일시 (ISO-8601 offset) |
| data.updated_at | String | 최종 수정 일시 |
| data.warnings | String[] | 주의 사항. 없으면 **빈 배열** |

### ★ `warnings` — 저장은 됐지만 안 보이는 경우들

| 상황 | 경고 |
|---|---|
| 팝업인데 `DRAFT`·`ARCHIVED` | `"팝업으로 지정했지만 상태가 DRAFT 라 뜨지 않습니다. 발행해야 보입니다."` |
| 발행했는데 종료일이 지남 | `"노출 종료일(2026-09-30)이 지났습니다. 발행 상태지만 목록·팝업에 나오지 않습니다 — …"` |
| 발행했는데 시작일이 미래 | `"노출 시작일이 2026-10-12 입니다. 그때까지는 보이지 않습니다(예약)."` |
| 동시에 뜨는 팝업이 2건 이상 | `"지금 동시에 뜨는 팝업이 3건입니다. 사용자는 앱을 열 때 3개를 연달아 닫아야 합니다."` |

**여러 개가 동시에 담깁니다.** 하나만 돌려주면 나머지가 조용히 사라지기 때문에 배열입니다.
전부 띄워 주세요. 정상적인 공지에는 빈 배열이 나갑니다.

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 400 | INVALID_INPUT_VALUE | type: 공지 유형을 선택해 주세요. | `type` 누락 |
| 400 | INVALID_INPUT_VALUE | title: 제목을 입력해 주세요. | `title` 이 비었거나 공백뿐 |
| 400 | INVALID_INPUT_VALUE | content: 내용을 입력해 주세요. | `content` 가 비었거나 공백뿐 |
| 400 | INVALID_INPUT_VALUE | title: 제목은 500자를 넘을 수 없습니다. | 길이 초과 |
| 400 | INVALID_INPUT_VALUE | 보관 상태로는 작성할 수 없습니다. 임시저장(DRAFT) 또는 발행(PUBLISHED)만 됩니다. | `status=ARCHIVED` |
| 400 | INVALID_INPUT_VALUE | 노출 시작일은 종료일보다 늦을 수 없습니다. | `starts_on` > `ends_on` |
| 400 | INVALID_INPUT_VALUE | 우리 스토리지에 올린 이미지만 쓸 수 있습니다. POST /admin/files 로 먼저 올리고 그 file_url 을 보내세요. | `image_url` 이 우리 스토리지 주소가 아님 |
| 400 | INVALID_INPUT_VALUE | imageUrl: 이미지 주소가 너무 깁니다. | 1000자 초과 |
| 400 | MALFORMED_REQUEST | 요청 본문을 해석할 수 없습니다. | JSON 파싱 실패, `type`·`status` 에 허용되지 않은 문자열, 날짜 형식 오류 |
| 401 | UNAUTHORIZED | 인증이 필요합니다. | 토큰 없음·만료 |
| 403 | FORBIDDEN | 권한이 없습니다. | 로그인은 했으나 `ROLE_ADMIN` 이 아님 |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 서버 측 처리 오류 |

> Bean Validation 이 걸러낸 오류의 `message` 는 `"{자바 필드명}: {제약 메시지}"` 형태입니다 —
> `is_popup` 이 아니라 `isPopup`. 자세한 내용은 [00-common.md](../../00-common.md) 를 보세요.
