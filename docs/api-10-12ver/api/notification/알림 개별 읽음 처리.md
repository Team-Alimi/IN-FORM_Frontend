# 알림 개별 읽음 처리

**알림 한 건을 읽음으로 표시합니다. 알림함에서 항목을 탭했을 때 부릅니다. 멱등이라 같은 알림을 여러 번 눌러도 계속 성공하고, 최초로 읽은 시각은 덮어쓰지 않습니다.**

- **Method / Endpoint: `PATCH /api/v1/notifications/{notificationId}/read`**
- **Auth Required: Required (User)**

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Authorization | Bearer {access_token} | 서비스 Access Token | **필수** |

## Path Param

| Name | Type | Description | Required |
| --- | --- | --- | --- |
| notificationId | Long | 읽음 처리할 알림 ID. 알림 목록의 `data.content[].id` | **필수** |

> 요청 body 는 없습니다. `Content-Type` 도 필요 없습니다.

## Request Sample

```
PATCH /api/v1/notifications/91/read
```

# Response

### Response Param

| name | type | 비고 |
| --- | --- | --- |
| success | Boolean | 요청 성공 여부 |
| data | Object | **항상 없습니다** — 아래 설명 참고 |
| error | Object | 에러 정보. **성공 응답에는 필드 자체가 없습니다** |

> **성공 응답 본문은 `{"success": true}` 한 줄입니다.**
> 서버가 `data` 에 `null` 을 담아 내보내지만 전역 설정이 `default-property-inclusion: non_null` 이라
> `data` 와 `error` 가 **둘 다 응답에서 사라집니다.**
> 프론트가 `response.data` 를 꺼내 쓰려 하면 `undefined` 입니다. 파싱 로직이 `data` 존재를 전제로
> 짜여 있으면 여기서 깨집니다. 성공 판단은 `success` 또는 HTTP 200 으로 하세요.

> **읽음 개수를 알고 싶다면 이 API 로는 알 수 없습니다.** 배지를 갱신하려면 안 읽은 개수 조회를 다시 부르거나
> 클라이언트가 로컬 상태에서 1 을 빼야 합니다. (전체 읽음 처리만 처리 개수를 돌려줍니다.)

> **멱등입니다.** 이미 읽은 알림을 다시 호출해도 200 이고, `read_at` 은 `COALESCE` 로 보존되어
> **최초로 읽은 시각이 유지**됩니다. 조건에 `read_at IS NULL` 을 넣었다면 재호출이 0행이 되어
> "내 알림이 아님" 과 구분할 수 없었기 때문에 이렇게 되어 있습니다.

### Response Sample

```json
{
  "success": true
}
```

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 400 | INVALID_INPUT_VALUE | notificationId: 값의 형식이 올바르지 않습니다. | 경로 변수가 숫자가 아닐 때 |
| 401 | UNAUTHORIZED | 인증이 필요합니다. | 토큰 없음·만료 |
| 404 | NOTIFICATION_NOT_FOUND | 존재하지 않는 알림입니다. | 없는 ID **또는 남의 알림** |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 서버 측 처리 오류 |

> **남의 알림을 지정하면 403 이 아니라 404 입니다.** 403 을 쓰면 "그 번호의 알림이 존재한다" 가
> 응답으로 새어 나갑니다. 알림은 목록에 공개되는 자원이 아니라 감출 이유가 있어서, 없는 것과
> 남의 것을 같은 응답으로 묶었습니다. 소유자 확인은 `UPDATE ... WHERE id = ? AND user_id = ?`
> 한 문장 안에 들어 있어 갱신된 행이 0이면 이 오류가 나갑니다.
