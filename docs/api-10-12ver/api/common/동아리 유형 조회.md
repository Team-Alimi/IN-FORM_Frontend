# 동아리 유형 조회

**동아리 추천 분류(학술/IT·체육/스포츠·음악/공연 등) 중 활성 상태인 것만 노출 순서대로 내려줍니다. 온보딩의 관심 동아리 선택 화면이 이 목록으로 그려집니다. 비로그인 상태에서도 호출할 수 있어 앱 진입 직후 토큰 없이 바로 부를 수 있습니다.**

- **Method / Endpoint: `GET /api/v1/club-types`**
- **Auth Required: Not Required**

> **하드코딩하지 마세요.** 사용자가 고른 값은 `PUT /api/v1/users/me/interests/club-types` 로
> **id** 를 보내 저장합니다. 화면에서 만든 임의의 값은 DB 의 `club_type_id` 와 맞지 않아
> 저장 시점에 실패합니다.

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Authorization | Bearer {access_token} | 서비스 Access Token | 선택 |

> **토큰을 보내도 응답은 달라지지 않습니다.** 로그인 여부와 무관하게 같은 목록이 나갑니다.
> 사용자가 이미 고른 유형은 이 응답에 표시되지 않으므로, 선택 상태를 그리려면
> `GET /api/v1/users/me/interests/club-types` 를 따로 불러 id 로 대조해야 합니다.
> 카테고리와 정확히 같은 구조입니다.

## Query Param

**없습니다.** 컨트롤러가 파라미터를 하나도 선언하지 않습니다.

| Name | Type | Description | Required | Default |
| --- | --- | --- | --- | --- |
| - | - | 받는 파라미터 없음 | - | - |

## Request Sample

```
GET /api/v1/club-types
```

# Response

### 정렬 기준

`sort_order` 오름차순, 같으면 `name`, 그다음 `id` 순입니다.
**프론트가 다시 정렬하지 말고 받은 순서를 그대로 그리는 것이 맞습니다.**

### 페이징이 없습니다

**`data` 는 배열 그 자체입니다.** `data.content` · `data.page_info` 가 없습니다.

### Response Param

| name | type | 비고 |
| --- | --- | --- |
| success | Boolean | 요청 성공 여부 |
| data | Array | 동아리 유형 목록. **`content`·`page_info` 로 감싸지 않은 평평한 배열** |
| data[].id | Long | 고유 ID. 관심 동아리 유형 저장에 쓰는 유일한 식별자 |
| data[].name | String | 표시 이름 (최대 100자) |
| data[].sort_order | Integer | 노출 순서. 작을수록 앞. **항상 존재** (null 아님) |
| error | Object | 에러 정보 (성공 시 null) |

> **`code` 는 내려가지 않습니다.** 카테고리와 같은 이유입니다 — 내보내면 프론트가
> `"SPORTS"` 같은 문자열에 로직을 걸기 시작하고, 그러면 표시명조차 못 바꾸게 됩니다.
> **표시는 `name`, 식별은 `id`** 입니다.

> **`is_active` 도 없습니다.** 이 목록에는 활성만 담기므로 항상 `true` 입니다.

> **비활성 유형은 나오지 않습니다.** 신규 선택하면 DB 트리거가 IN008 로 거부하기 때문에,
> 여기서 걸러 내지 않으면 고를 수 있는 것처럼 보여 주고 저장에서 400 을 주게 됩니다.

> **`id` 순서가 뒤죽박죽인 것이 정상입니다.** 시드된 순서와 화면 표시 순서가 다르기 때문입니다.
> `id` 로 정렬하면 화면이 틀어집니다. 받은 순서를 그대로 쓰세요.

> 목록을 바꾸려면 마이그레이션이 필요합니다. 관리자 화면으로 추가·수정하는 기능이 없습니다
> (`club_types` 테이블 주석: "항목은 seed 데이터로 관리").

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 서버 측 처리 오류 |

> **정상 경로에서 4xx 가 없습니다.** 받는 파라미터가 없어 바인딩이 실패할 여지가 없고,
> 조회만 하므로 서비스에서 던지는 예외도 없습니다.
> 활성 유형이 하나도 없으면 오류가 아니라 `"data": []` 입니다.

> **401·403 은 나오지 않습니다.** `SecurityConfig` 가 `GET /api/v1/club-types` 를 `permitAll` 로 열어 두었습니다.
