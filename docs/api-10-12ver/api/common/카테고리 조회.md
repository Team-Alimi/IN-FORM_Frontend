# 카테고리 조회

**공지 분류(장학·학사·취업 등) 중 활성 상태인 것을 관리자가 지정한 노출 순서대로 내려줍니다. 온보딩의 관심분야 선택 화면, 공지 목록의 분류 필터 칩이 이 목록으로 그려집니다. 비로그인 상태에서도 호출할 수 있어 앱 진입 직후 토큰 없이 바로 부를 수 있습니다.**

> **두 화면이 필요한 목록이 다릅니다.** 온보딩은 사용자가 <b>고를 수 있는</b> 분류만,
> 목록 필터는 <b>기타까지</b> 필요합니다 — 기타로 분류된 공지가 실제로 있고 사용자가 그걸 골라 볼 수 있어야 하기 때문입니다.
> `include_unselectable` 로 가릅니다.

- **Method / Endpoint: `GET /api/v1/categories`**
- **Auth Required: Not Required**

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Authorization | Bearer {access_token} | 서비스 Access Token | 선택 |

> **토큰을 보내도 응답은 달라지지 않습니다.** 로그인 여부와 무관하게 같은 목록이 나갑니다.
> 사용자가 이미 고른 관심분야는 이 응답에 표시되지 않으므로, 선택 상태를 그리려면
> `GET /api/v1/users/me/interests/categories` 를 따로 불러 id 로 대조해야 합니다.
>
> **만료·위조된 토큰을 붙여도 401 이 아닙니다.** 인증 필터는 해석에 실패한 토큰을 조용히 버리고
> 요청을 통과시킵니다(`JwtAuthenticationFilter`). 프론트는 이 호출의 401 을 재로그인 신호로 쓰면 안 됩니다.

## Query Param

| Name | Type | Description | Required | Default |
| --- | --- | --- | --- | --- |
| include_unselectable | Boolean | `true` 면 **고를 수 없는 분류(기타)까지** 포함 | 선택 | `false` |

> **기본값이 온보딩용입니다.** 빠뜨리면 "덜 보이는" 쪽으로 기웁니다 —
> 반대로 기본을 `true` 로 두면 온보딩에서 기타가 보이고, 사용자가 고르면 저장에서 400 이 납니다.
> 실수했을 때 안전한 쪽을 기본으로 둔 것입니다.

> `page`·`size`·`sort` 는 받지 않습니다(붙여 보내도 무시됩니다). 분류는 십여 건 규모라
> 나눠 줄 이유가 없고, `sort` 를 열어 두면 검증되지 않은 문자열이 ORDER BY 뒤에 그대로 붙어
> `?sort=foo` 하나로 500 이 납니다.

## Request Sample

```
GET /api/v1/categories                              ← 온보딩 (11개)
GET /api/v1/categories?include_unselectable=true    ← 목록 필터 (12개, 기타 포함)
```

# Response

### 정렬 기준

`sort_order` 오름차순입니다. 같은 값이면 `name`, 그다음 `id` 순입니다.

`sort_order` 는 관리자가 화면 배치를 직접 정하려고 두는 값이라, **프론트가 다시 정렬하지 말고
받은 순서를 그대로 그리는 것이 맞습니다.**

> `sort_order` 가 같은 분류끼리의 이름 순서는 DB 정렬(`en_US.utf8`)을 그대로 따릅니다.
> 한글 정렬 규칙이 없어 눈에 보이는 가나다순과 다를 수 있습니다.
> 제공처 목록이 애플리케이션에서 한국어 정렬을 다시 하는 것과 다른 점입니다.
> 실무상으로는 `sort_order` 를 서로 다르게 부여해 회피합니다.

### 페이징이 없습니다

**`data` 는 배열 그 자체입니다.** 다른 목록 API 와 달리 `data.content` · `data.page_info` 가 없습니다.

### Response Param

| name | type | 비고 |
| --- | --- | --- |
| success | Boolean | 요청 성공 여부 |
| data | Array | 분류 목록. **`content`·`page_info` 로 감싸지 않은 평평한 배열** |
| data[].id | Long | 분류 고유 ID. 필터·관심분야 저장에 쓰는 유일한 식별자 |
| data[].name | String | 분류 이름 (최대 100자) |
| data[].sort_order | Integer | 노출 순서. 작을수록 앞. **항상 존재** (null 아님) |
| error | Object | 에러 정보 (성공 시 null) |

> **`code` 는 내려가지 않습니다.** 크롤러의 AI 분류 결과가 이 문자열로 들어오는 계약 키라
> 화면이 쓸 이유가 없고, 내보내면 프론트가 `"SCHOLARSHIP"` 같은 값에 로직을 걸기 시작합니다.
> **표시는 `name`, 식별은 `id`** 입니다. 관심분야 저장·필터 요청에도 `id` 를 보냅니다.

> **`is_active` 도 없습니다.** 이 목록에는 활성만 담기므로 항상 `true` 입니다.

> **"활성" 과 "고를 수 있음" 은 다릅니다.**
>
> | | 뜻 | 예 | 기본 응답 | `include_unselectable=true` |
> |---|---|---|---|---|
> | 비활성 | 분류로도 안 쓰고 선택도 안 됨 | `모집·선발`, `국제·교환` | ✗ | **✗** |
> | 선택불가 | **공지 분류에는 쓰지만** 관심분야로 고를 수는 없음 | **`기타`** | ✗ | **✓** |
> | 정상 | 둘 다 됨 | 나머지 11개 | ✓ | ✓ |
>
> **비활성은 어느 쪽으로도 안 나옵니다.** 파라미터가 여는 것은 `기타` 뿐입니다.
>
> **온보딩에서는 기본값을 쓰세요.** 고를 수 없는 분류를 신규 선택하면 DB 트리거가
> `INACTIVE_CATEGORY` 로 거부합니다 — 화면에만 띄우면 고를 수 있어 보이는데 저장에서 400 입니다.

> **기본 응답은 11개입니다.** 온보딩 관심분야 화면이 이 목록 그대로입니다.
> `include_unselectable=true` 면 맨 끝에 `기타` 가 붙어 12개가 됩니다.
>
> ```json
> { "id": 8, "name": "기타", "sort_order": 999 }
> ```
>
> `sort_order` 가 999 라 **항상 마지막**입니다. 필터 칩에서도 끝에 놓으면 자연스럽습니다.

> **`id` 는 순서와 무관합니다.** 위 샘플에서도 첫 항목이 `id: 2` 입니다.
> 시드 순서와 표시 순서가 다르기 때문이고, 환경마다 값이 다를 수 있습니다.
> **정렬은 서버가 이미 했으니 받은 순서를 그대로 그리세요.**

> `sort_order` 값이 빈틈없이 이어진다는 보장은 없습니다. 중간 삽입 여지를 두려고
> 10 단위로 띄워 두었고, 관리자가 더 바꿀 수도 있습니다.
> 배열 인덱스 대신 받은 순서만 신뢰하세요.

> **기본 응답에 없는 분류가 공지에는 붙어 있을 수 있습니다.**
>
> - **비활성** — `모집·선발`, `국제·교환`. 접었지만 삭제하지 않아서 이미 붙은 공지는 그대로 표시됩니다.
>   `include_unselectable=true` 로도 나오지 않습니다.
> - **`기타`** — 크롤러가 "어느 분류에도 안 맞음" 을 표시하는 값이라 신규 공지에도 계속 붙습니다.
>   `include_unselectable=true` 로 받을 수 있습니다.
>
> 어느 쪽이든 **두 목록을 id 로 조인해 이름을 찾지 마세요.**
> 공지의 분류 이름은 공지 응답 안에 이미 들어 있습니다.

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 400 | INVALID_INPUT_VALUE | include_unselectable: 값의 형식이 올바르지 않습니다. | Boolean 으로 해석할 수 없는 값 |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 서버 측 처리 오류 |

> **`include_unselectable` 에 아무 문자열이나 넣으면 400 입니다.**
> Spring 이 받는 값은 `true` `on` `yes` `1` / `false` `off` `no` `0` 뿐이고,
> 그 밖의 값은 변환 단계에서 거부됩니다. `false` 로 떨어지지 않습니다.
>
> 파라미터를 **아예 안 보내는 것**은 정상이며 기본값 `false` 가 적용됩니다.

> **그 밖에는 4xx 가 없습니다.** 조회만 하므로 서비스에서 던지는 `BusinessException` 이 없습니다.
> 활성 분류가 하나도 없으면 오류가 아니라 `"data": []` 입니다 — 프론트는 빈 배열을 정상으로 다뤄야 합니다.

> **401·403 은 나오지 않습니다.** `SecurityConfig` 가 `GET /api/v1/categories` 를 `permitAll` 로 열어 두었고,
> `PublicEndpointsTest` 가 이 동작을 고정하고 있습니다. 이 경로에서 401 을 받았다면 서버 설정 사고입니다.
