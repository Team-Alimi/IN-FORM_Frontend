# 관리자 댓글 일괄 삭제

**목록에서 고른 댓글들을 한 번에 지웁니다. 부적절한 댓글을 DB 를 직접 열지 않고 관리자 화면에서 처리하기 위한 API 입니다. 부분 성공을 허용하며, 처리하지 못한 건은 사유와 함께 돌려줍니다.**

- **Method / Endpoint: `POST /api/v1/admin/comments/bulk/delete`**
- **Auth Required: Required (Admin)**

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Authorization | Bearer {access_token} | 서비스 Access Token (ROLE_ADMIN) | **필수** |
| Content-Type | application/json | | **필수** |

## Body Param

| Name | Type | Description | Required |
| --- | --- | --- | --- |
| ids | Array&lt;Long&gt; | 삭제할 댓글 ID. **비어 있으면 400**, **최대 200건**, 원소에 null 이 섞이면 400 | **필수** |

> 키가 `comment_ids` 가 아니라 **`ids`** 입니다. 벌크 작업 공통 규약을 따릅니다 —
> 경로(`/admin/comments/bulk/delete`)가 이미 무엇의 id 인지 말해 줍니다.

> **상한 200건은 잠금 때문입니다.** 삭제 판정은 댓글마다 행을 잠그고 시작하는데,
> 한 요청이 수천 건을 붙들면 그동안 그 공지의 댓글 작성이 전부 대기합니다.

## Request Sample

```json
POST /api/v1/admin/comments/bulk/delete
{
  "ids": [981, 977, 812]
}
```

# Response

### 삭제 규칙 — 행째 지웁니다

사용자 삭제(`DELETE /comments/{id}`)와 **완전히 같습니다.** 작성자 확인만 건너뜁니다.

**되살릴 수 없습니다.** 공지 상태 변경과 달리 댓글에는 감사 테이블이 없고,
지워진 행은 복구 경로가 없습니다. 남는 기록은 애플리케이션 로그뿐입니다.

> 예전에는 답글이 달린 댓글의 자리를 남겼지만(soft delete), 답글 기능이 없어지면서
> 자리를 남길 이유도 사라졌습니다 — 아래에 매달린 것이 없으므로 지워도 남의 글이 함께 사라지지 않습니다.
## Response Param

| name | type | 비고 |
| --- | --- | --- |
| success | Boolean | 요청 성공 여부 |
| data | Object | 응답 데이터 |
| data.succeeded | Array&lt;Long&gt; | 삭제에 성공한 댓글 ID |
| data.failed | Array | 처리하지 못한 건 |
| data.failed[].id | Long | 실패한 댓글 ID |
| data.failed[].code | String | 실패 사유 코드 (공통 Error 표와 같은 체계) |
| data.failed[].message | String | 사람이 읽을 사유 |
| error | Object | 에러 정보. 성공 시 null — `non_null` 설정이라 **성공 응답에는 이 키가 아예 없습니다** |

> **`failed` 가 비어 있지 않아도 HTTP 는 200 입니다.** 부분 성공이 정상 경로이기 때문입니다 —
> 프론트는 상태 코드가 아니라 `failed` 배열을 보고 판단해야 합니다.
>
> 요청한 id 는 **전부** `succeeded` 나 `failed` 중 한쪽에 나타납니다. 목록을 띄워 둔 사이에
> 글쓴이가 먼저 지운 댓글도 조용히 빠지지 않고 `failed` 에 담깁니다 — 30건을 골랐는데 28건만
> 처리된 것을 모르는 상황을 만들지 않기 위해서입니다.
>
> **중복 id 는 한 번으로 합쳐집니다.** 같은 id 를 두 번 보내도 `succeeded` 에 한 번만 나오고,
> 두 번째가 "이미 처리됨" 실패로 보이지 않습니다.

> **개별 실패 사유는 현재 `COMMENT_NOT_FOUND` 한 가지뿐입니다.** 이미 지워졌거나 존재하지 않는
> id 가 여기 해당합니다. 그 외의 실패는 요청 전체가 에러로 돌아갑니다(아래 Error 표).

## Response Sample

```json
{
  "success": true,
  "data": {
    "succeeded": [981, 977],
    "failed": [
      {
        "id": 812,
        "code": "COMMENT_NOT_FOUND",
        "message": "이미 삭제된 댓글입니다."
      }
    ]
  },
  "error": null
}
```

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 400 | INVALID_INPUT_VALUE | ids: 삭제할 댓글을 선택해 주세요. | `ids` 가 없거나 빈 배열 |
| 400 | INVALID_INPUT_VALUE | ids: 한 번에 200건까지 처리할 수 있습니다. | `ids` 가 200건 초과 |
| 400 | INVALID_INPUT_VALUE | ids[0]: 댓글 번호가 비어 있습니다. | 배열 원소에 null 이 섞임 |
| 400 | MALFORMED_REQUEST | 요청 본문을 해석할 수 없습니다. | body 가 JSON 이 아니거나 `ids` 타입이 맞지 않음 |
| 401 | UNAUTHORIZED | 인증이 필요합니다. | 토큰 없음·만료 |
| 403 | FORBIDDEN | 권한이 없습니다. | 로그인은 했으나 ROLE_ADMIN 이 아님 |
| 409 | RESOURCE_BUSY | 요청이 일시적으로 충돌했습니다. 잠시 후 다시 시도해 주세요. | DB 교착·직렬화 실패(SQLSTATE `40P01`·`40001`). 잠금 순서를 고정해 막고 있지만 남는 경우가 있습니다. **재시도하면 성공할 수 있는 실패**입니다 |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 서버 측 처리 오류 |

> 검증 실패 메시지는 `{필드명}: {메시지}` 형태이고, 필드명은 **JSON 키가 아니라 자바 필드명**입니다
> (예: `fileUrls[0]`). `ids` 는 두 이름이 같아 차이가 드러나지 않습니다.

> **409 가 나면 요청 전체가 롤백됩니다.** 이 벌크는 공지 벌크와 달리 건별로 트랜잭션을 나누지 않고
> **한 트랜잭션에서 처리**합니다. 부분 성공(`failed`)은 "이미 지워진 댓글" 을 건너뛰는 경우에만
> 발생하고, DB 수준의 실패는 `succeeded` 에 담겼던 건까지 함께 되돌아갑니다.
