# 서비스 공지 수정

**부분 수정입니다. 보낸 필드만 반영하고 생략한 필드는 그대로 둡니다. 어느 상태에서나 수정할 수 있습니다 — 발행된 공지의 오타도 고쳐야 하기 때문입니다.**

- **Method / Endpoint: `PATCH /api/v1/admin/announcements/{announcementId}`**
- **Auth Required: Required (Admin)**

> **상태는 여기서 바뀌지 않습니다.** 발행·보관은 전이 규칙을 타야 해서 전용 경로로만 갑니다

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Authorization | Bearer {access_token} | 서비스 Access Token | **필수** |
| Content-Type | application/json | | **필수** |

## Path Variable

| Name | Type | Description | Required |
| --- | --- | --- | --- |
| announcementId | Long | 공지 번호 | **필수** |

## Body Param

전부 선택입니다. **`null` 이거나 생략하면 "그대로 두기" 입니다.**

| Name | Type | Description |
| --- | --- | --- |
| type | String | `MAINTENANCE` \| `UPDATE` \| `EVENT` \| `GENERAL` |
| title | String | 제목. 최대 500자. 빈 문자열·공백뿐이면 400 |
| content | String | 본문. 빈 문자열·공백뿐이면 400 |
| image_url | String | 대표 이미지 **교체**. `POST /admin/files` 가 돌려준 `file_url` |
| clear_image | Boolean | 대표 이미지 **제거** |
| is_popup | Boolean | 팝업 켜고 끄기. **끄려면 `false` 를 명시해야 합니다** |
| starts_on | String | 노출 시작일 `yyyy-MM-dd` |
| ends_on | String | 노출 종료일 `yyyy-MM-dd` |
| clear_period | Boolean | **기존 기간을 먼저 지웁니다** (아래 설명) |

### ★ 기간을 비우는 방법 — `clear_period`

`null` 이 "그대로 두기" 라서 날짜만으로는 **"비워 달라" 를 표현할 수 없습니다.**
목록 필드는 빈 배열로 구분되지만 날짜에는 그런 값이 없습니다.

`clear_period: true` 는 **기존 기간을 먼저 지우고**, 같은 요청의 `starts_on`·`ends_on` 을 그 위에 적용합니다.

| 보낸 것 | 결과 |
|---|---|
| `clear_period: true` 만 | 기간 제한 없음 (둘 다 비움) |
| `clear_period: true`, `starts_on: A` | A 부터 계속 |
| `clear_period: true`, `ends_on: B` | 즉시부터 B 까지 |
| `ends_on: B` 만 | **시작일 유지**, 종료일만 B |
| `starts_on: A` 만 | **종료일 유지**, 시작일만 A |
| 아무것도 안 보냄 | 기간 그대로 |

> **이게 없으면 되살릴 방법이 없습니다.** 종료일을 잘못 넣은 공지는 목록·상세·팝업에서
> 통째로 사라지는데, 사라진 이유가 오류가 아니라 설정이라 더 찾기 어렵습니다.

### ★ 이미지 교체와 제거

기간과 같은 문제입니다 — `null` 이 "그대로 두기" 라서 `image_url` 만으로는 "지워 달라" 를
표현할 수 없습니다. 그래서 `clear_image` 를 둡니다.

| 보낸 것 | 결과 |
|---|---|
| 아무것도 안 보냄 | 이미지 그대로 |
| `image_url: "...새 주소"` | **교체** |
| `clear_image: true` | **제거** |
| 둘 다 보냄 | **400** — 뜻이 모순입니다 |

> **기간의 `clear_period` 와 규칙이 다릅니다.** 기간은 값이 둘(시작·종료)이라
> "먼저 지우고 보낸 값을 덮어쓰기" 가 쓸모가 있지만, 이미지는 값이 하나뿐이라
> 그 해석이 곧 "그냥 교체" 와 같아집니다. 같은 뜻을 두 가지로 쓸 수 있게 두지 않았습니다.

> **교체해도 옛 파일은 스토리지에 남습니다.** 서버가 지우지 않습니다 —
> 같은 이미지를 다른 공지가 쓰고 있을 수 있고, S3 삭제는 되돌릴 수 없습니다.
> 치우려면 `DELETE /api/v1/admin/files` 를 따로 부르세요. 공지 첨부와 같은 규칙입니다.

> **우리 스토리지 주소만 받습니다.** 외부 주소는 `400` 입니다 (등록과 같습니다).

### 팝업은 `false` 를 보내야 꺼집니다

`is_popup` 을 생략하면 지금 값이 유지됩니다. 끄려면 명시적으로 `false` 를 보내세요.

## Request Sample

제목 오타만 고치기 — 나머지는 전부 그대로입니다.

```json
PATCH /api/v1/admin/announcements/12
{
  "title": "10월 7일(화) 새벽 서버 점검 안내"
}
```

점검이 미뤄져서 종료일만 늘리기:

```json
PATCH /api/v1/admin/announcements/12
{
  "ends_on": "2026-10-14"
}
```

종료일을 잘못 넣어 사라진 공지를 되살리기:

```json
PATCH /api/v1/admin/announcements/12
{
  "clear_period": true
}
```

이미지 교체:

```json
PATCH /api/v1/admin/announcements/12
{
  "image_url": "https://<bucket>.s3.<region>.amazonaws.com/2026/10/08/maintenance.png"
}
```

이미지 제거:

```json
PATCH /api/v1/admin/announcements/12
{
  "clear_image": true
}
```

팝업 끄기:

```json
PATCH /api/v1/admin/announcements/12
{
  "is_popup": false
}
```

# Response

[서비스 공지 등록.md](%EC%84%9C%EB%B9%84%EC%8A%A4%20%EA%B3%B5%EC%A7%80%20%EB%93%B1%EB%A1%9D.md) 의 응답과 **같은 모양**이고, 수정 후의 전체 상태가 나갑니다.

| name | type | 비고 |
| --- | --- | --- |
| data.id ~ data.updated_at | | 등록 응답과 동일 (`image_url` 포함) |
| data.updated_at | String | **갱신된 값입니다.** 화면의 "마지막 수정" 에 그대로 쓰면 됩니다 |
| data.warnings | String[] | 수정 **후** 상태를 기준으로 다시 계산됩니다 |

> **`warnings` 는 수정 결과를 반영합니다.** 예를 들어 종료일을 늘려 경고를 해소하면
> 그 경고가 사라진 응답이 옵니다. 반대로 종료일을 과거로 바꾸면 경고가 생깁니다.

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 400 | INVALID_INPUT_VALUE | 제목을 입력해 주세요. | `title` 에 공백뿐인 문자열을 보냄 |
| 400 | INVALID_INPUT_VALUE | 내용을 입력해 주세요. | `content` 에 공백뿐인 문자열을 보냄 |
| 400 | INVALID_INPUT_VALUE | title: 제목은 500자를 넘을 수 없습니다. | 길이 초과 |
| 400 | INVALID_INPUT_VALUE | 노출 시작일은 종료일보다 늦을 수 없습니다. | 적용 결과가 거꾸로인 기간 |
| 400 | INVALID_INPUT_VALUE | image_url 과 clear_image 를 함께 보낼 수 없습니다. … | 교체와 제거를 동시에 요청 |
| 400 | INVALID_INPUT_VALUE | 우리 스토리지에 올린 이미지만 쓸 수 있습니다. … | `image_url` 이 우리 스토리지 주소가 아님 |
| 400 | MALFORMED_REQUEST | 요청 본문을 해석할 수 없습니다. | JSON 파싱 실패, 허용되지 않은 `type`, 날짜 형식 오류 |
| 401 | UNAUTHORIZED | 인증이 필요합니다. | 토큰 없음·만료 |
| 403 | FORBIDDEN | 권한이 없습니다. | `ROLE_ADMIN` 이 아님 |
| 404 | ANNOUNCEMENT_NOT_FOUND | 존재하지 않는 서비스 공지입니다. | 없는 번호 |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 서버 측 처리 오류 |

> **기간 검사는 "적용 후" 값으로 합니다.** 시작일만 보냈더라도 유지되는 종료일과 비교해
> 거꾸로가 되면 400 입니다.

> ⚠ **발행된 공지의 내용을 크게 고치지 마세요.** 팝업 "다시 보지 않기" 는 공지 번호를 키로
> 클라이언트에 저장됩니다. 이미 닫은 사용자는 같은 번호를 숨긴 상태라 **바뀐 내용을 영원히 못 봅니다.**
> 오타 수정은 괜찮지만 내용이 달라지면 새로 작성하세요.
