# 공지 목록 조회

**학교·동아리 공지를 하나의 목록으로 조회합니다. 제공처·분류 다중 필터, 키워드 검색, 관심 분야 필터, 기간 필터, 정렬, 페이지네이션을 모두 이 하나의 엔드포인트가 처리합니다. 홈 피드와 검색 결과 화면이 같은 호출을 파라미터만 바꿔서 씁니다. 본인의 북마크 여부가 각 항목에 함께 내려갑니다.**

- **Method / Endpoint: `GET /api/v1/articles`**
- **Auth Required: Required (User)**

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Authorization | Bearer {access_token} | 서비스 Access Token | **필수** |

## Query Param

| Name | Type | Description | Required | Default |
| --- | --- | --- | --- | --- |
| page | Integer | 조회할 페이지 번호 (**1부터 시작**) | 선택 | 1 |
| size | Integer | 페이지당 건수. **최대 50** | 선택 | 20 |
| sort | String | `{필드},{asc\|desc}`. 여러 번 지정 가능 | 선택 | `published_at,desc` |
| source_type | String | `SCHOOL` \| `CLUB`. 생략 시 통합 | 선택 | - |
| category_id | Array\<Long\> | 분류 ID 다중 필터. 여러 개면 **OR** | 선택 | - |
| vendor_id | Array\<Long\> | 제공처 ID 다중 필터. 여러 개면 **OR** | 선택 | - |
| keyword | String | 제목·본문 부분 일치. **2글자 이상** | 선택 | - |
| interest_only | Boolean | 내 관심 분류의 공지만. **안 보내면 꺼짐** | 선택 | false |
| starts_from | LocalDate | 기간 겹침 필터 시작 (yyyy-MM-dd) | 선택 | - |
| ends_to | LocalDate | 기간 겹침 필터 종료 (yyyy-MM-dd) | 선택 | - |
| has_deadline | Boolean | 마감일(`ends_on`)이 있는 공지만 | 선택 | false |

`category_id` · `vendor_id` 는 `category_id=1&category_id=2` 와 `category_id=1,2` 둘 다 받습니다.
같은 파라미터 안의 여러 값은 OR 이고, 서로 다른 파라미터끼리는 AND 입니다.

> **쿼리 파라미터 이름은 Jackson 이 바꿔 주지 않습니다.** 응답 본문만 snake_case 로 변환되고
> 쿼리 스트링은 컨트롤러가 적어 둔 이름 그대로입니다. `sourceType` 이 아니라 `source_type` 입니다.

### `interest_only` 주의

**안 보내면 `false` 입니다.** 기본은 전체 공지이고, 관심 분류로 거르려면
`interest_only=true` 를 **명시적으로** 보내야 합니다.

> **기본을 끔으로 둔 이유 — 이 필터에는 폴백이 없습니다.**
> 관심 분류가 0개인 사용자가 `true` 로 부르면 조건을 만족하는 공지가 없어
> `content` 가 빈 배열로 내려갑니다. 에러가 아니라 **정상 200 응답**입니다.
>
> 온보딩 중에는 최소 1개를 강제하지만(`ONBOARDING_MIN_SELECTION`), 온보딩을 끝낸 뒤
> 설정에서 전부 해제하는 것은 막지 않습니다. 이 상태가 기본값이었다면 그런 사용자는
> 파라미터를 안 보냈다는 이유만으로 **빈 피드**를 보게 되고, 서버는 200 을 주므로
> 어디에도 기록이 남지 않습니다. 놓친 마감을 놓친 줄도 모르게 됩니다.
>
> 반대 방향의 실수(켜야 하는데 안 켬)는 공지가 많이 보이는 것뿐이라 바로 눈에 띕니다.
> 두 실패의 비용이 달라서 안전한 쪽을 기본으로 뒀습니다.

> **필터가 보는 것은 분류뿐입니다.** 구독한 학과·기관(`user_vendors`)은 이 필터에 들어가지 않습니다.
> 학과만 구독하고 분류를 안 고른 사용자는 `true` 로 부르면 빈 목록을 받습니다.

### `has_deadline` 주의

`true` 일 때만 켜집니다. `false` 를 보내는 것과 아예 안 보내는 것은 같습니다.
켜면 `ends_on` 이 있는 공지만 남습니다.

### `starts_from` · `ends_to` (기간 겹침)

지정한 기간과 공지의 `starts_on`~`ends_on` 이 **겹치는** 공지를 고릅니다. 시작·종료를 정확히 맞추는 필터가 아닙니다.

- 한쪽만 보내면 반대쪽은 무한으로 봅니다
- 공지 쪽 날짜가 비어 있어도 무한으로 봅니다 ("마감일 없는 상시 모집" 이 기간 검색에서 사라지지 않도록)
- 다만 **`starts_on` 과 `ends_on` 이 둘 다 없는 공지는 제외**합니다. 기간으로 찾는다는 건 행사·모집을 찾는다는 뜻이라, 날짜가 없는 일반 안내까지 걸리면 필터가 의미를 잃습니다

### `keyword`

`title` 과 `content` 를 함께 훑습니다. 검색 대상 컬럼은 HTML 태그를 제거하고 소문자로 정규화해 저장한 값이라
`<b>인턴</b>` 처럼 태그가 끼어 있어도 "인턴" 으로 찾힙니다. 대소문자는 구분하지 않습니다.

앞뒤 공백을 제거한 길이가 **2글자 미만이면 `400 SEARCH_KEYWORD_TOO_SHORT`** 입니다.
pg_bigm 이 2-gram 인덱스라 한 글자로는 후보를 좁히지 못하고 사실상 전수 확인이 됩니다.
느린 요청이 아니라 보내면 안 되는 요청이라 400 으로 막습니다.

### `sort` 허용 필드

`published_at` · `created_at` · `updated_at` · `ends_on` · `bookmark_count`

- 목록에 없는 값은 `400 INVALID_SORT_PROPERTY` 입니다. **snake_case 로 보내야 합니다** — `publishedAt` 은 거부됩니다
- 서버가 **항상 `id DESC` 를 마지막에 붙입니다.** 일괄 발행하면 30건의 `published_at` 이 완전히 같아지는데, tie-breaker 가 없으면 페이지 경계에서 같은 공지가 두 번 나오거나 아예 누락됩니다. 카운터 정렬은 값이 0~5 에 몰려 더 심합니다
- `NULLS LAST` 가 항상 붙습니다. 마감일 없는 공지가 마감 임박 목록 맨 위에 올라오지 않게 하기 위해서입니다

> **`sort=ends_on` 은 `has_deadline=true` 와 함께만 됩니다.**
> 마감 필터 없이 마감순으로 정렬하면 부분 인덱스를 벗어나 전체 정렬이 됩니다.
> 따로 보내면 `400 INVALID_SORT_PROPERTY` 이고 메시지가 `"마감 임박순은 has_deadline=true 와 함께만 사용할 수 있습니다."` 로 내려갑니다.

> **`deadline_status` 로는 정렬도 필터도 할 수 없습니다.** DB 컬럼이 아니라 조회 시각에 계산하는 파생값입니다.
> 마감 관련 정렬은 `ends_on`, 필터는 `has_deadline` 을 씁니다.

### 페이지 경계값 처리 — 400 이 아니라 보정입니다

| 요청 | 결과 |
| --- | --- |
| `page` 가 1 미만 | 첫 페이지 |
| `size` 가 50 초과 | **50 으로 잘림** (에러 아님) |
| `size` 가 1 미만 | 기본값 20 |

> **`size=100` 을 보내도 200 이 나오고 50건만 옵니다.** 응답의 `page_info.size` 를 보면 잘렸는지 알 수 있습니다.
> 요청한 size 를 그대로 믿고 화면을 그리면 안 됩니다.

## Request Sample

```
# 기본 목록 (1페이지, 20건, 내 관심 분류만)
GET /api/v1/articles

# 전체 보기 + 다중 분류 + 키워드
GET /api/v1/articles?category_id=1,2&keyword=장학금&page=1&size=20

# 동아리 공지만, 마감 임박순
GET /api/v1/articles?source_type=CLUB&has_deadline=true&sort=ends_on,asc

# 기간 필터 (2월과 겹치는 공지)
GET /api/v1/articles?starts_from=2026-02-01&ends_to=2026-02-28

# 인기순
GET /api/v1/articles?sort=bookmark_count,desc
```

# Response

### 노출 기준

**`status = PUBLISHED` 인 공지만** 나옵니다. 크롤러가 원본 변경을 감지해 재검수로 내려간 공지는
이 목록에서 빠집니다(상세와 북마크 목록에서는 계속 열립니다).
따라서 이 응답의 `under_review` 는 **항상 `false`** 입니다.

### `deadline_status` 분류 기준

| 값 | 조건 |
| --- | --- |
| `UPCOMING` | 오늘 < `starts_on` |
| `OPEN` | 진행 중 (`starts_on` 만 있고 `ends_on` 이 없는 경우 포함) |
| `CLOSING_SOON` | `ends_on` 까지 **3일 이내** |
| `CLOSED` | 오늘 > `ends_on` |
| `ALWAYS` | `starts_on` · `ends_on` 이 둘 다 없음 (상시) |

> DB 컬럼이 아니라 **조회 시각에 계산**하는 파생값입니다. 컬럼으로 두면 매일 자정에 전 행을 갱신하는
> 배치가 필요하고, 그 배치가 밀리면 화면이 "어제 기준" 을 보여 줍니다.
> 한 페이지 안의 모든 항목은 같은 기준일로 판정됩니다.

### Response Param

| name | type | 비고 |
| --- | --- | --- |
| success | Boolean | 요청 성공 여부 |
| data | Object | 응답 데이터 |
| data.content | Array | 공지 목록. 결과가 없으면 빈 배열 |
| data.content[].id | Long | 게시글 고유 ID |
| data.content[].source_type | String | `SCHOOL` \| `CLUB` |
| data.content[].title | String | 제목 |
| data.content[].summary | String | AI 생성 요약. **미생성이면 필드 자체가 없습니다** |
| data.content[].published_at | String | 발행 일시 (ISO-8601 offset) |
| data.content[].starts_on | String | 시작일 (yyyy-MM-dd). **없으면 필드 자체가 없습니다** |
| data.content[].ends_on | String | 마감일 (yyyy-MM-dd). **없으면 필드 자체가 없습니다** |
| data.content[].deadline_status | String | 마감 상태 (위 표) |
| data.content[].bookmark_count | Integer | 전체 북마크 수 |

| data.content[].view_count | Long | 조회 수 |
| data.content[].is_bookmarked | Boolean | 호출한 사용자의 북마크 여부 |
| data.content[].has_attachment | Boolean | 첨부 존재 여부. 목록의 클립 아이콘용이라 개수·목록은 주지 않습니다 |
| data.content[].under_review | Boolean | 재검수 배지. **이 목록에서는 항상 false** |
| data.content[].vendors | Array | 제공처 목록. 없으면 빈 배열 |
| data.content[].vendors[].id | Long | 제공처 ID |
| data.content[].vendors[].name | String | 제공처 이름 |
| data.content[].vendors[].initial | String | 축약 표시 ("컴퓨터공학과" → "컴공"). 좁은 칩에 씁니다 |
| data.content[].vendors[].type | String | `SCHOOL` \| `CLUB` |
| data.content[].categories | Array | 분류 목록. 없으면 빈 배열 |
| data.content[].categories[].id | Long | 분류 ID |
| data.content[].categories[].name | String | 분류 이름 |
| data.page_info | Object | 페이징 정보 |
| data.page_info.current_page | Integer | 현재 페이지 번호 (1부터). 결과가 0건이어도 1 입니다 |
| data.page_info.size | Integer | 페이지당 건수. **요청값이 아니라 서버가 실제로 적용한 값** |
| data.page_info.total_pages | Integer | 전체 페이지 수. 0건이면 0 |
| data.page_info.total_items | Long | 전체 건수 |
| data.page_info.has_next | Boolean | 다음 페이지 존재 여부 |
| error | Object | 에러 정보 (성공 시 null) |

> **`null` 인 필드는 응답에서 아예 빠집니다** (`default-property-inclusion: non_null`).
> `summary` · `starts_on` · `ends_on` 이 여기 해당합니다. 프론트는 `article.summary === null` 이 아니라
> **키의 존재 여부**로 판단해야 합니다. 카운터와 boolean 은 원시 타입이라 항상 옵니다.

> **`vendors` · `categories` 는 배열입니다.** 같은 공지가 학과 게시판과 교무처 게시판에 동시에
> 올라오는 일이 흔하고, 분류도 여러 개가 붙습니다.
> 목록의 `vendors` 는 **같은 제공처가 중복되지 않게 정리**해서 내려갑니다 — 같은 게시판에 재게시된
> 원본은 DB 에 여러 행으로 남지만, 카드에 같은 이름의 칩이 두세 개 반복되면 안 되기 때문입니다.
> (상세는 반대로 중복을 남깁니다. 거기서는 행 하나가 원본 게시물 하나이고 각자 링크가 다릅니다.)

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 400 | SEARCH_KEYWORD_TOO_SHORT | 검색어는 2글자 이상 입력해야 합니다. | 공백 제거 후 `keyword` 가 1글자. pg_bigm 이 2-gram 이라 인덱스가 후보를 좁히지 못합니다 |
| 400 | INVALID_SORT_PROPERTY | 허용되지 않은 정렬 기준입니다: {필드} | `sort` 화이트리스트 밖의 필드 |
| 400 | INVALID_SORT_PROPERTY | 마감 임박순은 has_deadline=true 와 함께만 사용할 수 있습니다. | `sort=ends_on` 을 `has_deadline=true` 없이 보냄 |
| 400 | INVALID_INPUT_VALUE | {파라미터명}: 값의 형식이 올바르지 않습니다. | 날짜 형식 오류(`starts_from=2026-13-01`), `source_type` 오타·소문자(`club`), 숫자여야 할 자리에 문자 |
| 401 | UNAUTHORIZED | 인증이 필요합니다. | 토큰 없음·만료. **이 목록은 비로그인으로 열리지 않습니다** |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 서버 측 처리 오류 |

> 검증 순서는 `keyword` → `sort` 입니다. 둘 다 잘못된 요청은 `SEARCH_KEYWORD_TOO_SHORT` 가 먼저 나갑니다.
> 정렬 검증은 결과 건수를 세기 **전에** 합니다 — 나중에 하면 결과가 0건인 요청에서 검증이 통째로 건너뛰어져
> 같은 잘못된 요청이 데이터 유무에 따라 400 이 되기도 하고 200 이 되기도 합니다.
