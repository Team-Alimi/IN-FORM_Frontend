# 회원 탈퇴

**본인 계정을 탈퇴 처리합니다. 행을 지우지 않는 soft delete 로, 상태만 `WITHDRAWN` 으로 바꾸고 탈퇴 시각을 남깁니다. 성공하면 그 사용자의 모든 세션이 즉시 끊기므로, 프론트는 응답을 받은 뒤 저장한 토큰을 버리고 로그인 화면으로 돌아가면 됩니다.**

- **Method / Endpoint: `DELETE /api/v1/users/me`**
- **Auth Required: Required (User)**

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Authorization | Bearer {access_token} | 서비스 Access Token | **필수** |

요청 body 가 없습니다. 확인용 비밀번호나 사유 입력을 받지 않습니다.

## Request Sample

```
DELETE /api/v1/users/me
Authorization: Bearer eyJ...
```

# Response

## Response Param

| name | type | 비고 |
| --- | --- | --- |
| success | Boolean | 항상 `true` |
| data | - | **없습니다.** 반환값이 `null` 이라 키 자체가 응답에서 빠집니다 |
| error | Object | 에러 정보 (성공 시 키 자체가 빠짐) |

> **성공 응답 본문은 `{"success": true}` 한 줄입니다.**
> `data` 가 `null` 인 게 아니라 `data` 키가 아예 없습니다(`default-property-inclusion: non_null`).
> `response.data.something` 을 읽으려 들면 터집니다. 성공 판정은 `success` 로만 하세요.

## 무엇이 지워지고 무엇이 남는가

| 대상 | 처리 |
| --- | --- |
| `users` 행 | **남습니다.** `status = WITHDRAWN`, `withdrawn_at` 기록 (soft delete) |
| 구독 학과·기관 / 관심 분류 / 관심 동아리 유형 | 전부 삭제 |
| 북마크 | 전부 삭제 |
| 알림 | 전부 삭제 |
| 작성한 댓글 | **남습니다** |

> **북마크를 남기지 않는 이유**는 카운터입니다. soft delete 라 행이 남으므로 FK CASCADE 가
> 발동하지 않고, 그대로 두면 북마크 수가 부풀어 인기 공지 정렬이 왜곡됩니다.
> 그래서 같은 트랜잭션에서 명시적으로 지웁니다.
>
> **댓글은 반대로 남깁니다.** 지우면 대화 흐름이 끊깁니다. 작성자 표시는 화면에서
> "탈퇴한 사용자" 로 렌더링합니다.

## 세션 처리

탈퇴가 커밋된 뒤 Refresh Token 전체를 폐기하고, 이미 발급된 Access Token 도 발급 시각 기준으로
무효화합니다. Access Token 은 stateless 라 폐기하지 않으면 만료(1시간)까지 그대로 통하고,
그 사이 탈퇴한 계정이 댓글을 계속 남길 수 있습니다.

> 세션 정리가 실패해도 계정은 이미 탈퇴 처리된 상태입니다. 남은 Refresh Token 으로 재발급을
> 시도해도 활성 사용자만 통과시키므로 `USER_NOT_FOUND` 가 됩니다.

## 재가입

같은 구글 계정으로 다시 로그인하면 **새 계정**이 생깁니다. 활성 이메일 UNIQUE 인덱스가
`status = 'ACTIVE'` 부분 유니크라 탈퇴한 행과 충돌하지 않기 때문입니다.
이전 북마크·구독은 돌아오지 않습니다.

## Response Sample

```json
{
  "success": true
}
```

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 400 | CANNOT_CHANGE_OWN_ROLE | 관리자 권한을 가진 계정은 탈퇴할 수 없습니다. 다른 관리자에게 권한 해제를 요청한 뒤 다시 시도해 주세요. | `role = ADMIN` 인 계정의 탈퇴 시도 |
| 401 | UNAUTHORIZED | 인증이 필요합니다. | 토큰 없음·만료·무효화됨 |
| 404 | USER_NOT_FOUND | 존재하지 않는 사용자입니다. | 계정이 없거나 **이미 탈퇴한 계정의 재탈퇴 시도** |
| 409 | CONCURRENT_MODIFICATION | 다른 사용자가 먼저 수정했습니다. 새로고침 후 다시 시도해 주세요. | 탈퇴 저장 중 관리자가 같은 계정의 권한을 바꾼 경우 (낙관적 잠금) |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 서버 측 처리 오류 |

> **관리자 탈퇴 차단은 `CANNOT_CHANGE_OWN_ROLE` 로 나갑니다.** 코드 이름이 탈퇴와 어울리지 않아
> 보이지만, 이 경로가 지키는 불변식이 관리자 권한 변경과 같은 것("활성 관리자는 최소 한 명 남는다")이라
> 코드를 공유합니다. 메시지는 기본 문구 대신 위 표의 탈퇴 전용 문구가 내려가므로,
> 프론트는 `message` 를 그대로 노출해도 됩니다.
>
> 탈퇴해도 `role` 은 `ADMIN` 인 채 `status` 만 바뀝니다. 마지막 관리자가 탈퇴하면 활성 관리자가
> 0명이 되고, 그 사람이 다시 로그인하면 `role = USER` 인 새 계정이 만들어져 권한을 되돌릴 방법이
> 없어집니다. "관리자가 한 명뿐일 때만 막기" 로 세지 않는 이유는 그 판정이 동시 탈퇴에 취약하기
> 때문입니다.
>
> **탈퇴는 멱등이 아닙니다.** 두 번째 호출은 `404 USER_NOT_FOUND` 입니다. 다만 첫 호출로 토큰이
> 이미 무효화되므로 실제로는 `401` 을 먼저 받습니다.
