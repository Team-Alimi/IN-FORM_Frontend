# 관심 분류 저장

**관심 분류(장학·취업·행사 등)를 저장합니다. 온보딩 3단계의 "다음" 버튼과 마이페이지 관심사 관리의 "저장" 버튼이 같은 API 를 부릅니다. 개별 추가·삭제가 아니라 **최종 선택 집합 전체**를 보내면 서버가 현재 상태와 비교해 차이만 반영하고, 저장 후의 목록을 그대로 돌려줍니다.**

- **Method / Endpoint: `PUT /api/v1/users/me/interests/categories`**
- **Auth Required: Required (User)**

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Authorization | Bearer {access_token} | 서비스 Access Token | **필수** |
| Content-Type | application/json | | **필수** |

## Body Param

| Name | Type | Description | Required |
| --- | --- | --- | --- |
| ids | Array&lt;Long&gt; | 관심 분류 `categories.id` 의 **최종 목록**. 체크박스 상태를 그대로 보내면 됩니다 | **필수** |

> **`ids` 는 델타가 아니라 전체 교체 목록입니다.** 빠진 id 는 관심 해제로 처리됩니다.

> **빈 배열 `[]` 은 온보딩 중에만 거부됩니다.** 온보딩을 마친 뒤에는 "전부 해제" 로 정상
> 처리됩니다. 온보딩 여부는 클라이언트가 알려주는 값이 아니라 **서버가 DB 의 온보딩 완료 시각으로
> 판정**합니다 — 클라이언트가 알려주는 방식이면 그 값을 조작해 최소 선택 검증을 건너뛸 수 있습니다.

> **`ids` 필드 자체를 빼면 `400 INVALID_INPUT_VALUE`** 입니다. `[]` 와 필드 누락은 다릅니다.

> **비활성 분류는 새로 선택할 수 없지만, 이미 선택해 둔 것은 그대로 유지됩니다.**
> 저장이 델타 방식이라 기존 선택은 다시 INSERT 되지 않아 검사를 거치지 않습니다.
> 그래서 비활성화된 분류가 목록에 이미 들어 있는 상태에서 다른 분류를 하나 추가하는 저장은
> 정상 동작합니다. 반대로 목록에서 뺐다가 다시 넣으면 그때는 `400 INACTIVE_CATEGORY` 입니다.

> **중복 id 는 한 번으로 합쳐집니다.** `[3, 3, 5]` 는 `[3, 5]` 와 같습니다.

## Request Sample

```json
PUT /api/v1/users/me/interests/categories
Authorization: Bearer eyJ...
Content-Type: application/json

{
  "ids": [3, 5]
}
```

전부 해제 (온보딩 완료 후에만 허용):

```json
{
  "ids": []
}
```

# Response

## Response Param

| name | type | 비고 |
| --- | --- | --- |
| success | Boolean | 요청 성공 여부 |
| data | Array | 저장 후의 목록. `GET /users/me/interests/categories` 와 완전히 같은 모양 |
| data[].id | Long | `categories.id` |
| data[].name | String | 분류 이름 |
| error | Object | 에러 정보 (성공 시 키 자체가 빠짐) |

> **응답이 GET 과 동일합니다.** 저장 직후 GET 을 다시 부를 필요가 없습니다.
> 정렬은 **이름 오름차순**이며, 요청에 보낸 배열 순서는 보존되지 않습니다.

## Response Sample

```json
{
  "success": true,
  "data": [
    { "id": 5, "name": "취업" },
    { "id": 3, "name": "장학" }
  ]
}
```

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 400 | INVALID_INPUT_VALUE | ids: ids 는 필수입니다. | `ids` 필드가 없거나 `null` |
| 400 | MALFORMED_REQUEST | 요청 본문을 해석할 수 없습니다. | 본문이 없거나 JSON 이 아님, `ids` 원소가 숫자가 아님 |
| 400 | ONBOARDING_MIN_SELECTION | 최소 1개 이상 선택해야 합니다. | **온보딩 중**에 `ids: []` 를 보낸 경우 |
| 400 | INACTIVE_CATEGORY | 비활성 분류는 새로 선택할 수 없습니다 (category_id=7) | 비활성화된 분류를 **새로** 선택한 경우 (DB 트리거 `IN010`) |
| 400 | RELATED_RESOURCE_NOT_FOUND | 참조 대상이 존재하지 않습니다. | 존재하지 않는 `category_id` (FK 위반). **조용히 무시하지 않습니다** |
| 401 | UNAUTHORIZED | 인증이 필요합니다. | 토큰 없음·만료·무효화됨 |
| 404 | USER_NOT_FOUND | 존재하지 않는 사용자입니다. | 계정이 없거나 이미 `WITHDRAWN` |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 서버 측 처리 오류 |

> **`INACTIVE_CATEGORY` 의 `message` 는 ErrorCode 기본 문구가 아니라 DB 트리거가 만든 문장이며,
> 문제가 된 `category_id` 가 괄호 안에 들어 있습니다.** 여러 개가 비활성이면 먼저 걸린 하나만
> 보고됩니다.

> **부분 성공이 없습니다.** 목록에 잘못된 id 가 하나라도 있으면 트랜잭션 전체가 롤백되어
> 아무것도 저장되지 않습니다.
