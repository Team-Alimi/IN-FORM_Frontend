# 관심 분류 조회

**내가 고른 관심 분류(장학·취업·행사 등) 목록을 조회합니다. 온보딩 3단계에서 체크박스의 초기 선택 상태를 그릴 때, 그리고 마이페이지 관심사 관리 화면을 열 때 부릅니다. 여기서 고른 분류가 공지 목록의 `interest_only` 필터가 걸러 내는 기준이 됩니다.**

- **Method / Endpoint: `GET /api/v1/users/me/interests/categories`**
- **Auth Required: Required (User)**

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Authorization | Bearer {access_token} | 서비스 Access Token | **필수** |

## Request Sample

```
GET /api/v1/users/me/interests/categories
Authorization: Bearer eyJ...
```

# Response

## Response Param

| name | type | 비고 |
| --- | --- | --- |
| success | Boolean | 요청 성공 여부 |
| data | Array | **객체가 아니라 배열입니다.** 선택한 항목 목록 |
| data[].id | Long | `categories.id` |
| data[].name | String | 분류 이름 (예: `장학`) |
| error | Object | 에러 정보 (성공 시 키 자체가 빠짐) |

> **`data` 가 배열입니다.** `data.content` / `data.page_info` 로 감싸지 않고 페이징도 없습니다.

> **`code`·`is_active`·`sort_order` 는 내려가지 않습니다.** id 와 이름 두 개뿐입니다.
> 정렬 순서나 활성 여부가 필요하면 마스터 목록(`GET /categories`, 비로그인 허용)을 쓰세요.

> **정렬은 이름 오름차순(`name ASC`)입니다.** 마스터 목록의 `sort_order` 와 다릅니다.
> 두 화면의 순서를 맞추려면 프론트에서 다시 정렬해야 합니다.

> **비활성화된 분류도 여기에는 그대로 나옵니다.** 관리자가 분류를 비활성화해도 이미 선택해 둔
> 관계는 지우지 않기 때문입니다. 그 항목은 마스터 목록에는 없는데 이 응답에는 있을 수 있습니다 —
> 체크박스를 마스터 목록만으로 그리면 선택 상태가 사라진 것처럼 보입니다.

> **선택이 없으면 빈 배열 `[]` 입니다.** `null` 이 아닙니다.

## Response Sample

```json
{
  "success": true,
  "data": [
    { "id": 5, "name": "취업" },
    { "id": 3, "name": "장학" }
  ]
}
```

선택이 하나도 없을 때:

```json
{
  "success": true,
  "data": []
}
```

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 401 | UNAUTHORIZED | 인증이 필요합니다. | 토큰 없음·만료·무효화됨 |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 서버 측 처리 오류 |

> **이 조회는 `USER_NOT_FOUND` 를 내지 않습니다.** 사용자 행을 확인하지 않고 관계 테이블만 읽기
> 때문입니다. 저장(`PUT`) 쪽은 사용자 행을 확인하므로 `404` 가 있습니다.
