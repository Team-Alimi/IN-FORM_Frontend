# 중복 공지 병합

**중복 수집된 공지들을 하나로 합칩니다. 남길 공지(`target_id`)에 나머지(`source_ids`)의 제공처·북마크·첨부·분류·댓글·알림을 전부 옮긴 뒤, 흡수된 공지는 삭제합니다. `GET /admin/articles/{id}/similar` 로 두 글을 나란히 확인한 다음 부르는 것이 정상 흐름입니다.**

- **Method / Endpoint: `POST /api/v1/admin/articles/merge`**
- **Auth Required: Required (Admin)**

> **되돌릴 수 없습니다.** 흡수된 공지는 하드 삭제되고 복구 경로가 없습니다.
> 실행 전에 확인 단계를 두는 것을 권합니다.

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Authorization | Bearer {access_token} | 서비스 Access Token | **필수** |
| Content-Type | application/json | | **필수** |

## Body Param

| Name | Type | Description | Required |
| --- | --- | --- | --- |
| target_id | Long | **남길** 공지 ID. 여기로 전부 모입니다 | **필수** |
| source_ids | Array&lt;Long&gt; | 흡수될 공지 ID 목록. 비어 있으면 `400`, **최대 20건** | **필수** |
| memo | String | 상태 이력에 남길 사유. 최대 500자 | 선택 |

- `source_ids` 안의 **중복은 합쳐지고, `target_id` 와 같은 값은 걸러집니다.**
  걸러낸 뒤 남는 것이 없으면 `400 INVALID_INPUT_VALUE` 입니다
- 응답의 `merged` 가 실제로 처리된 목록이라, 요청과 다를 수 있습니다

## Request Sample

```json
POST /api/v1/admin/articles/merge
{
  "target_id": 42,
  "source_ids": [39, 40],
  "memo": "같은 장학 공지가 학과·교무처에 중복 수집됨"
}
```

# Response

## Response Param

| name | type | 비고 |
| --- | --- | --- |
| success | Boolean | 요청 성공 여부 |
| data | Object | 응답 데이터 |
| data.target_id | Long | 남은 공지 ID |
| data.merged | Array&lt;Long&gt; | **실제로** 흡수된 공지 ID (중복·자기 자신 제외 후) |
| data.moved | Object | 옮겨진 것들의 건수 |
| data.moved.vendors | Integer | 옮겨진 제공처 연결 수 |
| data.moved.bookmarks | Integer | 옮겨진 북마크 수 |
| data.moved.attachments | Integer | 옮겨진 첨부 수 |
| data.moved.categories | Integer | 옮겨진 분류 연결 수 |
| data.moved.comments | Integer | 옮겨진 댓글 수 |
| data.moved.notifications | Integer | 옮겨진 알림 수 |
| error | Object | 에러 정보 (성공 시 null) |

> **`moved` 를 화면에 반드시 보여 주세요.** 병합은 되돌릴 수 없고 흡수된 공지는 사라집니다.
> 관리자가 그 자리에서 "예상한 만큼 옮겨졌나" 를 확인할 수 없으면, 무언가 빠졌어도 알아챌 방법이 없습니다.

## Response Sample

```json
{
  "success": true,
  "data": {
    "target_id": 42,
    "merged": [39, 40],
    "moved": {
      "vendors": 2,
      "bookmarks": 17,
      "attachments": 3,
      "categories": 1,
      "comments": 5,
      "notifications": 8
    }
  },
  "error": null
}
```

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 400 | INVALID_INPUT_VALUE | 흡수할 공지가 없습니다. | `source_ids` 를 걸러낸 뒤 남는 것이 없을 때 |
| 400 | INVALID_INPUT_VALUE | 유효하지 않은 입력 값입니다. | `target_id` 누락, `source_ids` 가 비었거나 20건 초과, `memo` 500자 초과 |
| 400 | INVALID_STATE_TRANSITION | 휴지통에 있는 공지로는 병합할 수 없습니다. | `target_id` 가 `TRASHED` 일 때 |
| 400 | VENDOR_TYPE_MISMATCH | 공지 출처와 제공처 유형이 일치하지 않습니다. | 학교 공지에 동아리 제공처를 옮기려 할 때 (DB 트리거) |
| 401 | UNAUTHORIZED | 인증이 필요합니다. | 토큰 없음·만료 |
| 403 | FORBIDDEN | 권한이 없습니다. | 관리자가 아님 |
| 404 | ARTICLE_NOT_FOUND | 존재하지 않는 게시글입니다. | `target_id` 또는 `source_ids` 중 하나가 없을 때 |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 서버 측 처리 오류 |

> **벌크 API 와 달리 부분 성공이 없습니다.** 한 건이라도 실패하면 전체가 롤백됩니다 —
> 절반만 합쳐진 상태는 관리자가 손으로 되돌릴 수 없기 때문입니다.
