# 카테고리 등록

**새 공지 카테고리를 등록합니다. `code` 는 크롤러 AI 분류기가 결과를 보낼 때 쓰는 계약 키라서, 등록 전에 크롤러 팀의 카테고리 목록과 값을 맞춰 두어야 합니다. 관리 화면의 카테고리 관리 탭에서 "추가" 를 눌렀을 때 호출합니다.**

- **Method / Endpoint: `POST /api/v1/admin/categories`**
- **Auth Required: Required (Admin)**

성공 시 HTTP 상태는 **201 Created** 입니다.

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Authorization | Bearer {access_token} | 서비스 Access Token | **필수** |
| Content-Type | application/json | | **필수** |

## Body Param

| Name | Type | Description | Required |
| --- | --- | --- | --- |
| code | String | 크롤러 AI 카테고리 계약 키. 최대 50자. **영문·숫자·밑줄만**. **등록 후 변경 불가** | **필수** |
| name | String | 화면 표시 이름. 최대 100자 | **필수** |
| sort_order | Integer | 화면 정렬 값. **생략하면 `0`** | 선택 |

### `code` 규칙

- **대문자로 정규화되어 저장됩니다.** `"scholarship"` 을 보내면 `"SCHOLARSHIP"` 이 저장됩니다.
  대소문자만 다른 값을 따로 두면 UNIQUE 에도 안 걸리고 카테고리만 조용히 실패하는데,
  목록에서는 `SCHOLARSHIP` 과 `Scholarship` 이 둘 다 그럴듯해 보여 어느 쪽이 진짜인지 알 수 없습니다
- 앞뒤 공백은 제거합니다
- 정규화한 값이 `[A-Z0-9_]+` 를 만족해야 합니다. **한글·공백·하이픈은 거부합니다** (`400`)
- **등록 후에는 바꿀 수 없습니다.** 오타를 냈다면 새로 만들고 기존 것을 지우거나 비활성화하세요

> **`code` 와 `name` 이 둘 다 UNIQUE 입니다.** 어느 쪽이 겹쳤는지 응답 메시지에 담아 보냅니다 —
> 그러지 않으면 관리자는 같은 화면에서 두 값을 번갈아 바꿔 봐야 합니다.

> **등록만으로는 카테고리가 붙지 않습니다.** 크롤러 AI 카테고리 목록에 이 `code` 가 추가돼야
> 새 공지에 실제로 달리기 시작합니다. 크롤러 시드는 이 API 의 사정 밖이라 서버가 강제할 방법이 없고,
> 제공처 등록과 달리 **응답 `warning` 으로도 알려 주지 않습니다.**
> 그 안내는 화면 문구로 직접 넣어야 합니다.

## Request Sample

```json
POST /api/v1/admin/categories
{
  "code": "EXCHANGE_PROGRAM",
  "name": "교환학생",
  "sort_order": 30
}
```

`sort_order` 를 생략하면 `0` 으로 저장돼 목록 맨 앞에 옵니다.

```json
POST /api/v1/admin/categories
{
  "code": "contest",
  "name": "공모전"
}
```

# Response

## Response Param

| name | type | 비고 |
| --- | --- | --- |
| success | Boolean | 요청 성공 여부 |
| data | Object | 등록된 카테고리 |
| data.id | Long | 새로 발급된 카테고리 ID |
| data.code | String | 정규화(트림 + 대문자)된 계약 키. **요청에 보낸 문자열과 다를 수 있습니다** |
| data.name | String | 정규화(앞뒤 공백 제거)된 이름 |
| data.is_active | Boolean | 등록 직후에는 항상 `true` |
| data.sort_order | Integer | 정렬 값. 생략했으면 `0` |
| data.in_use | Boolean | 등록 직후에는 항상 `false` |
| data.warning | String | **등록 응답에서는 절대 내려오지 않습니다** |

> `code` 는 응답 값을 기준으로 삼으세요. 크롤러 카테고리 목록에 적을 문자열은 요청 원문이 아니라
> `data.code` 입니다.

> **`sort_order` 의 기본값은 `0` 입니다.** 화면에서 입력란을 비워 둔 채 등록하면 새 카테고리가
> 목록 맨 앞으로 올라옵니다. 뒤에 붙이려면 값을 명시해서 보내야 합니다.

## Response Sample

```json
{
  "success": true,
  "data": {
    "id": 21,
    "code": "EXCHANGE_PROGRAM",
    "name": "교환학생",
    "is_active": true,
    "sort_order": 30,
    "in_use": false
  }
}
```

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 400 | INVALID_INPUT_VALUE | code: 카테고리 코드를 입력해 주세요. | `code` 가 비었거나 공백뿐 |
| 400 | INVALID_INPUT_VALUE | name: 카테고리 이름을 입력해 주세요. | `name` 이 비었거나 공백뿐 |
| 400 | INVALID_INPUT_VALUE | 카테고리 코드는 영문 대문자·숫자·밑줄만 쓸 수 있습니다. 크롤러와 주고받는 계약 키입니다. | `code` 에 한글·공백·하이픈 등이 섞임 |
| 400 | INVALID_INPUT_VALUE | code: 카테고리 코드는 50자를 넘을 수 없습니다. | 길이 초과 (`name` 100자도 같은 코드) |
| 400 | MALFORMED_REQUEST | 요청 본문을 해석할 수 없습니다. | JSON 파싱 실패, `sort_order` 가 정수가 아님 |
| 401 | UNAUTHORIZED | 인증이 필요합니다. | 토큰 없음·만료 |
| 403 | FORBIDDEN | 권한이 없습니다. | 로그인은 했으나 `ROLE_ADMIN` 이 아님 |
| 409 | DUPLICATE_RESOURCE | 이미 쓰이고 있는 카테고리 코드입니다: {code} | `code` 중복 (대문자로 정규화한 뒤 비교) |
| 409 | DUPLICATE_RESOURCE | 이미 쓰이고 있는 카테고리 이름입니다: {name} | `name` 중복 |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 서버 측 처리 오류 |

> Bean Validation 이 걸러낸 오류의 `message` 는 `"{필드명}: {제약 메시지}"` 형태이고,
> 이때 **필드명은 JSON 키가 아니라 자바 필드 이름(camelCase)** 입니다 — `sort_order` 가 아니라 `sortOrder`.

> 코드·이름 중복은 컬럼 UNIQUE 도 함께 막습니다. 동시 요청이 겹쳐 그쪽까지 갔을 때도
> 같은 `409 DUPLICATE_RESOURCE` 지만, 메시지는 `"이미 존재하는 값입니다."` 라는 일반 문구가 나갑니다.
