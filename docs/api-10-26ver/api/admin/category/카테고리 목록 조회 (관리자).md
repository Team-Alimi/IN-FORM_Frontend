# 카테고리 목록 조회 (관리자)

**관리 화면의 카테고리 목록입니다. 비활성 카테고리까지 포함하고, 각 항목에 "지금 쓰이고 있는지"(`in_use`)가 함께 내려옵니다. 프론트는 이 값으로 삭제 버튼의 활성 여부를 미리 정합니다. 사용자용 목록(`GET /categories`)과 별개이며 그쪽은 활성만, `code` 없이 내보냅니다.**

- **Method / Endpoint: `GET /api/v1/admin/categories`**
- **Auth Required: Required (Admin)**

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Authorization | Bearer {access_token} | 서비스 Access Token | **필수** |

## Query Param

| Name | Type | Description | Required | Default |
| --- | --- | --- | --- | --- |
| is_active | Boolean | 활성 여부 필터. **생략하면 비활성 포함 전체** | 선택 | - |

> **`is_active` 를 생략하면 비활성 카테고리가 함께 내려옵니다.** 접어 둔 카테고리를 다시 켤 수 있어야 하므로
> 이것이 기본값입니다. 활성만 보려면 `is_active=true` 를 명시하세요.

> **페이징이 없습니다.** `page`·`size`·`sort` 를 보내도 서버가 읽지 않습니다.
> 정렬은 `sort_order` 오름차순 → `name` 오름차순 → `id` 오름차순으로 쿼리에 고정돼 있습니다.
> `name` 정렬은 DB collation(`en_US.utf8`)을 따르므로 한글 이름은 사전 순이 아닐 수 있습니다 —
> 다만 `sort_order` 가 앞서므로 관리자가 정한 순서가 우선합니다.

## Request Sample

```
# 전체 (비활성 포함)
GET /api/v1/admin/categories

# 활성 카테고리만
GET /api/v1/admin/categories?is_active=true
```

# Response

## Response Param

| name | type | 비고 |
| --- | --- | --- |
| success | Boolean | 요청 성공 여부 |
| data | Array | 카테고리 목록. **`data.content`·`data.page_info` 가 없습니다 — 배열이 곧 `data` 입니다** |
| data[].id | Long | 카테고리 ID |
| data[].code | String | 크롤러 AI 카테고리 계약 키. 대문자·숫자·밑줄. **등록 후 변경 불가** |
| data[].name | String | 화면 표시 이름 |
| data[].is_active | Boolean | 활성 여부. `false` 는 신규 선택·카테고리에서 숨긴 상태 |
| data[].sort_order | Integer | 화면 정렬 값 |
| data[].in_use | Boolean | 공지 또는 사용자 관심분야가 이 카테고리를 쓰고 있는지 |
| data[].warning | String | **이 목록에서는 절대 내려오지 않습니다** |

> **`in_use: true` 면 삭제 버튼을 비활성화하세요.** 눌러 봐야 `409 CATEGORY_IN_USE` 로 돌아옵니다.
> 누르기 전에 알 수 있게 하려고 넣은 값입니다. 판정은 `article_categories` 와
> `user_interest_categories` **둘 다** 를 봅니다 — 공지가 안 쓰더라도 누군가의 관심분야에 들어 있으면 `true` 입니다.
>
> 운영에 들어간 카테고리는 사실상 전부 `in_use: true` 가 됩니다. 삭제는
> **잘못 만든 카테고리를 등록 직후 되돌리는 용도**로 보는 편이 맞습니다.

> **목록 응답에는 `warning` 이 없습니다.** 이 필드는 수정에서 비활성화했을 때만 채워집니다.
> 목록은 항상 `null` 로 만들어지고 `null` 필드는 응답에서 빠지므로, 프론트는 목록 행에
> `warning` 키가 있다고 가정하면 안 됩니다.

> **`code` 를 화면 로직에 쓰지 마세요.** 크롤러 AI 카테고리와 주고받는 계약 키라서 내보내기는 하지만,
> 이 문자열에 조건을 걸면 연동 계약을 바꿀 때 프론트까지 함께 깨집니다.
> 표시는 `name`, 식별은 `id` 입니다. 사용자용 목록(`GET /categories`)에는 아예 나가지 않습니다.

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 400 | INVALID_INPUT_VALUE | is_active: 값의 형식이 올바르지 않습니다. | `is_active` 가 boolean 으로 해석되지 않음 |
| 401 | UNAUTHORIZED | 인증이 필요합니다. | 토큰 없음·만료 |
| 403 | FORBIDDEN | 권한이 없습니다. | 로그인은 했으나 `ROLE_ADMIN` 이 아님 |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 서버 측 처리 오류 |
