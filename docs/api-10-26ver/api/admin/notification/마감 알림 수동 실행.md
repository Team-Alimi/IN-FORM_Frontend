# 마감 알림 수동 실행

**마감 D-1 알림 생성 배치를 지금 한 번 돌립니다. 09:00 배치를 기다리지 않고 알림 화면을 확인할 때 씁니다.**

- **Method / Endpoint: `POST /api/v1/admin/notifications/deadline-run`**
- **Auth Required: Required (Admin)**

> **09:00 배치와 완전히 같은 코드입니다.** 테스트용 별도 경로가 아니라 같은 메서드를 부릅니다 —
> 경로가 갈라지면 테스트에서 본 결과가 운영을 대변하지 못합니다.

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Authorization | Bearer {access_token} | 서비스 Access Token | **필수** |

본문도 파라미터도 없습니다.

## Request Sample

```
POST /api/v1/admin/notifications/deadline-run
```

# 테스트 흐름

```
1) 공지를 하나 만들거나 골라 마감일(ends_on)을 내일로 둡니다
2) 테스트 계정으로 그 공지를 북마크합니다
3) 이 API 를 부릅니다  →  알림이 즉시 생깁니다
4) GET /api/v1/notifications 로 확인
```

## ★ 날짜를 받지 않습니다

기준일은 **언제나 "내일"** 입니다. 임의 날짜를 지정할 수 없습니다.

알림 문구가 `마감이 하루 남았습니다` 로 고정돼 있어서, 두 달 뒤 마감인 공지에 이걸 보내면
**실제 사용자에게 거짓을 알리는 것**이 됩니다. 그래서 날짜를 파라미터로 열지 않았습니다.

> 특정 공지로 시험하고 싶으면 **그 공지의 마감일을 내일로 바꾸세요**
> (`PATCH /api/v1/admin/articles/{articleId}` 의 `ends_on`).

## 여러 번 눌러도 안전합니다

같은 (사용자, 공지, 마감일) 조합은 유니크 인덱스가 막습니다. 두 번째부터는 `created: 0` 입니다.

# Response

## Response Param

| name | type | 비고 |
| --- | --- | --- |
| success | Boolean | 요청 성공 여부 |
| data.deadline | String | 이번 실행의 기준 마감일 `yyyy-MM-dd` (= 서버가 본 "내일") |
| data.created | Integer | **새로** 만들어진 건수. 중복으로 건너뛴 것은 세지 않습니다 |

## Response Sample

```json
{
  "success": true,
  "data": {
    "deadline": "2026-10-13",
    "created": 3
  }
}
```

## `created: 0` 일 때

**정상인 경우가 대부분입니다.** 다음 셋 중 하나입니다.

| 원인 | 확인 방법 |
|---|---|
| 이미 만들어 둠 (두 번째 실행) | 알림 목록에 이미 있는지 |
| 내일 마감인 공지를 아무도 북마크하지 않음 | 응답의 `deadline` 과 공지의 `ends_on` 비교 |
| 그 공지가 발행 상태가 아님 | 관리자 공지 목록에서 `status` 확인 |

> **응답의 `deadline` 을 먼저 보세요.** 서버가 본 "내일" 이 찍혀 있어서,
> 공지의 `ends_on` 과 하루라도 어긋나면 바로 드러납니다.

> 탈퇴한 사용자(`status = WITHDRAWN`)의 북마크는 대상이 아닙니다.

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 401 | UNAUTHORIZED | 인증이 필요합니다. | 토큰 없음·만료 |
| 403 | FORBIDDEN | 권한이 없습니다. | `ROLE_ADMIN` 이 아님 |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 생성 실패 |

> **수동 실행은 실패를 숨기지 않습니다.** 09:00 배치는 예외를 삼키고 로그만 남기지만
> (스케줄러 스레드가 죽으면 다음 날도 돌지 않기 때문입니다), 이쪽은 500 으로 내보냅니다 —
> 손으로 돌린 사람은 "대상이 없음" 과 "실패" 를 구분할 수 있어야 합니다.
