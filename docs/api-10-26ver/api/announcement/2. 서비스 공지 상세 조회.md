# 서비스 공지 상세 조회

**서비스 공지 한 건의 본문입니다.**

- **Method / Endpoint: `GET /api/v1/announcements/{announcementId}`**
- **Auth Required: Not Required**

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Authorization | Bearer {access_token} | 있어도 되고 없어도 됩니다. 응답은 동일합니다 | 선택 |

## Path Variable

| Name | Type | Description | Required |
| --- | --- | --- | --- |
| announcementId | Long | 공지 번호. 목록 응답의 `id` | **필수** |

## Request Sample

```
GET /api/v1/announcements/12
```

# Response

## Response Param

| name | type | 비고 |
| --- | --- | --- |
| success | Boolean | 요청 성공 여부 |
| data.id | Long | 공지 번호 |
| data.type | String | `MAINTENANCE` \| `UPDATE` \| `EVENT` \| `GENERAL` |
| data.title | String | 제목 |
| data.content | String | 본문. **평문 텍스트입니다** — HTML 이 아닙니다 |
| data.image_url | String | 대표 이미지 주소. **없으면 필드 자체가 빠집니다** |
| data.published_at | String | 발행 일시 (ISO-8601 offset) |

> **응답 모양이 팝업 조회와 같습니다.** 팝업이 띄울 것도 결국 제목과 본문이라
> 모양을 나누지 않았습니다. 같은 컴포넌트로 그리면 됩니다.

> **대표 이미지는 한 장이고 본문과 별개입니다.** 본문 안에 삽입되지 않으므로
> `image_url` 을 어디에 배치할지는 화면이 정하면 됩니다. 없으면 필드가 빠집니다.
> 본문의 줄바꿈은 그대로 들어오므로 화면에서 살려 주세요.

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 404 | ANNOUNCEMENT_NOT_FOUND | 존재하지 않는 서비스 공지입니다. | 아래 네 가지가 모두 같은 404 입니다 |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 서버 측 처리 오류 |

### ★ 404 가 나는 네 가지 경우

| 상황 | 결과 |
|---|---|
| 번호가 없음 | 404 |
| 임시저장(작성 중) 공지 | 404 |
| 보관된 공지 | 404 |
| 노출 기간 밖(예약 중이거나 종료됨) | 404 |

**이유를 나누어 알려 주지 않습니다.** `id` 가 순번이라 번호를 맞추는 것이 쉽고,
"번호 N 에는 아직 안 알린 공지가 있다" 를 구분해 주면 그 자체가 정보가 됩니다.

> **목록과 상세의 조건이 완전히 같습니다.** 목록에 보이는 공지는 반드시 상세도 열리고,
> 목록에 없으면 상세도 404 입니다. 한쪽만 되는 경우는 없습니다.

> ⚠ **종료일이 지나면 상세도 닫힙니다.** 팝업에서 "자세히 보기" 로 넘어가는 링크를
> 사용자가 나중에 다시 열면 404 가 날 수 있습니다. 계속 읽히게 하려면
> 운영팀이 종료일을 비워 두어야 합니다.
