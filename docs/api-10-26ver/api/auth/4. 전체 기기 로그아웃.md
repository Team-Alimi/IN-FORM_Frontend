# 전체 기기 로그아웃

**로그인한 사용자의 모든 기기 세션을 한 번에 끊습니다. Refresh Token 을 전부 지울 뿐 아니라, 이미 발급돼 아직 만료되지 않은 Access Token 까지 즉시 무효화합니다. "다른 기기에서 모두 로그아웃" 버튼과 회원 탈퇴가 같은 동작을 씁니다.**

- **Method / Endpoint: `POST /api/v1/auth/logout/all`**
- **Auth Required: Required (User)**

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Authorization | Bearer {access_token} | 서비스 Access Token | **필수** |

> **본문이 없습니다.** 대상 사용자는 Access Token 에서 읽으므로 `Content-Type` 도 필요 없습니다.
> 어떤 세션을 끊을지 고르는 것이 아니라 **그 사용자의 전부**가 대상입니다 — 지금 호출한
> 기기의 세션도 함께 끊깁니다.

## Request Sample

```
POST /api/v1/auth/logout/all
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...
```

# Response

## Response Param

| name | type | 비고 |
| --- | --- | --- |
| success | Boolean | 항상 `true` |
| data | Object | **없습니다.** 응답 본문에 `data` 키 자체가 나타나지 않습니다 |
| error | Object | **없습니다.** 성공 응답에는 이 키가 나타나지 않습니다 |

> **성공 응답은 `{"success": true}` 한 줄입니다.** `data: null` 이 아니라 키가 통째로
> 빠집니다(`default-property-inclusion: non_null`).

### 일반 로그아웃과 무엇이 다른가

| | 로그아웃 | 전체 기기 로그아웃 |
| --- | --- | --- |
| 대상 | 본문이 지목한 세션 1개 | 그 사용자의 세션 전부 |
| Refresh Token | 지목한 것만 폐기 | 전부 폐기 |
| **남은 Access Token** | **그대로 통함 (최대 1시간)** | **즉시 무효화** |

> **★ 남은 Access Token 까지 끊는 것이 이 API 의 핵심입니다.** Refresh Token 만 지우면
> 다른 기기가 한 시간 더 정상 동작하고, 그러면 "모든 기기에서 로그아웃" 이라는 기능이
> 거짓말을 하게 됩니다. 탈퇴한 사용자가 그 사이 댓글을 계속 남길 수 있다는 문제도 같은 뿌리입니다.
> 그래서 "이 시각 이전에 발급된 Access Token 은 전부 무효" 라는 기준 시각을 함께 남깁니다.

> **끊은 직후 다시 로그인할 수 있습니다.** 무효화 기준이 "차단 플래그" 가 아니라 **시각**이라,
> 무효화 이후에 발급된 토큰은 정상 동작합니다.
> 다만 **판정이 초 단위**라 무효화와 **같은 초**에 발급된 토큰은 막는 쪽으로 처리됩니다.
> 무효화 직후 1초 안에 재로그인하면 새 토큰이 한 번 401 을 받을 수 있고, 잠시 뒤 재시도로 풀립니다.
> 통과시키는 쪽을 택하면 그 토큰이 남은 수명 내내(최대 1시간) 살아남기 때문에 막는 쪽으로 정했습니다.

> **200 을 받아도 프론트는 저장된 토큰을 스스로 지워야 합니다.** 서버가 무효화하는 것과
> 클라이언트 저장소를 비우는 것은 별개입니다.

> **Access Token 무효화가 실패해도 200 이 나갑니다.** 세션 저장소 장애로 무효화 기록을 쓰지
> 못하면 서버는 로그만 남기고 성공으로 응답합니다(가용성 우선). 이 경우 남은 Access Token 이
> 만료까지 살아 있을 수 있습니다. 반대로 Refresh Token 폐기 단계에서 장애가 나면 500 입니다.

## Response Sample

```json
{
  "success": true
}
```

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 401 | UNAUTHORIZED | 인증이 필요합니다. | `Authorization` 헤더가 없거나, Access Token 이 만료·위조됐거나, 이미 무효화된 토큰 |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 서버 측 처리 오류. 세션 저장소(Redis) 장애로 Refresh Token 폐기에 실패한 경우 |

> **관리자 여부와 무관합니다.** 로그인한 사용자면 누구나 자기 세션을 전부 끊을 수 있으므로
> 403 은 나오지 않습니다.
>
> 이미 전체 로그아웃을 한 뒤 같은 Access Token 으로 다시 호출하면 그 토큰이 무효화된 상태라
> **401 UNAUTHORIZED** 입니다. 이 API 자체가 멱등이 아니라, 두 번째 호출이 인증 단계에서
> 걸리는 것입니다.
