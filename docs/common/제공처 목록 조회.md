# 제공처 목록 조회

**공지를 올리는 제공처(학과·기관 또는 동아리) 중 활성 상태인 것만 이름 오름차순으로 내려줍니다. 온보딩 첫 화면의 학과·동아리 선택지, 공지 목록의 제공처 필터, 관심 제공처 설정 화면이 모두 이 목록으로 그려집니다. 비로그인 상태에서도 호출할 수 있어 앱 진입 직후 토큰 없이 바로 부를 수 있습니다.**

- **Method / Endpoint: `GET /api/v1/vendors`**
- **Auth Required: Not Required**

> **2026-09-01 현재 이 목록은 비어 있습니다. 버그가 아닙니다.**
> `vendors` 는 시드로 채우지 않기로 한 테이블입니다 — `initial` 컬럼이 크롤러의 사이트별
> 식별자와 1:1로 맞아야 하는 계약 키라, 추측해서 넣으면 크롤러 연동이 깨집니다.
> 규약은 **관리자 페이지로 먼저 등록 → 크롤러 시드에 추가** 순서입니다
> (`V5__seed_and_grants.sql` 주석). 학과가 등록되면 자동으로 채워집니다.

# Request

## Request Header

| Name | Value | Description | Required |
| --- | --- | --- | --- |
| Authorization | Bearer {access_token} | 서비스 Access Token | 선택 |

> **토큰을 보내도 응답은 달라지지 않습니다.** 로그인 여부와 무관하게 같은 목록이 나갑니다.
>
> **만료·위조된 토큰을 붙여도 401 이 아닙니다.** 인증 필터는 해석에 실패한 토큰을 조용히 버리고
> 요청을 통과시킵니다(`JwtAuthenticationFilter`). 게스트 화면이 낡은 토큰 하나 때문에
> 통째로 막히는 것을 피하기 위해서입니다. 프론트는 이 호출의 401 을 재로그인 신호로 쓰면 안 됩니다.

## Query Param

| Name | Type | Description | Required | Default |
| --- | --- | --- | --- | --- |
| type | String | `SCHOOL` \| `CLUB`. 생략하면 두 유형 전부 | 선택 | - |

### `type` 값 규칙

| 값 | 의미 |
| --- | --- |
| `SCHOOL` | 학과·기관 |
| `CLUB` | 동아리 |

> **대문자로만 받습니다.** `?type=school`, `?type=Club` 은 `400 INVALID_INPUT_VALUE` 입니다.
> 문자열을 enum 으로 바꾸는 변환기를 따로 두지 않았기 때문에 대소문자가 정확히 일치해야 합니다.
>
> 유형을 섞어서 보낼 수는 없습니다(`?type=SCHOOL,CLUB` 은 400). 둘 다 필요하면 파라미터를 생략하세요.

## Request Sample

```
# 전체 제공처 (학과 + 동아리)
GET /api/v1/vendors

# 학과·기관만
GET /api/v1/vendors?type=SCHOOL

# 동아리만
GET /api/v1/vendors?type=CLUB
```

# Response

### 정렬 기준

**한국어 이름 오름차순**이고, 이름이 같으면 `id` 오름차순입니다.

정렬은 DB 가 아니라 애플리케이션이 `java.text.Collator`(`Locale.KOREAN`)로 수행합니다.
운영 DB 의 collation 이 `en_US.utf8` 이라 한글 정렬 규칙이 없고, DB 정렬만 믿으면
"학생지원팀 → 컴퓨터공학과 → 정보통신공학과" 처럼 사용자 눈에 아무 순서도 아닌 목록이 나옵니다.

> **관리자 목록(`GET /api/v1/admin/vendors`)과 정렬이 다릅니다.** 관리자 쪽은 유형으로 먼저 묶기
> 때문에 `'CLUB' < 'SCHOOL'` 이 되어 동아리 전체가 학과 전체보다 앞에 옵니다.
> 두 화면의 순서가 다른 것은 의도된 것이며, 이 목록에서 유형별로 묶어 보여주고 싶다면
> 프론트가 `type` 으로 그룹핑해야 합니다.

### 페이징이 없습니다

**`data` 는 배열 그 자체입니다.** 다른 목록 API 와 달리 `data.content` · `data.page_info` 가 없고,
`page` · `size` · `sort` 파라미터도 받지 않습니다(붙여 보내도 무시됩니다).
제공처는 많아야 수백 건이라 페이징이 필요 없고, `sort` 를 열어 두면 검증되지 않은 문자열이
ORDER BY 뒤에 그대로 붙어 `?sort=foo` 하나로 500 이 납니다.

### Response Param

| name | type | 비고 |
| --- | --- | --- |
| success | Boolean | 요청 성공 여부 |
| data | Array | 제공처 목록. **`content`·`page_info` 로 감싸지 않은 평평한 배열** |
| data[].id | Long | 제공처 고유 ID. 필터·관심 설정에 쓰는 유일한 식별자 |
| data[].name | String | 제공처 이름 (최대 100자) |
| data[].type | String | `SCHOOL` \| `CLUB` |
| data[].homepage_url | String | 제공처 홈페이지 주소 (최대 500자). **없으면 필드 자체가 없음** |
| error | Object | 에러 정보 (성공 시 null) |

> **`homepage_url` 은 값이 없으면 키가 아예 빠집니다.** `default-property-inclusion: non_null`
> 이라 `"homepage_url": null` 이 아니라 필드가 사라집니다. 프론트는 반드시 키 존재 여부를 확인하고
> 링크 버튼을 그려야 합니다. 홈페이지가 없는 제공처가 실제로 있습니다.

> **`initial` 과 `is_active` 는 내려가지 않습니다.**
> `initial` 은 크롤러 시드가 제공처를 찾을 때 쓰는 내부 계약 키입니다. 내보내면 프론트가 그 문자열로
> 제공처를 식별하기 시작하고, 그러면 크롤러 계약을 바꿀 때 프론트까지 함께 깨집니다.
> `is_active` 는 이 목록에 활성만 담기므로 항상 `true` 라 의미가 없습니다.
> 비활성 제공처를 봐야 하는 화면은 관리자 API 를 쓰세요.

> **비활성 제공처는 절대 나오지 않습니다.** 관리자가 제공처를 비활성화하는 목적이 곧
> "신규 선택지에서 빼기" 이므로, 여기서 새면 사용자가 없어진 학과를 구독하게 됩니다.
> 이미 그 제공처로 등록된 공지의 출처 표시는 그대로 유지되므로, 공지 상세에서 본
> 제공처가 이 목록에 없을 수 있습니다. **공지 응답의 `vendors[]` 와 이 목록을 id 로 조인해
> 이름을 찾는 방식은 쓰지 마세요** — 없는 id 가 나옵니다.

# Error

| HTTP Status | Code | Message | Description |
| --- | --- | --- | --- |
| 400 | INVALID_INPUT_VALUE | type: 값의 형식이 올바르지 않습니다. | `type` 이 `SCHOOL`·`CLUB` 이 아님 (소문자 포함) |
| 500 | INTERNAL_SERVER_ERROR | 서버 내부 오류가 발생했습니다. | 서버 측 처리 오류 |

> **401·403 은 나오지 않습니다.** `SecurityConfig` 가 `GET /api/v1/vendors` 를 `permitAll` 로 열어 두었고,
> `PublicEndpointsTest` 가 이 동작을 고정하고 있습니다. 이 경로에서 401 을 받았다면 서버 설정 사고입니다.

> 조회만 하는 경로라 서비스·엔티티에서 던지는 `BusinessException` 이 없습니다.
> 위 400 은 컨트롤러 파라미터 바인딩 실패(`MethodArgumentTypeMismatchException`)를
> `GlobalExceptionHandler` 가 변환한 것입니다.
