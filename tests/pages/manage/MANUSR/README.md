# 회원관리 수동 확인 시나리오

관리자 계정으로 로그인하고 상단 **회원 관리** 탭 또는 `/manage/users`로 이동한다. 실제 권한 변경은 테스트 계정으로만 확인한다.

1. 목록: 회원 ID·이메일·이름·역할·상태·가입일이 표시되고 페이지를 이동할 수 있는지 확인한다. ID는 서버의 실제 숫자 값이다.
2. 검색: 이름/이메일을 2글자 이상 입력하고 조회한다. 1글자는 안내와 함께 차단된다. 역할·상태 필터를 함께 조회하고 초기화하면 전체 목록으로 돌아오는지 확인한다.
3. 상세: 회원 행이나 상세보기 버튼을 눌러 오른쪽 패널을 연다. 이름·이메일·온보딩 완료 여부·가입/탈퇴 일시를 확인한다. 이름이 없으면 `—`/`이름 없음`, 활성 회원의 탈퇴 일시는 `—`다.
4. 승격: 활성 사용자 테스트 계정에서 관리자로 승격 → 취소하면 변경되지 않는다. 다시 확인하면 관리자 배지와 사용자로 변경 버튼이 나타나야 한다.
5. 강등: 다른 관리자 테스트 계정에서 사용자로 변경을 확인한다. 탈퇴한 관리자도 강등할 수 있지만 탈퇴 사용자는 승격할 수 없어야 한다.
6. 본인: 자신의 상세에서는 권한 변경 버튼이 비활성화되고 안내가 표시되어야 한다.
7. 갱신: 사용자 필터로 조회한 회원을 승격하면 해당 목록에서 빠지고 건수가 줄어야 한다. 마지막 페이지의 마지막 회원이면 유효한 이전 페이지로 돌아와야 한다.
8. 충돌/실패: 409 발생 시 최신 정보를 불러오고 다시 확인하라는 안내가 나온다. 변경 실패를 성공으로 표시하지 않아야 한다. 요청 중 닫기·취소·중복 제출을 할 수 없어야 한다.
9. 모바일·키보드: 430px에서 검색은 줄바꿈되고 표만 가로 스크롤된다. 상세는 화면 너비에 맞으며 Escape로 닫을 수 있다. 확인 단계에서는 Escape가 확인만 취소하고, 요청 중에는 닫지 않는다.

자동 검증: Vite 개발 서버 실행 후 `python tests/pages/manage/MANUSR/users_browser.py`. 모든 API를 모의 응답으로 대체하여 실제 회원 권한은 변경하지 않는다. `screenshots/`에 목록·상세의 데스크톱/모바일 캡처를 저장한다.
