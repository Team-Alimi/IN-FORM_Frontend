# 휴지통 수동 확인 시나리오

관리자 계정으로 로그인한 뒤 `/manage/garbage`를 연다. 복구·영구 삭제 확인은 테스트용 게시물로 진행한다.

1. 목록: 삭제 전 상태, 카테고리, 출처, 행사 기간, 수정일이 표시되고 제목을 누르면 상세로 이동하는지 확인한다.
2. 검색: ID, 제목 일부, 출처 일부, 카테고리, 상태를 조회한다. 행사 기간은 입력 구간과 겹치는 게시물을 찾는다. 초기화를 누르면 전체 목록으로 돌아온다.
3. 전체 검색: 휴지통에 50건 이상 있을 때 뒤쪽 게시물의 제목을 검색해 표시되는지 확인한다. 전체 페이지를 읽는 동안 검색과 작업 버튼은 비활성화된다.
4. 선택: 전체 선택은 현재 화면의 최대 8건에만 적용된다. 페이지 이동·검색·초기화 시 선택이 해제되는지 확인한다.
5. 복구: 테스트 게시물을 선택하고 선택 복구 → 취소하면 변화가 없어야 한다. 다시 확인하면 휴지통에서 사라지고 삭제 직전 상태의 목록에 나타나야 한다. 운영 게시물은 사용자에게 다시 공개된다.
6. 이력 없음: 삭제 전 상태가 없는 게시물은 복구가 비활성화되고 사유가 표시되어야 한다. 영구 삭제는 선택할 수 있다.
7. 영구 삭제: 확인창의 복구 불가 안내를 확인한다. 취소하면 유지되고 확인하면 목록에서 사라져야 한다. 실제 삭제 후 되돌릴 수 없으므로 테스트 데이터만 사용한다.
8. 오류: 일부 실패는 성공/실패 건수와 실패한 ID·사유로 표시된다. 처리 중에는 중복 클릭·검색·페이지 이동을 할 수 없어야 한다.
9. 모바일: 430px에서 검색창이 줄바꿈되고 표만 가로 스크롤되어야 한다.

자동 검증은 Vite 개발 서버 실행 후 `python tests/pages/manage/MANGBG/trash_browser.py`로 실행한다. 모든 API는 모의 응답으로 대체하며 실제 게시물을 수정하거나 삭제하지 않는다.

현재 서버 API에는 검색 조건이 없어 전체 조회 후 화면에서 검색한다. 데이터가 많으면 최초 조회 및 처리 후 갱신 시간이 늘어난다. 목업의 30일 자동 삭제는 서버 명세에서 확인되지 않아 화면 안내에서 제외했다.
