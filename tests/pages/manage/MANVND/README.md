# 제공처·동아리 관리 수동 확인 시나리오

관리자 계정으로 로그인하고 **제공처/동아리 관리** 탭 또는 `/manage/vendors`로 이동한다. 등록·수정은 테스트용 제공처로 확인한다.

1. 목록: ID·이름·식별자·유형·홈페이지·활성 여부·등록일이 표시된다. 8건을 넘으면 페이지를 이동한다. 페이지 이동은 추가 API 요청 없이 처리된다.
2. 필터: 유형과 활성 여부를 선택한 뒤 **조회**한다. **숨김**도 정상 조회되며 초기화하면 전체 목록으로 돌아온다. 조회 결과가 없으면 빈 목록 안내가 나온다.
3. 등록: 이름·공백 없는 고유 식별자·유형을 입력한다. 홈페이지는 생략할 수 있다. 빈 이름, 식별자 내부 공백, HTTP(S)가 아닌 홈페이지 주소는 차단된다. 이미 사용 중인 식별자는 서버 오류를 표시하고 입력을 보존한다.
4. 등록 성공: 서버가 반환한 이름·식별자와 수집 설정 안내가 표시된다. **확인** 후 목록이 갱신된다. 등록만으로 수집이 시작되는 것은 아니며, 응답의 안내에 따라 별도 시드 설정이 필요하다.
5. 수정: 식별자와 유형은 수정할 수 없다. 변경하지 않으면 저장 버튼이 비활성화된다. 이름만 변경하면 이름만 전송한다. 홈페이지를 지우면 빈 문자열을 전송하고 목록에서 링크가 사라진다.
6. 숨김/재활성화: 수정창에서 숨김으로 저장하면 목록·필터 노출과 수집 동작을 구분하는 서버 안내가 나온다. 숨김 필터에서 다시 열어 활성화할 수 있다. 활성 필터의 마지막 페이지에서 마지막 항목을 숨기면 유효한 페이지로 돌아온다.
7. 저장 중/실패: 처리 중 중복 저장·닫기·Escape를 막는다. 실패하면 입력이 남고 오류를 표시한다. 저장은 성공했지만 목록 갱신이 실패한 경우에도 성공 안내를 유지하고 중복 등록을 유도하지 않는다. 목록에서 다시 시도할 수 있다.
8. 권한/링크: 로그아웃 상태에서 `/manage/vendors`에 직접 접속하면 API 요청 없이 로그인 화면으로 이동한다. 온보딩이 완료된 관리자 계정으로 로그인하면 제공처 관리로 돌아온다. 로그인 상태의 API 403은 다시 로그인 안내를 표시한다. 홈페이지는 HTTP(S) 주소만 새 탭으로 연다. 기존 비표준 주소는 링크 없이 표시하며 이름만 수정하는 것은 가능하다.
9. 모바일·키보드: 430px/375px에서 페이지 자체가 가로로 넘치지 않고 표만 가로 스크롤된다. 등록·수정창은 화면에 맞게 표시되며 Escape로 닫으면 이전 버튼으로 포커스가 돌아온다.

자동 검증: Vite 개발 서버 실행 후 `python tests/pages/manage/MANVND/vendors_browser.py`. Python Playwright와 Chromium이 필요하다. 모든 제공처 API를 모의 응답으로 대체하므로 실제 데이터를 변경하지 않는다. `screenshots/`에 목록·등록·수정의 데스크톱/모바일 캡처를 저장한다.
