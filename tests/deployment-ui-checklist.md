# 배포 후 UI·라우팅 회귀 확인 (#81)

아래 항목은 실제 브라우저에서 수행하는 수동 테스트이며, 체크하지 않은 항목은 미검증이다.
모바일은 430px 이하, 데스크톱은 430px 초과에서 확인한다.

- [ ] 모바일 EVD: 긴 본문에서 북마크 뒤에 흰색 원이 보이며, 마지막 내용까지 스크롤하여 읽을 수 있다.
- [ ] 모바일 EVD: 북마크 저장·해제가 동작하고 북마크 수가 갱신된다.
- [ ] 데스크톱 EVD: 북마크가 EventDetail 카드 내부 오른쪽 하단에 하나만 표시되고 저장·해제 및 개수 갱신이 동작한다.
- [ ] 모바일 EVL → EVD: 목록 중간까지 스크롤한 뒤 상세 진입 시 제목부터 보인다. 다른 공지를 선택해 반복한다.
- [ ] 모바일 CBL → CBD: 목록에서 상세 진입 시 최상단부터 보이고, 하단 고정바가 마지막 내용을 가리지 않는다.
- [ ] 비로그인 HOM: 기본 캘린더 조회와 날짜·월 변경은 유지된다.
- [ ] 비로그인 HOM: 카테고리 칩(전체 포함), 모바일 필터 열기, 관심학과 체크 시 `/login`으로 이동한다.
- [ ] 비로그인 HOM: 캘린더 일별 공지와 지금 뜨는 공지를 각각 클릭하면 상세 API 호출/바텀시트 열기 없이 `/login`으로 이동한다.
- [ ] 기존 계정 로그인 완료 후 클릭했던 공지 상세로 돌아간다.
- [ ] 로그인 HOM: 필터 적용, 관심학과 조회, 모바일 상세 바텀시트와 데스크톱 상세 이동이 유지된다.
- [ ] Vercel 배포 후 `/login`, `/events`, `/events/detail/{실제 ID}`, `/clubs`, `/bookmarks`, `/mypage` 직접 접속과 새로고침 시 Vercel 404가 발생하지 않는다. 보호 경로는 로그아웃 상태에서 로그인으로 이동한다.
- [ ] Vercel 배포 후 존재하지 않는 경로는 앱의 오류 화면으로 표시되며 JS/CSS/이미지는 정상 로드된다.

`npm run build`나 Vite 개발 서버만으로 Vercel rewrite의 실제 적용을 검증할 수는 없다.
